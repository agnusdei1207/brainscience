## 0. 핵심 인사이트

> **핵심**: LMAX Disruptor는 큐 기반 경쟁 잠금을 줄이기 위해 링 버퍼와 시퀀스 배리어를 활용하여 고성능·저지연 이벤트 처리를 수행하는 메모리 중심 동시성 패턴이다.
> **비유**: 여러 작업자가 하나의 좁은 문 앞에서 순서를 다투지 않고, 원형 트랙의 각 지점을 정해진 순서로 통과하며 작업하는 방식과 같다.

## 1. 개요 및 필요성

187. LMAX 아키텍처와 Disruptor 패턴 (LMAX Disruptor Architecture)은 링 버퍼 기반 락 최소화 이벤트 처리 아키텍처를 다루는 주제다.
이 패턴이 중요한 직접 배경은 전통적 Blocking Queue는 락 경합과 캐시 미스 때문에 초저지연 요구를 만족하기 어렵다.
이를 해결하기 위한 구조적 가치로는 단일 작성자 시퀀스, 캐시 친화적 메모리 배치, 배리어 기반 의존성으로 높은 처리량을 낸다.
설계자가 집중해야 하는 관점은 핵심 초점은 ring buffer, sequence, barrier, false sharing 회피, batch effect다.
이 섹션에서는 왜 이 구조가 필요해졌는지와, 어떤 비용을 줄이기 위해 등장했는지를 논리적으로 정리한다.

## 2. 구성요소

| 요소 | 역할 | 핵심 포인트 |
|:---|:---|:---|
| Ring Buffer | 고정 크기 순환 버퍼 | 메모리 재사용과 캐시 친화성 |
| Sequence | 생산자/소비자 위치 인덱스 | 락 대신 진행 상태 표현 |
| Sequencer | 게시 순서 관리 | single/multi producer 지원 |
| Event Processor | 소비자 처리기 | 배리어 기반 의존성 |
| Sequence Barrier | 소비 가능 여부 확인 | 선행 단계 완료 대기 |
| Wait Strategy | 대기 방식 | busy spin, yielding 등 |
| Preallocated Event | 객체 재사용 | GC 부담 감소 |

구성요소는 개별 기능보다 상호작용을 통해 의미를 가진다.
각 요소가 어떤 경계에서 책임을 갖고, 어디까지 추상화를 제공하는지가 설계 품질을 좌우한다.

## 3. 구조 및 원리
**핵심 조건**: 공유 큐 경쟁 대신 순서 번호와 링 버퍼를 사용해 메모리 접근과 동기화 비용을 최소화해야 한다.

Disruptor는 큐 자료구조보다 메모리 배치와 캐시 친화성을 더 중시한다.
생산자와 소비자는 sequence를 통해 진행 상태를 조율한다.
pre-allocation으로 객체 생성과 Garbage Collection 부담을 줄인다.
wait strategy 선택은 CPU 사용량과 지연 시간의 트레이드오프다.
false sharing을 피하기 위한 padding 같은 저수준 고려가 중요하다.
금융 거래와 같은 초저지연 시스템에서 특히 유효하다.
이 조건이 지켜질 때 구조는 단순 분할이 아니라 실제 동작 원리로 기능한다.

동작 순서:
1. **버퍼 준비**: 고정 크기 링 버퍼와 이벤트 슬롯을 미리 할당한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
2. **시퀀스 할당**: 생산자가 다음 sequence를 확보한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
3. **이벤트 기록**: 해당 슬롯에 데이터를 기록한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
4. **게시**: 시퀀스를 publish하여 소비자에게 가시화한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
5. **배리어 확인**: 소비자가 자신의 선행 의존성 sequence를 확인한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
6. **배치 처리**: 연속 sequence를 가능한 한 묶어 처리한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
7. **진행 갱신**: 소비자가 완료 sequence를 갱신해 후속 단계가 진행한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.

```
Producer --> [Sequencer] --> [Ring Buffer Slot 0..N]
                    |                  |
                    | publish seq      v
                    +------------> [Sequence Barrier]
                                       |
                         +-------------+-------------+
                         v                           v
                 [Consumer A]                  [Consumer B]
                         |                           |
                         +-------- dependency -------+
```

## 8. 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| Ring Buffer | 핵심 저장 구조 |
| Sequence | 진행 상태 표현 |
| False Sharing | 성능 저해 요인 |
| Wait Strategy | 지연-CPU 트레이드오프 |
| Batching | 처리량 향상 요인 |
| Producer-Consumer | 비교 대상 기본 모델 |
| Lock-Free | 완전 무락은 아니지만 지향 개념 |
| GC Pressure | 객체 재사용으로 완화 |
| Cache Line | 메모리 성능 핵심 |
| Event Processing Pipeline | 다단계 소비 구조 |

### 정리 메모
- Disruptor는 큐의 또 다른 구현체가 아니라, 동시성 병목을 메모리 배치와 sequence 설계로 다시 푸는 아키텍처적 접근이다.
  - 관련 개념까지 함께 묶어 이해하면 주제의 실전 활용도가 높아진다.
