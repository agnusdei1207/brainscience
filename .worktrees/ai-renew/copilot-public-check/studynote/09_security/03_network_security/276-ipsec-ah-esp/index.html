핵심 인사이트 (3줄 요약)

  1. 본질: AH (Authentication Header)는 인증·무결성만, ESP (Encapsulating Security Payload)는 인증·무결성·기밀성을 모두 제공하며, 현대 IPsec에서는 NAT (Network Address Translation) 호환성과 암호화 필요성으로 인해 ESP가 사실상 표준이다.
  2. 가치: AH가 NAT 환경에서 사용 불가능한 이유는 IP 헤더를 포함한 전체 패킷에 서명하기 때문으로, NAT가 IP 주소를 변경하면 서명 검증이 실패한다. ESP는 IP 헤더를 서명 범위에서 제외해 NAT를 허용한다.
  3. 판단 포인트: AH와 ESP의 헤더 구조, 보호 범위, NAT 호환성을 정확히 구별하고, ESP+AH 동시 사용 시나리오를 설명할 수 있어야 한다.

Ⅰ. 개요 및 필요성

IPsec은 두 개의 독립적인 보안 프로토콜을 제공한다. AH (RFC 4302)는 무결성(Integrity)과 데이터 출처 인증(Data Origin Authentication)에 특화되며, ESP (RFC 4303)는 이에 더해 기밀성(Confidentiality)을 추가한다.

AH와 ESP의 설계 철학 차이는 "무엇을 보호하는가"에 있다. AH는 IP 헤더를 포함한 패킷 전체에 서명해 IP 레벨 위조를 방지하는 것이 목적이다. ESP는 페이로드(상위 레이어 데이터)만 암호화·인증해 게이트웨이나 NAT 장비가 IP 헤더를 정당하게 수정할 수 있도록 한다.

실무에서 AH 단독 사용은 거의 사라졌다. NAT 환경이 기본이 된 현재 인터넷에서 AH는 작동하지 않고, ESP가 무결성까지 제공하므로 AH의 기능이 ESP로 완전히 대체된다. RFC 7321은 ESP with non-null 암호화를 IPsec 구현의 필수(MUST) 항목으로 지정했다.

📢 섹션 요약 비유: AH는 봉투 겉면까지 포함해 도장을 찍는 방식이라, 배달부(NAT)가 주소를 고쳐 쓰면 도장이 깨진다. ESP는 봉투 안 내용물에만 도장을 찍어 주소 수정을 허용한다.

Ⅲ. 비교 및 연결

NAT-T (NAT Traversal) 메커니즘

NAT 환경에서 ESP를 사용하려면 NAT-T (RFC 3948)가 필요하다. NAT-T는 ESP 패킷을 UDP (User Datagram Protocol) 포트 4500으로 캡슐화해 NAT 장비가 포트 번호로 세션을 추적하도록 한다.

[NAT-T 없는 ESP]
IP 헤더 | ESP 헤더 | 암호화 페이로드
→ NAT가 IP 주소를 변경하면 ESP ICV 검증 실패 가능성

[NAT-T 적용 ESP (UDP 캡슐화)]
IP 헤더 | UDP(4500) | ESP 헤더 | 암호화 페이로드
→ NAT는 UDP 헤더의 IP:Port를 변환, ESP 내부는 그대로
환경권장 프로토콜비고
NAT 없는 사설망ESP 또는 AH+ESPAH 사용 가능
인터넷 VPN (NAT 포함)ESP + NAT-TUDP 4500 포트 허용 필요
클라우드 VPNESP + NAT-T대부분 NAT 환경
IKE 협상UDP 포트 500IKEv2 표준
IKE over NATUDP 포트 4500NAT 감지 시 자동 전환

📢 섹션 요약 비유: NAT-T는 "원래 봉투를 새 봉투(UDP)에 넣어" NAT 장비가 바깥 봉투만 건드리고 안 봉투는 그대로 두게 하는 이중 포장이다.

Ⅳ. 실무 적용 및 기술사 판단

ESP 암호 스위트 선택 기준 (RFC 8221 기준)

[권장 조합 - AES-GCM 기반 AEAD]
esp=aes256gcm16    # AES-256 GCM, 16바이트 ICV
esp=aes128gcm16    # AES-128 GCM (성능 우선 시)

[레거시 조합 - 별도 인증 필요]
esp=aes256-sha256  # AES-256 CBC + HMAC-SHA-256
esp=aes128-sha1    # 취약, 사용 자제

[사용 금지]
esp=3des-md5       # 3DES, MD5 모두 취약
esp=des-sha1       # DES 56비트, 취약

AEAD (Authenticated Encryption with Associated Data) 알고리즘인 AES-GCM은 암호화와 인증을 한 패스로 처리해 성능이 우수하다. 최신 IPsec 구현에서 AES-GCM-128/256이 표준이다.

AH 사용이 여전히 유효한 시나리오:

  • 암호화 수출 규제가 있는 국가 간 연결 (기밀성 불필요, 무결성만 요구)
  • 법적 요구사항으로 패킷 내용을 평문으로 유지해야 하는 경우
  • IP 헤더 필드(소스 IP 등) 위변조 방지가 최우선인 경우

기술사 포인트: AH가 실무에서 사라진 이유를 NAT 환경, ESP의 기능 완전성, RFC 7321의 요구사항 세 가지 축으로 설명하면 완성도 높은 답안이 된다.

📢 섹션 요약 비유: AH는 설계상 훌륭하지만 현실 인터넷(NAT 가득)에서는 작동을 못 한다. 완벽한 이론보다 현실에 맞는 ESP가 채택된 것은 공학적 실용주의의 좋은 예다.

Ⅴ. 기대효과 및 결론

AH와 ESP는 서로 다른 보안 목표를 위해 설계됐지만, 현실 인터넷에서는 ESP가 AH의 기능을 완전히 포함하면서 NAT 환경도 지원하기 때문에 ESP가 유일한 실용적 선택이 됐다. AH는 주로 학술적·이론적 맥락에서 언급된다.

현대 IPsec 구현에서는 AES-GCM 기반 AEAD 알고리즘을 ESP에 적용해 성능과 보안을 동시에 달성한다. 하드웨어 AES-NI (Advanced Encryption Standard New Instructions) 지원 CPU에서는 AES-GCM이 소프트웨어 암호화보다 10배 이상 빠르다.

📢 섹션 요약 비유: AH와 ESP는 두 종류의 금고인데, AH 금고는 이사할 때(NAT) 열쇠가 맞지 않아 못 쓴다. ESP 금고는 이사해도 잘 열리고 더 많은 기능을 제공한다.
