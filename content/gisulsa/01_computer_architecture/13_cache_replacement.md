# 🎯 캐시 교체 정책 & 페이지 교체 알고리즘

> **별점**: ★★★★★ | 기본 필수

## 1. 교체 알고리즘 비교

| 알고리즘 | 원리 | 장단점 |
|---------|------|--------|
| **OPT** | 앞으로 가장 오래 사용 안할 것 교체 | 최적이지만 미래 예측 불가 (이론적) |
| **LRU** | 가장 오래 전에 사용된 것 교체 | 성능 우수, 참조 시간 추적 필요 |
| **LFU** | 사용 빈도 가장 낮은 것 교체 | 초기 빈도 높은 데이터 잔존 문제 |
| **FIFO** | 가장 먼저 들어온 것 교체 | 단순, Belady의 이상 현상 발생 |
| **Clock** | 시계 방향, 참조 비트 0인 것 교체 | LRU 근사, 구현 효율적 |
| **NRU** | 최근 미사용 중 랜덤 교체 | 단순화된 LRU |

## 2. Belady의 이상 현상

```
FIFO에서 프레임 수 ↑ → 페이지 폴트 ↑ 역설

예) 참조열: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
프레임 3: 페이지 폴트 9번
프레임 4: 페이지 폴트 10번 (더 나쁨!)

원인: FIFO가 지역성을 고려하지 않기 때문
해결: LRU, Clock 알고리즘 사용
```

## 3. LRU 구현 방식

```
[카운터 방식]
각 페이지에 접근 시간 기록
최소 카운터 = 가장 오래된 = 교체 대상
오버헤드: 비교 연산 많음

[스택 방식]
참조 시마다 스택 최상단으로 이동
스택 바닥 = 가장 오래된 = 교체 대상

[Clock 알고리즘 (근사 LRU)]
원형 큐 + 참조 비트(R bit)
  접근 시: R=1 설정
  교체 시: R=1이면 0으로 초기화 후 이동
           R=0이면 교체

실제 OS: Clock 또는 변형 알고리즘 사용
```

## 4. 답안 포인트

**3단락**: ① OPT/LRU/FIFO/Clock 비교 → ② Belady 이상 현상 & 원인 → ③ LRU 구현(카운터/스택/Clock) & 실제 OS 적용
