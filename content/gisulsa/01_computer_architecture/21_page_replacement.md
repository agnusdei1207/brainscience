# 🎯 가상 메모리 & 페이지 교체 알고리즘

> **별점**: ★★★★★ | 매회 필출

## 1. 가상 메모리 구조

```
[페이징 (Paging)]
가상 주소 공간 → 고정 크기 페이지 (4KB)
물리 메모리 → 동일 크기 프레임

페이지 테이블: 가상 페이지 번호 → 물리 프레임 번호 매핑

가상 주소 변환:
  VA = 페이지 번호(VPN) + 오프셋
  PA = 프레임 번호(PFN) + 오프셋
  변환: TLB 히트 → 즉시 변환
        TLB 미스 → 페이지 테이블 참조

[세그먼테이션 (Segmentation)]
가변 크기 세그먼트 (코드/데이터/스택)
내부 단편화 없음, 외부 단편화 발생

[혼합 (Segmented Paging)]
세그먼트 + 페이지 혼합 (현대 x86-64 페이징 중심)
```

## 2. 페이지 폴트

```
페이지 폴트: 요청 페이지가 메모리에 없을 때 발생

[처리 절차]
1. 프로세스가 가상 주소 접근
2. MMU: 페이지 테이블 확인 → 유효 비트 = 0
3. 트랩 발생 → OS 페이지 폴트 핸들러
4. 디스크에서 해당 페이지 읽기 (느림!)
5. 빈 프레임에 적재 (없으면 교체)
6. 페이지 테이블 갱신, 프로세스 재시작

[유효 접근 시간 (EAT)]
EAT = (1-p)×메모리 시간 + p×페이지폴트 시간
p: 페이지 폴트율
p ≈ 1/1000이면 성능 10% 저하
```

## 3. 지역성 원리

```
시간적 지역성: 최근 참조된 항목은 곧 다시 참조
  → LRU 교체 정책 근거

공간적 지역성: 참조된 항목 주변을 곧 참조
  → 캐시 블록, 프리패칭 기반

루프 예시:
  for (i=0; i<N; i++) sum += a[i];
  시간적: sum (반복 참조)
  공간적: a[0], a[1], a[2]... (순차 접근)
```

## 4. 답안 포인트

**3단락**: ① 가상 메모리(페이징/세그먼테이션) & 주소 변환 → ② 페이지 폴트 처리 절차 & EAT → ③ 지역성 원리 & 교체 정책 연계

## 5. 관련 개념

`TLB(16번)` → 주소 변환 가속 | `스래싱(★132회, 22번)` → 페이지 폴트 과다 | `교체 정책(13번)` → OPT/LRU/Clock
