# 🎯 핵심 키워드: HW 규모산정, TPC-C, tpmC, 과학기술정보통신부 고시

> **출제 빈도**: ★★★★☆ | **난이도**: ★★★☆☆ | **기출**: ★135회 (컴시응 필수)

## 1. 정의

정보시스템 하드웨어 규모산정 지침은 **과학기술정보통신부 고시**로, 공공 정보시스템 구축 시 서버·스토리지·네트워크 장비의 적정 규모를 산정하는 방법론을 표준화한 국내 지침이다.

## 2. 출제 포인트

| 포인트 | 내용 | 채점 비중 |
|--------|------|----------|
| 정의 | 고시 목적, 적용 대상(공공 정보시스템) | 20% |
| 서버 산정 | tpmC 기반 트랜잭션 처리 성능 | 35% |
| 스토리지 산정 | 데이터 증가율, 여유 용량, 백업 | 25% |
| 적용 절차 | 업무량 분석 → 성능 산정 → 규모 결정 | 20% |

## 3. 답안 목차 템플릿

**문제**: "정보시스템 하드웨어 규모산정의 개념과 서버 및 스토리지 산정 절차를 설명하시오."

```
I. HW 규모산정 지침 개요
   - 근거: 과학기술정보통신부 고시 (공공SW사업 관련)
   - 목적: 과대/과소 사양 방지, 예산 효율화
   - 대상: 공공기관 정보시스템 구축 사업

II. 서버 규모 산정 방법
   
   [산정 흐름]
   업무량 분석 → 피크 TPS 산정 → tpmC 환산 → 여유율 적용 → 서버 사양
   
   핵심 지표:
   - tpmC (TPC-C benchmark): 서버 처리 성능 단위
   - TPS (Transaction Per Second): 초당 트랜잭션 수
   - CPU 사용률: 피크 시 70% 이하 권장
   
   산정 공식:
   필요 tpmC = (피크 TPS × 60) / CPU사용률목표
   여유율: 성장률 고려 30~50% 추가
   
   서버 유형별:
   | 유형           | 산정 기준        |
   |---------------|----------------|
   | OLTP 서버     | tpmC            |
   | WAS 서버      | 동시 접속자 수   |
   | 배치 서버     | 처리 데이터량/시간 |
   | AI/빅데이터   | GPU 연산량 기반  |

III. 스토리지 규모 산정
   
   총 용량 = 초기 데이터량 × (1 + 연간증가율)^운영기간
            + 시스템 영역 + 백업 용량 + 여유 공간(30%)
   
   RAID 구성별 실효 용량:
   - RAID 1: 총용량 × 0.5
   - RAID 5: 총용량 × (n-1)/n
   - RAID 10: 총용량 × 0.5

IV. 클라우드 시대 규모산정
   - IaaS 전환: 온프레미스 사양 → 클라우드 인스턴스 타입 매핑
   - 자동 스케일링 고려: 최소/최대/기준 스펙 정의
   - FinOps 연계: 실사용량 모니터링 → 우측 사이징(Right-sizing)
```

## 4. 핵심 암기 포인트

- **tpmC**: TPC-C 벤치마크의 서버 성능 단위 (Transactions Per Minute)
- **피크 부하 기준**: 평균이 아닌 피크 시점 기준 산정
- **여유율 30~50%**: 성장 대비, 고장 대비 버퍼
- **공공 필수**: 공공 SW 사업에서 필수 적용 (감리 체크 항목)

## 5. 관련 개념 연결

| 개념 | 연결 포인트 |
|------|------------|
| RAID | 스토리지 규모산정 시 유효 용량 계산 |
| HA (고가용성) | 이중화 구성 시 추가 HW 산정 |
| RPO/RTO | 스토리지 백업 용량 산정 기준 |
| 정보시스템 감리 (★134회) | 규모산정 적정성 감리 체크 |
| FinOps | 클라우드 환경의 우측 사이징 |
