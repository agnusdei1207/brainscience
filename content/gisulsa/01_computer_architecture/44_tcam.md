## 0. 핵심 인사이트

> **정의**: 0, 1, **X(Don't Care)** 세 가지 상태를 저장하는 내용 주소 지정 메모리
> **핵심 특징**: 데이터를 주소 대신 **내용으로 검색**, 병렬 비교 → 1클럭 O(1) 검색
> **시험 포인트**: CAM vs TCAM 차이 → 라우터/스위치 패킷 분류 적용 → 고속/고비용 트레이드오프

---

## 1. 개요 및 필요성

일반 RAM은 주소를 입력해 내용을 읽는다(주소 → 데이터). CAM(Content Addressable Memory)은 반대로 내용을 입력해 주소를 찾는다(데이터 → 주소). 이를 통해 일치하는 엔트리를 O(1)에 검색 가능하다.

TCAM은 CAM을 확장해 **X(Don't Care, 마스크)** 비트를 추가한다. 라우팅 테이블의 CIDR 주소(예: 192.168.1.0/24)처럼 일부 비트를 무시(마스크)하는 와일드카드 매칭이 필요한 패킷 분류에 필수적이다.

---

## 2. 구성요소 및 비교

| 항목 | RAM | CAM | TCAM |
|:---|:---|:---|:---|
| 검색 방식 | 주소 → 데이터 | 데이터 → 주소 | 데이터+마스크 → 주소 |
| 저장 비트 | 0, 1 | 0, 1 | 0, 1, X(Don't Care) |
| 검색 속도 | O(1) 읽기 | O(1) 병렬 | **O(1) 병렬** |
| 전력/비용 | 낮음 | 높음 | **매우 높음** |
| 밀도 | 높음 | 낮음 | **낮음** |
| 주요 용도 | 일반 저장 | 캐시 태그 | **라우터 패킷 분류** |

---

## 3. 구조 및 원리

**TCAM 셀 구조** (비트당 2개 SRAM 셀 사용):

```
데이터 비트 | 마스크 비트 | 의미
    0       |     0      | 정확히 0
    1       |     0      | 정확히 1
    0 or 1  |     1      | X (Don't Care, 무시)
```

**패킷 분류 동작**:

```
입력 IP 주소: 10.0.0.5 (이진수)

TCAM 엔트리 1: 10.0.0.0/24 → 마스크: 11111111.11111111.11111111.00000000
TCAM 엔트리 2: 10.0.0.0/8  → 마스크: 11111111.00000000.00000000.00000000
TCAM 엔트리 3: 0.0.0.0/0   → 마스크: 00000000.00000000.00000000.00000000 (기본경로)

→ 모든 엔트리 동시 비교 → 최장 prefix 매칭(LPM) → 1클럭에 결과
```

---

## 4. 실무 적용

**주요 사용처**:
1. **라우터 포워딩 테이블**: IP 패킷의 최장 접두사 매칭(Longest Prefix Match)
2. **스위치 ACL**: 출발/목적지 IP+포트 조합 패킷 필터링
3. **방화벽**: 룰셋 기반 패킷 허용/차단 결정
4. **QoS 분류**: 트래픽 유형 식별 및 우선순위 부여

**한계**:
- 비트당 2개 SRAM → 용량 대비 면적/전력 비용 매우 큼
- 수십만 엔트리 규모에서 전력 소비 문제 심각
- → **소프트웨어 기반 대안**: DPDK, eBPF, P4 언어로 TCAM 기능 SW화 추세

---

## 5. 시험 답안 포인트

**답안 작성 3단락 구조**:

- **1단락 (개념)**: "TCAM은 0, 1, X(Don't Care) 세 상태를 갖는 내용 주소 지정 메모리로, 라우터의 IP 패킷 분류에서 수십만 개의 라우팅 규칙을 1클럭에 병렬 비교하여 최장 접두사 매칭을 수행한다."
- **2단락 (구조)**: 셀 구조, CAM/RAM 비교표, 패킷 분류 동작 흐름
- **3단락 (트렌드)**: "TCAM의 고비용·고전력 문제로 인해 eBPF, P4 프로그래머블 데이터플레인, FPGA 기반 소프트웨어 패킷 분류로의 전환이 가속화되고 있다."

---

## 6. 결론 및 최신 트렌드

고속 네트워크 장비에서 TCAM은 여전히 필수적이나, 소프트웨어 정의 네트워킹(SDN)과 스마트 NIC(DPU)의 부상으로 TCAM 기능을 eBPF/P4로 대체하는 추세가 가속화되고 있다. 데이터센터 규모 라우팅에서 ECMP(등가 다중 경로)와 결합한 TCAM 활용이 핵심 설계 포인트다.

## 7. 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| CAM | TCAM의 기반. 이진 상태만 저장 |
| SRAM | TCAM 구현 소자. 비트당 2셀 |
| 라우팅 프로토콜 (OSPF/BGP) | TCAM에 저장되는 라우팅 테이블 생성 |
| SDN | TCAM 기반 하드웨어 포워딩의 소프트웨어화 |
| eBPF | TCAM 기능의 SW 대안. Linux 커널 내 패킷 분류 |
| DPU (☆예측) | SmartNIC에서 TCAM 기능 오프로딩 |
