# 🎯 핵심 키워드: 교착상태, 4대 발생 조건, 은행원 알고리즘, 자원할당 그래프

> **출제 빈도**: ★★★★★ | **기출**: ★134회

## 1. 정의

교착상태(Deadlock)는 두 개 이상의 프로세스가 서로 상대방이 점유한 자원을 기다리며 무한 대기하는 상태. 어떤 프로세스도 진행 불가.

## 2. 4대 발생 조건 (모두 동시 성립 시 교착 발생)

| 조건 | 설명 | 제거 방법 |
|------|------|----------|
| **상호 배제** | 자원을 하나의 프로세스만 사용 | 자원 공유 (제거 어려움) |
| **점유와 대기** | 자원을 보유하면서 다른 자원 대기 | 모든 자원 한번에 요청 |
| **비선점** | 강제로 자원 빼앗을 수 없음 | 선점 가능하게 변경 |
| **순환 대기** | P0→P1→...→Pn→P0 사이클 | 자원에 순서 부여 |

## 3. 답안 목차 템플릿

**문제**: "교착상태의 발생 조건과 예방/회피/탐지 기법을 설명하시오."

```
I. 교착상태 정의 & 자원할당 그래프
   
   [자원할당 그래프]
   프로세스 → 자원: 요청 간선
   자원 → 프로세스: 할당 간선
   사이클 존재 → 교착상태 가능성
   (단일 인스턴스: 사이클 = 교착 확정)

II. 교착상태 처리 전략

   1) 예방 (Prevention) - 4대 조건 중 하나 제거
      - 상호배제 제거: 불가 (공유 불가 자원 존재)
      - 점유대기 제거: 시작 시 모든 자원 요청 (자원 낭비)
      - 비선점 제거: 선점 가능하게 (구현 복잡)
      - 순환대기 제거: 자원 번호 순서대로 요청 ← 실용적

   2) 회피 (Avoidance) - 은행원 알고리즘
      
      [은행원 알고리즘]
      안전 상태 (Safe State): 모든 프로세스가 완료 가능한 순서 존재
      
      Max(i,j) = 프로세스 i가 자원 j를 최대 요청할 수 있는 수
      Allocation(i,j) = 현재 할당량
      Need(i,j) = Max(i,j) - Allocation(i,j)
      
      요청 수락 조건:
      1. Need(i) ≤ Available
      2. 가정 할당 후에도 안전 상태 유지

   3) 탐지 & 복구 (Detection & Recovery)
      - 탐지: 자원할당 그래프 사이클 탐지 주기적 수행
      - 복구:
        * 프로세스 종료 (비용 최소 프로세스 선택)
        * 자원 선점 (체크포인팅 + 롤백)

   4) 무시 (Ignore) - Ostrich Algorithm
      - 발생 빈도 낮으면 그냥 무시
      - UNIX/Windows의 일반적 접근

III. 현대적 적용
   - K8s: Pod 리소스 요청/제한으로 교착 예방
   - 분산 시스템: 분산 교착상태 탐지 (더 복잡)
   - DB: 교착상태 탐지 후 희생자 트랜잭션 롤백
```

## 4. 핵심 암기 포인트

- **4대 조건**: 상호배제 / 점유대기 / **비선점** / **순환대기**
- **은행원 알고리즘**: Need ≤ Available → 안전 상태 검사
- **실무**: DB 교착상태 → 희생자 트랜잭션 자동 롤백
