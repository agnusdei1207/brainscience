# 🎯 모놀리식 vs MSA 전환 전략

> **별점**: ★★★★★ | ★133회, ★135회 기출

## 1. 핵심 비교

| 항목 | 모놀리식 | MSA |
|------|---------|-----|
| 배포 | 전체 재배포 | 서비스별 독립 |
| 확장 | 전체 스케일아웃 | 서비스별 스케일 |
| 장애 격리 | 전체 영향 | 서비스별 격리 |
| 데이터 | 단일 DB | 서비스별 DB |
| 트랜잭션 | ACID 보장 | 사가 패턴 필요 |
| 복잡도 | 낮음 | 높음 (분산 복잡성) |
| 적합 | 초기 단계, 소규모 | 대규모, 빠른 배포 |

## 2. MSA 전환 핵심 패턴

```
[사가 패턴 (Saga) — 분산 트랜잭션]
Choreography (이벤트 기반):
  주문 → 이벤트 발행 → 결제/재고/배송 서비스 자율 반응
  장점: 서비스 독립 | 단점: 복잡한 이벤트 흐름 추적

Orchestration (중앙 조율):
  사가 오케스트레이터 → 각 서비스에 명령 발행
  장점: 흐름 명확 | 단점: 오케스트레이터 의존성

[Strangler Fig 전환 패턴]
레거시 → API 게이트웨이 앞단 → 점진적 서비스 분리 → 레거시 제거
```

## 3. 답안 포인트

**3단락**: ① 모놀리식 한계(배포/확장/장애) → ② MSA 아키텍처 설계(도메인 분리, API GW, 사가) → ③ 전환 전략(Strangler Fig) & 위험 관리

**핵심 주장**: "MSA는 기술이 아닌 조직 변화(콘웨이 법칙)와 함께 가야 성공"

## 4. 관련 개념

`사가패턴` → 분산 트랜잭션 | `API 게이트웨이` → 단일 진입점 | `DDD` → 도메인별 서비스 분리
