# 🎯 SOLID 원칙 & GoF 디자인 패턴

> **별점**: ★★★★☆ | 기본 필수

## 1. SOLID 5대 원칙

| 원칙 | 의미 | 위반 시 |
|------|------|--------|
| **S** — SRP | 단일 책임 원칙 (클래스는 한 가지 변경 이유) | 변경 파급효과 ↑ |
| **O** — OCP | 개방-폐쇄 원칙 (확장엔 열림, 변경엔 닫힘) | 기존 코드 수정 반복 |
| **L** — LSP | 리스코프 치환 원칙 (하위 타입은 상위 대체 가능) | 다형성 깨짐 |
| **I** — ISP | 인터페이스 분리 원칙 (작고 응집된 인터페이스) | 불필요 의존성 |
| **D** — DIP | 의존역전 원칙 (구체 아닌 추상에 의존) | 결합도 ↑ |

## 2. GoF 디자인 패턴 (23가지, 3분류)

```
[생성 패턴 — 객체 생성]
- Singleton: 인스턴스 1개 보장
- Factory Method: 서브클래스가 생성 결정
- Abstract Factory: 관련 객체 군 생성
- Builder: 복잡한 객체 단계별 생성

[구조 패턴 — 클래스/객체 조합]
- Adapter: 인터페이스 변환
- Decorator: 기능 동적 추가
- Proxy: 접근 제어, 지연 초기화
- Facade: 복잡한 서브시스템 단순 인터페이스

[행위 패턴 — 객체 간 통신]
- Observer: 이벤트 구독/발행 (EDA 기반)
- Strategy: 알고리즘 교체 가능
- Command: 요청을 객체로 캡슐화
- Template Method: 알고리즘 골격 정의
```

## 3. 답안 포인트

**3단락**: ① SOLID 원칙 정의 및 의의 → ② 주요 패턴 그룹별 특성 → ③ MSA/클린아키텍처와 SOLID 연계

## 4. 관련 개념

`DDD` → 도메인 모델에 SOLID 적용 | `TDD` → SOLID 준수 → 테스트 용이성 | `클린아키텍처` → DIP 기반
