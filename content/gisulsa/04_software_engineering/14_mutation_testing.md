# 🎯 뮤테이션 테스팅 (Mutation Testing)

> **별점**: ★★★★★ | ★133회 기출

## 1. 정의

뮤테이션 테스팅: 소스코드에 **의도적으로 결함(변이)을 주입**한 뮤턴트(Mutant)를 만들고, 기존 테스트가 해당 결함을 탐지(Kill)하는지 확인하여 **테스트 스위트의 실효성**을 측정하는 기법.

## 2. 동작 원리

```
[뮤테이션 테스팅 프로세스]
원본 코드
  ↓ 변이 연산자(Mutation Operator) 적용
뮤턴트 생성 (변이 코드들)
  ↓ 기존 테스트 스위트 실행
결과 분류:
  - Kill (사망): 테스트가 뮤턴트 탐지 ✓
  - Survive (생존): 테스트가 탐지 못함 ✗ → 테스트 보강 필요
  - Equivalent: 의미적으로 원본과 동일 (제외)

뮤테이션 점수 = Kill된 뮤턴트 수 / 전체 뮤턴트 수 × 100%
목표: 80% 이상 권장
```

## 3. 변이 연산자 종류

```
산술 연산자 변이: +→-, *→/
관계 연산자 변이: >→>=, ==→!=
논리 연산자 변이: &&→||, !제거
경계값 변이: >→>=, <→<=
상수 변이: 0→1, true→false
문장 삭제: 특정 문장 제거
```

## 4. 강점 vs 약점

| 강점 | 약점 |
|------|------|
| 테스트 품질 정량화 | 뮤턴트 수 많아 실행 시간 ↑ |
| 숨겨진 테스트 갭 발견 | 동등 뮤턴트 판별 어려움 |
| 자동화 가능 | 대규모 코드베이스 적용 비용 ↑ |

## 5. 답안 포인트

**3단락**: ① 뮤테이션 테스팅 정의 & 목적 → ② 프로세스(변이주입→테스트→Kill/Survive) & 점수 계산 → ③ 기존 커버리지 vs 뮤테이션 점수 비교 & 적용 한계

## 6. 관련 개념

`화이트박스 테스팅` → 뮤테이션은 고급 화이트박스 | `TDD` → TDD 테스트의 실효성 검증 | `CI/CD` → 파이프라인에 뮤테이션 통합
