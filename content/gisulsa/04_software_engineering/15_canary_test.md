# 🎯 카나리 테스트 & 배포 전략 (Blue-Green, Rolling, Canary)

> **별점**: ★★★★★ | ★132회 기출

## 1. 배포 전략 비교

| 전략 | 방식 | 장점 | 단점 |
|------|------|------|------|
| **롤링** | 순차적 인스턴스 교체 | 자원 절약 | 롤백 느림 |
| **블루-그린** | 두 환경 동시 운영, 전환 | 즉시 롤백 | 자원 2배 |
| **카나리** | 소수 트래픽 먼저 신버전 | 위험 최소화 | 모니터링 복잡 |
| **피처 플래그** | 코드 배포 후 기능 토글 | 기능별 제어 | 코드 복잡도 |

## 2. 카나리 배포 상세

```
[카나리 배포 흐름]
전체 트래픽 → 100% 구버전(v1)

Step 1: 5% 트래픽 → 신버전(v2)
         95% 트래픽 → v1
         ↓ KPI 모니터링 (오류율, 지연, 전환율)

Step 2: 문제 없으면 → 30% → v2
         오류 발생 → 즉시 0%로 롤백

Step 3: 50% → 100% 점진적 증가

도구: Kubernetes + Argo Rollouts, Istio
     AWS: CodeDeploy, App Mesh
     특징: 실제 사용자 트래픽으로 테스트
```

## 3. 블루-그린 배포

```
[Blue-Green 배포]
Blue (현재 운영): v1 ──→ DNS/LB 연결
Green (새 버전): v2 ──→ 테스트 완료 후

LB 전환: Blue → Green (즉시 전환, 다운타임 0)
문제 시: Green → Blue 즉시 롤백
단점: 자원 2배, DB 스키마 변경 복잡
```

## 4. 답안 포인트

**3단락**: ① 배포 전략 개요 & 비교 → ② 카나리 배포 단계별 프로세스 → ③ K8s/서비스메시 구현 & 모니터링

## 5. 관련 개념

`CI/CD 파이프라인` → 배포 전략 자동화 | `K8s(★133회)` → Argo Rollouts로 카나리 구현 | `SRE` → 에러 버짓 기반 카나리 판단
