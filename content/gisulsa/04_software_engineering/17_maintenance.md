# 🎯 SW 유지보수 & 3R (역공학/재공학/재구조화)

> **별점**: ★★★★★ | ★133회 기출

## 1. SW 유지보수 유형

| 유형 | 정의 | 비율 |
|------|------|------|
| **수정(Corrective)** | 결함 제거 | 약 17% |
| **적응(Adaptive)** | 환경 변화 대응 | 약 18% |
| **완전화(Perfective)** | 기능 개선·추가 | 약 60% |
| **예방(Preventive)** | 미래 문제 예방 | 약 5% |

## 2. 3R 기법

```
[역공학 (Reverse Engineering)]
기존 코드/시스템 → 설계 문서·명세 추출
목적: 문서 없는 레거시 시스템 이해
산출물: 자료흐름도, 클래스 다이어그램, ERD

[재구조화 (Restructuring)]
기능은 유지, 코드 구조만 개선
= 리팩토링과 동일 개념
예) 스파게티 코드 → 구조화 코드

[재공학 (Re-engineering)]
역공학 → 재설계 → 순공학 (전체 프로세스)
목적: 레거시 시스템을 현대화 (기능 개선 포함)
= 역공학 + 재구조화 + 순공학

[관계]
원본 시스템
   ↓ 역공학 → 설계 문서
      ↓ 재설계 (기능 개선)
      ↓ 순공학 → 새로운 시스템
= 재공학
```

## 3. 레거시 현대화 전략 (6R)

```
Retire: 폐기 (사용자 없음)
Retain: 유지 (현재 최적)
Rehost: 리호스팅 (클라우드 이전, Lift&Shift)
Replatform: 리플랫폼 (OS/DB 교체)
Refactor: 리팩터 (코드 재구성)
Rearchitect: 재아키텍처 (MSA 전환)
```

## 4. 답안 포인트

**3단락**: ① 유지보수 유형 & 완전화 위주 비중 → ② 3R 기법(역공학→재구조화→재공학) 상세 → ③ 레거시 현대화 6R 전략

## 5. 관련 개념

`기술부채` → 재공학으로 해소 | `애자일` → 지속적 리팩토링 | `클라우드 전환(★135회)` → 6R 전략 적용
