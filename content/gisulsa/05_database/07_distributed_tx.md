# 🎯 분산 트랜잭션 — 2PC, 3PC, 사가 패턴

> **별점**: ★★★★★ | ★132회 기출

## 1. 정의

분산 트랜잭션: 여러 노드에 걸친 트랜잭션에서 **전체 원자성** 보장 문제.

## 2. 2단계 커밋 (2PC, Two-Phase Commit)

```
[Phase 1: 준비(Prepare)]
코디네이터 → 참여자들: "커밋 준비됐나?"
참여자: 로그 기록 후 "Yes" or "No"

[Phase 2: 커밋(Commit)]
모두 Yes → 코디네이터: "커밋!"
하나라도 No → 코디네이터: "롤백!"

문제점:
- 코디네이터 장애 시 블록킹 (2PC 한계)
- 성능 저하 (2번의 라운드트립)
```

## 3. 사가 패턴 (Saga Pattern) — MSA의 해결책

```
[Choreography 방식]
주문서비스 → 이벤트(주문생성) → Kafka
  ↓
결제서비스 구독 → 결제 → 이벤트(결제완료)
  ↓
재고서비스 구독 → 재고감소 → ...

실패 시: 보상 트랜잭션(Compensating Transaction) 발행
예) 결제 실패 → 주문 취소 이벤트 발행

[Orchestration 방식]
사가 오케스트레이터가 각 서비스에 명령 전달
중앙 집중식 흐름 제어
```

## 4. 비교

| 항목 | 2PC | 사가 |
|------|-----|------|
| 일관성 | 강한 일관성 | 최종 일관성 |
| 성능 | 낮음 | 높음 |
| 장애 처리 | 블록킹 위험 | 보상 트랜잭션 |
| 적합 | 단일 DB | MSA/분산 |

## 5. 답안 포인트

**3단락**: ① 분산 트랜잭션 문제 정의 → ② 2PC 메커니즘 & 한계 → ③ 사가 패턴으로 MSA 해결

## 6. 관련 개념

`ACID` → 2PC로 분산 ACID 구현 | `MSA(★133·135회)` → 사가 패턴 필수 | `Kafka` → 사가 이벤트 브로커
