# 🎯 데이터 샤딩 & 복제 (Sharding & Replication)

> **별점**: ★★★★☆ | 기본 필수

## 1. 데이터 파티셔닝

```
[수평 파티셔닝 = 샤딩]
행(Row) 단위로 분할 → 여러 서버에 분산
예) 사용자 ID 1~100만: 샤드1, 100만~200만: 샤드2

[수직 파티셔닝]
열(Column) 단위로 분할 → 자주 쓰는 컬럼 분리
예) 사용자 기본정보 | 사용자 상세정보 (별도 테이블)

[샤딩 키 선택 기준]
- 균일한 분산 (핫스팟 방지)
- 주요 쿼리 패턴과 일치 (크로스 샤드 쿼리 최소화)
- 재샤딩 비용 고려
```

## 2. 샤딩 방식

```
[해시 샤딩]
shard = hash(key) % N
장점: 균일한 분산
단점: 샤드 추가 시 재분배 (Consistent Hashing으로 완화)

[범위 샤딩]
날짜, 알파벳 범위로 분할
장점: 범위 쿼리 효율
단점: 핫스팟 가능 (최신 날짜에 트래픽 집중)

[디렉토리 샤딩]
별도 조회 테이블로 키→샤드 매핑
유연하나 단일 장애점
```

## 3. 복제 (Replication)

```
[Master-Slave 복제]
Master(쓰기) → Slave(읽기 전용) 복제
읽기 부하 분산, Master 장애 시 Slave 승격

[Multi-Master]
모든 노드에서 쓰기 가능
충돌 해결 로직 필요

[쿼럼 (Quorum)]
W + R > N 보장 → 강한 일관성
N=3, W=2, R=2 → 항상 최신 데이터
```

## 4. 답안 포인트

**3단락**: ① 파티셔닝 종류(수평/수직) → ② 샤딩 방식(해시/범위/디렉토리) 비교 → ③ 복제 + 쿼럼으로 가용성 보장

## 5. 관련 개념

`CAP 정리(★134회)` → 샤딩+복제의 일관성-가용성 트레이드오프 | `Consistent Hashing` → 샤드 재분배 최소화 | `NoSQL` → 내장 샤딩/복제 지원
