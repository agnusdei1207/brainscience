# 🎯 데이터 웨어하우스 & OLAP

> **별점**: ★★★★★ | 기본 필수

## 1. DW 아키텍처

```
ETL 소스들 (ERP, CRM, 로그)
      ↓ ETL (Extract-Transform-Load)
Staging Area (임시 저장)
      ↓
데이터 웨어하우스 (주제별 통합)
      ↓ ↓ ↓
데이터 마트   데이터 마트   데이터 마트
(영업팀)      (마케팅)      (재무)
      ↓
OLAP 분석 / 리포팅 / AI/ML
```

## 2. 다차원 스키마

```
[스타 스키마]
팩트 테이블 (매출금액, 수량) — 측정값
  ↑ ↑ ↑ ↑
차원 테이블들: 날짜/상품/고객/지역
장점: 쿼리 단순, 성능 우수
단점: 데이터 중복

[눈꽃 스키마 (Snowflake)]
차원 테이블이 추가로 정규화
장점: 저장공간 절약
단점: 조인 복잡, 성능 저하

[OLAP 연산]
Roll-Up: 세부 → 요약 (일별→월별→연별)
Drill-Down: 요약 → 세부
Slice: 특정 차원 값 고정 (2024년만)
Dice: 여러 차원 조합
Pivot: 차원 축 변경
```

## 3. ELT vs ETL

```
ETL (Extract-Transform-Load):
  데이터 이동 전 변환 → 데이터 웨어하우스
  전통 방식, 소규모~중규모

ELT (Extract-Load-Transform):
  데이터 먼저 로드 → 데이터 레이크에서 변환
  빅데이터/클라우드 환경에 적합
  도구: dbt (data build tool)
```

## 4. 답안 포인트

**3단락**: ① DW 아키텍처(ETL→스테이징→DW→마트) → ② 스타/눈꽃 스키마 & OLAP 연산 → ③ 레이크하우스로의 진화 & ELT

## 5. 관련 개념

`레이크하우스(★★11번)` → DW의 진화 형태 | `데이터 메시(★135회)` → DW → 도메인별 데이터 제품 | `비즈니스 인텔리전스(BI)` → DW 활용
