# 🎯 핵심 키워드: TLS 1.3, 0-RTT, AEAD, 완전 순방향 비밀성 (PFS)

> **출제 빈도**: ★★★★★ | **기출**: ★136회

## 1. 정의

TLS 1.3(Transport Layer Security 1.3)은 2018년 RFC 8446으로 표준화된 최신 전송 계층 보안 프로토콜로, TLS 1.2 대비 **핸드셰이크 속도 개선**, **레거시 암호화 제거**, **완전 순방향 비밀성 기본화**가 핵심이다.

## 2. TLS 1.2 vs 1.3 비교

| 항목 | TLS 1.2 | TLS 1.3 |
|------|---------|---------|
| 핸드셰이크 | 2-RTT | **1-RTT** (재연결 시 **0-RTT**) |
| 암호화 | 선택적 | **AEAD 전용** (GCM, ChaCha20-Poly1305) |
| 키 교환 | RSA/DH 포함 | **ECDHE 전용** (PFS 필수) |
| 레거시 지원 | RC4, 3DES, SHA-1 | **완전 제거** |
| 세션 재개 | 세션 ID/티켓 | **PSK (Pre-Shared Key)** |

## 3. 답안 목차 템플릿

**문제**: "TLS 1.3의 개념과 TLS 1.2 대비 개선 사항을 설명하시오."

```
I. TLS 1.3 정의 및 등장 배경
   - TLS 1.2 문제: 핸드셰이크 복잡, 레거시 취약 알고리즘
   - 목표: 보안 강화 + 성능 개선 (웹 서비스 지연 감소)

II. TLS 1.3 핸드셰이크 (1-RTT)
   
   [TLS 1.3 핸드셰이크]
   클라이언트               서버
      │── ClientHello ──────→│  (key_share, cipher_suites)
      │← ─ServerHello ───────│  (key_share, 인증서, 완료)
      │   (서버 키 교환 완료)  │
      │── Finished ──────────→│  (클라이언트 완료)
      │← ─Application Data ──│
   ※ 1-RTT: TLS 1.2(2-RTT) 대비 절반으로 감소
   
   [0-RTT 재연결 (Session Resumption)]
   이전 세션의 PSK 사용 → 핸드셰이크 없이 즉시 데이터 전송
   ※ 단: 재전송 공격(Replay Attack) 위험 → 멱등 요청만 허용

III. 핵심 보안 강화 사항
   
   1) 완전 순방향 비밀성 (PFS, Perfect Forward Secrecy)
      - ECDHE 필수 → 세션 키가 장기 개인키와 독립
      - 장기 키 탈취 시에도 과거 세션 복호화 불가
   
   2) AEAD 암호화만 허용
      - AES-128-GCM, AES-256-GCM, ChaCha20-Poly1305
      - 인증 + 암호화 동시 수행 (무결성+기밀성)
   
   3) 취약 알고리즘 완전 제거
      - RSA 키 교환, RC4, MD5, SHA-1, 3DES 모두 제거

IV. 현대 적용
   - HTTP/3 (QUIC): TLS 1.3 기반 0-RTT 내장
   - mTLS (상호 인증): 서비스메시(Istio)에서 Pod 간 암호화
   - 핀테크/의료: HTTPS 필수화 + TLS 1.3 의무화 추세
```

## 4. 핵심 암기 포인트

- **1-RTT** = TLS 1.3 기본, **0-RTT** = 재연결 (재전송 공격 주의)
- **ECDHE 필수** = PFS 강제 → 과거 데이터 보호
- **AEAD 전용** = AES-GCM, ChaCha20-Poly1305만 허용

## 5. 관련 개념 연결

| 개념 | 연결 포인트 |
|------|------------|
| QUIC/HTTP3 (☆예측) | TLS 1.3 기반, 0-RTT 핵심 |
| mTLS | 서비스메시에서 TLS 1.3 상호인증 |
| PQC (☆예측) | TLS 1.3의 다음 단계 - 양자내성 암호 교체 |
| Zero Trust (★136회) | mTLS + TLS 1.3으로 내부 통신 암호화 |
