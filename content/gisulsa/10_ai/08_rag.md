# 🎯 핵심 키워드: RAG, 벡터 DB, 임베딩, 환각(Hallucination) 감소

> **출제 빈도**: ★★★★★ | **기출**: ★135회

## 1. 정의

RAG(Retrieval Augmented Generation)는 LLM이 응답 생성 시 **외부 지식베이스를 실시간 검색**하여 최신 정보와 맥락을 활용하는 기법이다. LLM의 학습 데이터 컷오프 문제와 환각(Hallucination) 문제를 해결한다.

## 2. 출제 포인트

| 포인트 | 내용 | 채점 비중 |
|--------|------|----------|
| 정의 | Fine-tuning vs RAG 차이 | 20% |
| 아키텍처 | 인덱싱→검색→증강→생성 파이프라인 | 35% |
| 벡터DB | 임베딩, 유사도 검색, FAISS/Pinecone | 25% |
| 한계 & 개선 | Chunk 크기, Reranking, GraphRAG | 20% |

## 3. 답안 목차 템플릿

**문제**: "RAG(검색 증강 생성)의 개념과 아키텍처를 설명하고, Fine-tuning과의 차이를 비교하시오."

```
I. RAG 정의 및 필요성
   
   LLM 한계:
   - 학습 데이터 컷오프: 최신 정보 부재
   - 환각(Hallucination): 존재하지 않는 정보 생성
   - 기업 내부 문서 미학습
   
   RAG 해결: 외부 지식베이스 + 실시간 검색 + LLM 결합

II. RAG 파이프라인 아키텍처
   
   [오프라인: 인덱싱]
   문서 수집 → 청크 분할 → 임베딩 모델 → 벡터 DB 저장
   
   [온라인: 검색+생성]
   사용자 질문
      ↓ 임베딩 변환
   벡터 DB 유사도 검색 (Top-K 문서 검색)
      ↓
   ┌──────────────────────────────┐
   │ 프롬프트 = 질문 + 검색된 컨텍스트 │
   └──────────────────────────────┘
      ↓ LLM 생성
   최종 답변 (근거 문서 포함)

III. 벡터 DB & 임베딩
   - 임베딩 모델: text-embedding-ada, BGE, E5
   - 유사도 검색: 코사인 유사도, L2 거리, 내적
   - 벡터 DB: Pinecone, Weaviate, Chroma, pgvector
   - 인덱스: FAISS (Facebook), HNSW (계층 그래프)

IV. Fine-tuning vs RAG 비교
   | 항목         | Fine-tuning         | RAG                  |
   |-------------|---------------------|----------------------|
   | 학습 방식    | 모델 가중치 업데이트  | 모델 변경 없음        |
   | 최신 정보    | 재학습 필요          | 실시간 업데이트 가능  |
   | 비용         | 높음 (GPU, 데이터)   | 낮음 (벡터DB 구축)   |
   | 환각         | 여전히 발생          | 근거 기반 → 감소     |
   | 적합 용도    | 특정 도메인 스타일   | 최신/내부 문서 Q&A   |

V. RAG 개선 기법
   - Reranking: BM25+벡터 하이브리드, Cross-encoder
   - GraphRAG: 지식 그래프 기반 엔티티 관계 검색
   - Agentic RAG: 에이전트가 검색 전략 자율 결정
   - Multimodal RAG: 이미지+텍스트 통합 검색
```

## 4. 핵심 암기 포인트

- **핵심 3단계**: 인덱싱(오프라인) → 검색 → 증강 생성
- **임베딩**: 문장 → 고차원 벡터 (의미 유사도 = 벡터 거리)
- **환각 감소**: 검색된 근거 문서 기반으로 생성 → 신뢰도 향상
