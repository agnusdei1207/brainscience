# 🎯 ADR (Architecture Decision Record) & ATAM

> **별점**: ★★★★★ | ★131회 기출

## 1. ATAM (Architecture Tradeoff Analysis Method)

```
정의: SW 아키텍처의 품질속성 요구사항에 대한
     트레이드오프를 체계적으로 분석하는 방법

[ATAM 4단계]
1. 아키텍처 제시: 설계자가 아키텍처 설명
2. 품질 속성 유틸리티 트리:
   - 목표: 성능, 가용성, 보안, 변경성
   - 시나리오: "동시 1000명 → 2초 이내"
3. 민감점 & 트레이드오프 식별:
   - 민감점: 특정 품질에 영향 큰 설계 결정
   - 트레이드오프: A ↑ → B ↓
4. 위험 및 비위험 결정 목록화

[ATAM 결과물]
- 유틸리티 트리 (품질 시나리오)
- 아키텍처 민감점 목록
- 트레이드오프 포인트
- 위험 목록
```

## 2. ADR (Architecture Decision Record)

```
정의: 중요한 아키텍처 결정과 그 이유를 문서화한 짧은 기록

[ADR 형식 (Michael Nygard)]
# ADR-001: MongoDB 선택 (날짜)

## 상태
수락됨

## 맥락 (Context)
사용자 활동 로그 저장 필요. 스키마 유연성 요구.
초당 10,000건 쓰기 필요.

## 결정 (Decision)
MongoDB를 메인 DB로 사용

## 결과 (Consequences)
긍정: 유연한 스키마, 수평 확장
부정: ACID 트랜잭션 제한 → 금융 데이터 불가
```

## 3. SW 아키텍처 평가 비교

| 방법 | 시기 | 방법 | 특징 |
|------|------|------|------|
| ATAM | 설계 후 | 분석 | 품질 트레이드오프 |
| SAAM | 설계 후 | 시나리오 | 변경성 중심 |
| CBAM | 설계 중 | 비용편익 | ROI 분석 |
| ADR | 지속적 | 문서화 | 결정 이력 추적 |

## 4. 답안 포인트

**3단락**: ① ATAM 정의 & 4단계 → ② 품질속성 트레이드오프 분석 예시 → ③ ADR과의 연계(결정 문서화)

## 5. 관련 개념

`SOLID` → 아키텍처 결정의 원칙 | `MSA(★133회)` → ATAM으로 MSA 전환 결정 분석 | `아키텍처 패턴` → 결정 후 ADR로 기록
