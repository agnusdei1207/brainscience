# 🎯 DDD (Domain Driven Design)

> **별점**: ★★★★☆ | ☆ 예측

## 1. DDD 핵심 개념

```
정의: 복잡한 비즈니스 도메인을 소프트웨어에 반영하기 위한
     설계 방법론. Eric Evans 제안(2003).

[전략적 설계]
바운디드 컨텍스트 (Bounded Context):
  명확한 경계를 가진 도메인 컨텍스트
  = "주문 컨텍스트", "결제 컨텍스트", "재고 컨텍스트"
  경계 안에서 유비쿼터스 언어(공통 언어) 사용

유비쿼터스 언어 (Ubiquitous Language):
  개발자+도메인 전문가가 공유하는 공통 언어
  코드 클래스명과 일치 → 코드가 도메인 설명

컨텍스트 맵 (Context Map):
  바운디드 컨텍스트 간 관계 정의
  Upstream/Downstream, ACL(변환 계층)
```

## 2. 전술적 설계 (Building Blocks)

```
[DDD 핵심 패턴]
엔티티 (Entity):
  고유 식별자를 가진 객체 (Order #12345)
  
값 객체 (Value Object):
  식별자 없음, 값으로 동등성 (Money(1000, "KRW"))
  
애그리게이트 (Aggregate):
  엔티티+값객체의 일관성 경계
  루트를 통해서만 외부 접근

도메인 이벤트 (Domain Event):
  "주문완료됨", "결제처리됨" → 다른 컨텍스트 통지

리포지토리 (Repository):
  도메인 객체 저장/조회 (DB 접근 추상화)

도메인 서비스 (Domain Service):
  어느 엔티티에도 속하지 않는 도메인 로직
```

## 3. DDD + MSA

```
[바운디드 컨텍스트 = MSA 서비스 경계]
주문 서비스 ← 바운디드 컨텍스트: 주문
결제 서비스 ← 바운디드 컨텍스트: 결제
재고 서비스 ← 바운디드 컨텍스트: 재고

컨텍스트 간 통신: 사가 패턴 (이벤트)
→ DDD가 MSA의 올바른 서비스 분리를 안내
```

## 4. 답안 포인트

**3단락**: ① DDD 전략적 설계(바운디드컨텍스트, 유비쿼터스언어) → ② 전술적 패턴(엔티티/VO/애그리게이트) → ③ MSA 연계(컨텍스트=서비스)

## 5. 관련 개념

`MSA(★133·135회)` → DDD로 서비스 경계 결정 | `CQRS` → DDD의 읽기/쓰기 모델 분리 | `사가 패턴` → DDD 이벤트 기반 컨텍스트 통신
