# 🎯 SP 품질인증 & 코드 인스펙션 (FTR)

> **별점**: ★★★★☆ | ★134회 연계

## 1. SP (소프트웨어 프로세스 품질인증)

```
KISA 주관의 SW 개발 프로세스 품질 인증 제도

[SP 인증 목적]
SW 개발 기업의 프로세스 역량 인증
공공사업 입찰 우대 (가점)
ISO 15504/CMMI 기반 평가

[SP 인증 레벨]
1등급: 프로세스 기본 수준
2등급: 프로세스 체계화
3등급: 표준 프로세스 수립 (CMMI 3과 유사)

평가 영역:
프로젝트 관리, 엔지니어링, 지원, 프로세스 관리
```

## 2. FTR (Formal Technical Review) — 코드 인스펙션

```
정의: 소프트웨어 산출물(코드, 설계서)을 조직적이고
     체계적으로 검토하는 품질 보증 활동

[FTR 역할]
작성자 (Author): 산출물 작성자
검토자 (Reviewer): 1~3인 전문 검토자
진행자 (Moderator): 검토 회의 진행
기록자 (Recorder): 결함 목록 기록

[FTR 프로세스]
계획 → 준비 (검토자 사전 검토) → 검토 회의
→ 재작업 → 추적 (결함 수정 확인)

[결함 분류]
1. 오류 (Error): 수정 필수
2. 이슈 (Issue): 논의 필요
3. 질문 (Question): 명확화 필요

[측정]
결함 밀도: 결함 수 / 코드 라인 수 (목표: 1개/KLOC)
인스펙션 속도: 200~500 LOC/시간
```

## 3. 인스펙션 vs 검사 vs 워크스루

| 방법 | 형식 | 목적 | 강도 |
|------|------|------|------|
| 인스펙션 | 공식, FTR | 결함 탐지 | 높음 |
| 검사 | 반공식 | 결함 탐지 | 중간 |
| 워크스루 | 비공식 | 교육, 이해 | 낮음 |

## 4. 답안 포인트

**3단락**: ① SP 인증 목적 & 레벨 → ② FTR(코드 인스펙션) 프로세스 & 역할 → ③ 인스펙션 효과(조기 결함 발견 = 비용 10배 절감)

## 5. 관련 개념

`CMMI(★★04_sw 23번)` → SP 인증과 동일 맥락 | `기술부채` → FTR로 조기 발견 | `TDD` → FTR + TDD = 이중 품질망
