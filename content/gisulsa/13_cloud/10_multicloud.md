# 🎯 멀티클라우드 & 하이브리드 클라우드

> **별점**: ★★★★★ | ★135회 기출

## 1. 클라우드 전략 비교

| 전략 | 정의 | 장점 | 단점 |
|------|------|------|------|
| **퍼블릭** | CSP 단독 (AWS/Azure/GCP) | 단순, 저비용 | 벤더 락인 |
| **프라이빗** | 자체 구축 사설 클라우드 | 보안, 통제 | 초기 비용 ↑ |
| **하이브리드** | 퍼블릭+온프레미스 연결 | 유연성, 규제 | 복잡도 ↑ |
| **멀티클라우드** | 여러 CSP 동시 사용 | 락인 방지 | 관리 복잡 |

## 2. 멀티클라우드 아키텍처

```
[멀티클라우드 적용 이유]
벤더 다양화: AWS + Azure 병행 (락인 방지)
지역 최적화: AWS(북미) + 알리바바(중국)
서비스 최적화: GCP AI + AWS EC2
규제 준수: 데이터 상주 요건

[멀티클라우드 과제]
통합 관리: 각 CSP마다 다른 API/CLI
비용 복잡: 여러 청구서 통합 분석
보안: 일관된 정책 적용 어려움
네트워크: CSP 간 전송 비용 발생

[해결 도구]
Terraform: 멀티클라우드 인프라 코드 (IaC)
Kubernetes: 멀티클라우드 오케스트레이션
Anthos (GCP), Arc (Azure): 멀티클라우드 관리
```

## 3. 하이브리드 클라우드

```
[연결 방식]
VPN: 인터넷 기반, 저비용, 보안 우려
전용선: AWS Direct Connect, Azure ExpressRoute
  → 안정적, 고대역폭, 고비용

[데이터 동기화 패턴]
Active-Passive: 온프레미스 주, 클라우드 DR
Active-Active: 동시 운영, 고가용성
Burst-to-Cloud: 피크 시 클라우드 확장

[보안]
SD-WAN: 소프트웨어 정의 WAN 연결
SASE: SD-WAN + 클라우드 보안 통합
Zero Trust: 위치 무관 인증
```

## 4. 답안 포인트

**3단락**: ① 퍼블릭/프라이빗/하이브리드/멀티 비교 → ② 멀티클라우드 적용 이유 & 과제 → ③ Terraform/K8s 도구 & 하이브리드 연결 방식
