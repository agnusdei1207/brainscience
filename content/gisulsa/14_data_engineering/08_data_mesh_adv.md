# 🎯 데이터 메시 & 데이터 패브릭

> **별점**: ★★★★★ | ★135회 기출

## 1. 데이터 메시 (Data Mesh)

```
정의: 데이터를 중앙화하지 않고, 비즈니스 도메인 팀이
     자신의 데이터를 제품으로 소유·관리하는 분산 아키텍처

[기존 중앙 데이터 레이크 문제]
병목: 데이터 팀 = 모든 요청 처리 → 속도 저하
품질: 도메인 지식 부족 → 데이터 품질 저하
사일로: 중앙 팀 vs 비즈니스 팀 갈등

[데이터 메시 4원칙 (Zhamak Dehghani)]
1. 도메인 소유: 각 도메인이 데이터 소유·책임
2. 데이터 제품: 데이터를 제품처럼 설계
   FAIR 원칙: 발견 가능, 주소 지정, 자기 기술, 상호운용
3. 셀프서비스 플랫폼: 도메인이 독립적으로 운영 가능한 인프라
4. 연합 거버넌스: 중앙 표준 + 도메인 자율성

[데이터 메시 예시]
주문 도메인 → 주문 데이터 제품 (Order Data Product)
고객 도메인 → 고객 데이터 제품
재무 도메인 → 재무 데이터 제품
각 제품: REST API, Kafka 토픽, 데이터 카탈로그 등록
```

## 2. 데이터 패브릭 (Data Fabric)

```
정의: 이기종 데이터 소스를 지능적으로 통합하는
     아키텍처 (Gartner 정의)

vs 데이터 메시:
  메시: 조직·문화 변화 (사람 중심)
  패브릭: 기술 자동화 (기술 중심)
  → 상호 보완적 (함께 사용 가능)

[데이터 패브릭 핵심 기술]
능동적 메타데이터: AI가 데이터 관계 자동 탐색
그래프 기반 지식: 데이터 관계를 그래프로 표현
자동화된 통합: AI가 ETL 변환 자동 제안
실시간 거버넌스: 정책 자동 적용

[도구]
Alation, Collibra, IBM Watson Knowledge Catalog
Informatica IDMC: 대표적 패브릭 플랫폼
```

## 3. 답안 포인트

**3단락**: ① 데이터 메시 4원칙 & 중앙 레이크 문제 → ② 데이터 제품 개념 & FAIR 원칙 → ③ 데이터 패브릭 vs 메시 비교 & 상호보완

## 4. 관련 개념

`레이크하우스(05_db)` → 메시의 기반 인프라 | `데이터 카탈로그(16_bigdata)` → 메시 데이터 제품 등록 | `MLOps(10_ai)` → 메시 + ML 피처 스토어
