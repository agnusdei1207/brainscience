## 0. 핵심 인사이트

> **핵심**: 상태도 (State Diagram)는 시스템의 모든 유효 상태와 입력에 따른 전이(Transition) 과정, 그리고 그에 따른 출력을 방향성 그래프로 추상화한 설계 모델이다.
> **비유**: 특정 장소에서 어떤 교통수단을 타면 어디로 이동할 수 있는지 모든 경로를 한눈에 보여주는 노선도와 같다.

## 1. 개요 및 필요성

유한 상태 기계(FSM)와 순차 논리회로는 현재의 입력뿐만 아니라 시스템이 기억하고 있는 "과거의 상태"에 의해 다음 행동이 결정된다. 이러한 복잡한 동적 동작을 단순한 글이나 코드만으로 설계하면 예외 조건을 누락하거나 논리적 오류를 범하기 쉽다. 상태도는 시스템의 행동 규칙을 시각적으로 명확하게 정의하여, 논리 회로 구현 전 설계의 결함을 검증하고 개발자 간 소통을 돕는 필수적인 표준 명세 도구다.

---

## 2. 구성요소

| 요소 | 역할 | 핵심 포인트 |
|:---|:---|:---|
| 상태 노드 (State Node) | 시스템이 머무는 특정 시점의 상황 | 원(Circle)으로 표현하며 상태명 또는 변수 할당 |
| 전이 화살표 (Transition) | 한 상태에서 다른 상태로 넘어가는 흐름 | 방향성 화살표로 경로 표시 |
| 전이 조건 (Input Condition) | 상태를 변화시키는 외부 트리거 자극 | 화살표 위에 논리식이나 신호 값으로 명시 |
| 출력 (Output) | 특정 상태나 전이 과정에서 외부로 내보내는 결과 | 무어(Moore) 기계는 노드 내, 밀리(Mealy) 기계는 화살표 위 표시 |

---

## 3. 구조 및 원리

**핵심 조건**: 동일한 상태 노드에서 출발하는 모든 전이 조건은 상호 배타적(Mutually Exclusive)이어야 하며 전체 집합(Exhaustive)을 포괄해야 한다.

동작 순서:
1. 시스템의 시작 노드(Reset/Init State)를 명시
2. 현재 상태에서 발생 가능한 모든 입력 조건을 도출
3. 입력에 따라 이동할 다음 상태(Next State)로 화살표 연결
4. 무어 기계 또는 밀리 기계 모델에 따라 적절한 위치에 출력 값 정의
5. 미정의 입력이나 비정상 상태 발생 시 안전 상태로 돌아오는 예외 경로 추가

```text
       Input=1 / Output=0
      ┌──────────────────┐
      ▼                  │
( State A ) ──Input=0──▶ ( State B )
      │       Output=1       ▲
      └───────Input=1────────┘
              Output=0
```

## 4. 비교 및 연결

| 항목 | 상태도 (State Diagram) | 상태표 (State Table) | 순서도 (Flowchart) |
|:---|:---|:---|:---|
| 표현 방식 | 노드와 화살표의 방향성 그래프 | 조건과 상태 값을 정리한 매트릭스 표 | 알고리즘의 순차적 흐름 도형 |
| 강점 | 전체 시스템 행동과 예외 경로 시각적 파악 | 논리식 최적화 및 회로 구현용 수식 도출 | 데이터 처리 및 소프트웨어 절차 명세 |
| 단점 | 상태 수가 많아지면 그래프가 매우 복잡해짐 | 직관적인 전체 흐름 파악이 어려움 | 하드웨어 클럭 동기화 표현의 한계 |

상태도는 복잡한 시스템의 행동 명세를 사람이 직관적으로 파악하도록 돕는다. 반면 상태표는 상태도를 기반으로 실제 하드웨어 게이트 조합을 최적화(K-Map 등)하기 위해 논리 값을 맵핑하는 데 유리하다. 실무에서는 상태도로 설계를 검증한 뒤 상태표로 변환하여 합성하는 상호 보완적 단계를 거친다.

---

## 5. 실무 적용 및 판단

**채택**: 네트워크 프로토콜 명세 작성, 복잡한 하드웨어 FSM 제어기 설계, 게임 캐릭터 행동 패턴(AI) 설계
**회피**: 입력 변수와 상태의 조합이 기하급수적으로 많은 시스템, 단순 조합 논리만으로 해결 가능한 연산 블록

체크리스트:
1. 전원을 켜거나 오류 발생 시 시스템을 원복 시키는 명확한 리셋(Reset) 전이 경로가 있는가?
2. 특정 상태에서 정의되지 않은 입력이 들어올 때 시스템이 정지(Deadlock)하지 않는가?
3. 무어 기계와 밀리 기계의 출력 특성을 구분하여 타이밍 마진에 맞게 설계했는가?

---

## 6. 기대효과 및 결론

상태도를 통한 설계는 개발 단계에서 논리적 결함(Deadlock, Unreachable State) 조기에 식별하여 시스템의 신뢰성을 극대화한다. 또한 추상화된 행동 모델은 하드웨어 기술 언어(HDL)나 소프트웨어 코드로 기계적 변환이 가능하다는 강력한 이점을 지닌다. 결론적으로 상태도는 시스템의 모든 가능성을 통제 가능한 규칙으로 시각화하는 디지털 설계의 첫 단추다.

---

## 7. 발전 흐름도

```text
시스템 요구사항 분석
    ↓
상태도 (State Diagram) 작성 및 검증
    ↓
상태표 (State Table) 변환
    ↓
FSM 로직 최적화 및 회로 합성
```

## 8. 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| 유한 상태 기계 (FSM) | 상태도로 묘사되는 대상 자체로 유한한 상태를 갖는 시스템 |
| 무어 기계 (Moore Machine) | 시스템 출력이 오직 "현재 상태"에 의해서만 결정되는 모델 |
| 밀리 기계 (Mealy Machine) | 시스템 출력이 "현재 상태"와 "현재 입력" 모두에 의해 결정되는 모델 |
| 상태표 (State Table) | 상태도의 시각적 전이 규칙을 플립플롭 설계를 위해 논리 표로 변환한 형태 |
