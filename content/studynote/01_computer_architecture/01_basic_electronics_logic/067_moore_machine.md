## 0. 핵심 인사이트

> **핵심**: 무어 머신 (Moore Machine)은 출력이 오직 "현재 상태"에 의해서만 결정되는 순차 논리 모델이다.
> **비유**: 외부에서 무슨 말을 해도, 자기가 입고 있는 유니폼(상태)에 정해진 행동만 하는 경비원과 같다.

---

> 📝 모범 답안

## 1. 개요 및 필요성

제어 시스템에서는 입력의 미세한 떨림(Glitch)이 출력으로 바로 전달되면 안 되는 경우가 많다. 무어 머신 (Moore Machine)은 출력을 현재 상태에만 동기화하여 이러한 비동기적 노이즈를 차단한다. 입력 신호가 출력에 직접적인 영향을 주지 않으므로, 타이밍 분석이 쉽고 동작의 안정성을 보장할 수 있다.

---

## 2. 구성요소

| 요소 | 역할 | 핵심 포인트 |
|:---|:---|:---|
| 상태 레지스터 (State Register) | 현재 상태를 저장 | 클럭 에지에서만 갱신 |
| 다음 상태 논리 (Next State Logic) | 입력과 현재 상태로 다음 상태 계산 | 조합 논리회로로 구현 |
| 출력 논리 (Output Logic) | 현재 상태만으로 출력 결정 | 입력 변수 개입 없음 |

---

## 3. 구조 및 원리

**핵심 조건**: 출력식 $Z(t)$는 현재 상태 $S(t)$만의 함수여야 한다. ($Z(t) = f(S(t))$)

동작 순서:
1. 클럭 에지가 발생하면 상태 레지스터가 다음 상태로 갱신된다.
2. 갱신된 "현재 상태"가 출력 논리로 전달된다.
3. 출력 논리는 오직 이 상태 값만 해독하여 최종 출력을 내보낸다.
4. 동시에 다음 상태 논리는 외부 입력과 현재 상태를 받아들인다.
5. 연산된 다음 상태가 다음 클럭 에지를 대기한다.

```
[입력] ─→ (다음 상태 논리) ─→ [상태 레지스터] ─→ (출력 논리) ─→ [출력]
```

---

## 4. 비교 및 연결

| 항목 | 무어 머신 (Moore Machine) | 밀리 머신 (Mealy Machine) |
|:---|:---|:---|
| 출력 결정 요인 | 현재 상태 | 현재 상태 + 현재 입력 |
| 상태 수 | 상대적으로 많음 (출력마다 상태 분리) | 상대적으로 적음 |
| 타이밍 (반응성) | 클럭 에지 이후 출력 변경 (지연 발생) | 입력 변화 즉시 출력 변경 (빠름) |

무어 머신은 출력이 클럭 주기에 엄격히 동기화되므로 글리치(Glitch)에 강하지만 반응이 한 클럭 늦어질 수 있다. 반면 밀리 머신은 반응이 빠르나 입력 노이즈가 출력에 섞일 위험이 크다.

---

## 5. 실무 적용 및 판단

**채택**: 글리치 없는 안정적인 제어 신호가 필요한 경우, 파이프라인 제어기, 엘리베이터 컨트롤러
**회피**: 입력 변화에 즉각(비동기적) 반응해야 하거나 상태 수를 극단적으로 줄여야 하는 하드웨어 설계

체크리스트:
1. 출력이 정말로 현재 상태에만 의존하게 설계되었는가?
2. 한 클럭 주기 지연이 시스템 요구사항을 위배하지 않는가?
3. 불필요하게 상태 수가 증가하여 하드웨어 자원을 낭비하지 않는가?

---

## 6. 기대효과 및 결론

안정적이고 예측 가능한 타이밍 설계를 통해 검증이 매우 용이해진다. 한계는 밀리 머신보다 상태 수가 늘어나 플립플롭과 조합 논리 면적이 증가할 수 있다는 점이다. **무어 머신은 속도보다 "안전하고 글리치 없는 출력"이 최우선일 때 선택하는 FSM 표준 모델이다.**

## 7. 발전 흐름도

```
FSM 기초 개념
    ↓
밀리 머신 (반응 최적화) vs 무어 머신 (안정성 최적화)
    ↓
클럭 동기화 제어 회로 (MCU, CPU Control Unit)
```

---

## 8. 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| FSM (Finite State Machine) | 무어 머신이 속하는 유한 상태 기계의 범주 |
| 글리치 (Glitch) | 무어 머신이 차단하고자 하는 조합 논리의 원치 않는 신호 흔들림 |
| 밀리 머신 (Mealy Machine) | 출력 결정 방식이 다른 대척점의 모델 |
| 상태 할당 (State Assignment) | 상태 수를 최소화하여 논리를 단순화하는 기법 |
