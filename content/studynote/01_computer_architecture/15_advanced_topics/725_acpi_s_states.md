## 0. 핵심 인사이트

> **핵심**: 앞서 배운 C-State(코어), P-State(성능)가 **CPU 하나만의 미시적인 전력 관리**라면, **S-State (Sleep States)**는 램(RAM), 하드디스크, 모니터, 메인보드를 포함한 **컴퓨터 시스템 전체의 거시적인 수면 상태**를 뜻한다.
> **비유**: S3(절전 모드)는 직원이 하던 일을 책상(RAM) 위에 그대로 다 펼쳐두고, 불 끄고 잠깐 자러 간 상태입니다. 부르면 바로 일어납니다. 단, 도둑이 들어와서 책상을 엎어버리면(정전) 큰일 납니다.

## 1. 개요 및 필요성

ACPI(고급 구성 및 전원 인터페이스) 규격은 시스템의 전원 상태를 S0부터 S5까지 6단계로 나눕니다.

* **S0 (Working)**
  컴퓨터가 정상적으로 켜져서 돌아가는 중입니다. (화면 켜짐, 팬 돌아감)
* **S1 / S2 (Power on Suspend)**
  초창기 절전 모드. CPU와 RAM에 전기가 다 들어가 있고 단순히 화면과 하드디스크만 끕니다. 전기 소모가 너무 많아 요즘은 안 씁니다.
* **S3 (Suspend to RAM / Sleep)**
  우리가 흔히 쓰는 **"절전 모드"**입니다.
  CPU, 하드디스크, 쿨링팬의 전원 플러그를 물리적으로 뽑아버립니다. 오직 **RAM(메모리)에만 대기 전력을 줘서 데이터가 증발하지 않게 꽉 붙잡고 있습니다.** 마우스를 흔들면 RAM의 기억을 바탕으로 1초 만에 화면이 뜹니다. 단점: 컴퓨터 콘센트(배터리)를 뽑으면 RAM이 죽어서 작업하던 내용이 다 날아갑니다.

## 2. 구성요소

| 요소 | 역할 | 핵심 포인트 |
|:---|:---|:---|
| 핵심 대상 | ACPI S-States (S0 ~ S5)에서 직접 다루는 연산, 자원, 상태, 지표 | 문제 정의와 측정 기준을 먼저 명확히 해야 함 |
| 제어 메커니즘 | 동작을 결정하는 규칙, 신호, 정책, 알고리즘 | 성능과 안정성의 균형을 좌우 |
| 구현 자원 | 회로, 메모리, 인터커넥트, 전력, 소프트웨어 협력 요소 | 병목과 비용의 직접 원인 |
| 결과/출력 | 처리 결과, 상태 변화, 품질 지표, 후속 제어 신호 | 상위 계층의 의사결정 근거 |

* **S4 (Suspend to Disk / Hibernation)**
  윈도우의 **"최대 절전 모드"**입니다.
  OS가 RAM에 있는 모든 데이터를 C드라이브(SSD)의 찌꺼기 파일(`hiberfil.sys`)로 복사해 버립니다. 복사가 끝나면 RAM, CPU 할 것 없이 컴퓨터의 **전원 코드를 완전히 뽑아버린 것과 동일한 0W 소모 상태**가 됩니다. 콘센트를 뽑고 이사가도 됩니다. 나중에 전원 버튼을 누르면, SSD에 저장된 파일을 다시 RAM으로 퍼 올려서(복구) 끄기 직전의 화면을 그대로 띄워줍니다. (부팅 시간 10초 내외)
* **S5 (Soft Off)**
  윈도우에서 **"시스템 종료"**를 누른 상태입니다. RAM 데이터를 저장하지 않고 그냥 싹 다 버리고 끕니다.
  (단, 메인보드 끄트머리에 랜선으로 전원을 켜는 Wake-on-LAN(WOL)이나 전원 버튼 인식을 위해 아주 미세한 전류만 흐르고 있습니다.)

## 3. 구조 및 원리

**핵심 조건**: ACPI S-States (S0 ~ S5) 적용 시 입력 조건, 내부 상태, 제약 자원이 함께 맞물려야 기대한 동작이 성립한다.

스마트폰의 화면을 껐다고 생각해 봅시다. 화면은 까맣고 잠을 자고 있지만, 카톡이 오면 즉시 띠링! 하고 알림이 옵니다. 스마트폰은 S3(절전 모드)에 들어간 걸까요?

아닙니다. 만약 스마트폰이 S3 상태라면 CPU와 랜카드가 완전히 꺼져있기 때문에 카톡을 받을 수 없습니다. 카톡을 받으려면 CPU가 1초라도 깨어나서 확인해야 합니다.
전통적인 S3 모드는 "한 번 자면 외부에서 마우스를 흔들기 전까지는 완벽하게 뻗어있는" 멍청한 수면입니다.

현대의 노트북(Intel Evo, 맥북 등)과 스마트폰은 이 멍청한 S3를 버리고, **화면이 꺼져있을 때도 백그라운드에서 CPU가 0.01초씩 깼다 잤다를 반복하며 이메일을 수신하는 스마트한 수면 모드**로 진화했습니다. 이것이 다음 장에서 다룰 **S0ix (Modern Standby)**입니다.

동작 순서:
1. 입력값, 상태 정보, 제어 조건이 먼저 정의된다.
2. 내부 구성요소가 정해진 규칙에 따라 상호작용하며 핵심 처리가 수행된다.
3. 처리 결과가 출력, 상태 갱신, 후속 제어 신호로 연결되어 다음 단계 동작을 결정한다.

```text
[입력 / 상태 / 제어 조건]
            ↓
     [핵심 처리 로직]
            ↓
    [출력 / 상태 갱신 / 효과]
```

## 4. 비교 및 연결

| 관점 | 기본 접근 | 최적화/확장 접근 |
|:---|:---|:---|
| 초점 | 기능을 성립시키는 최소 구조 | 성능·전력·확장성까지 함께 최적화 |
| 장점 | 구현과 이해가 단순함 | 대규모 시스템에서 효율이 높음 |
| 주의점 | 병목과 한계가 빨리 드러남 | 검증·설계 복잡도와 비용이 증가 |

ACPI S-States (S0 ~ S5)를 비교할 때는 단순한 우열보다 어떤 제약 조건에서 어느 방식이 더 적합한지 판단하는 것이 중요하다. 같은 기술도 워크로드, 전력 예산, 검증 난이도, 호환성에 따라 최적 해가 달라진다.

## 6. 기대효과 및 결론

ACPI S-States (S0 ~ S5)는 단일 기능으로 끝나는 개념이 아니라, 성능·전력·복잡도·확장성 사이의 균형점을 설계자가 어디에 두는지에 따라 가치가 달라지는 아키텍처 요소다. 앞서 살펴본 구조, 비교, 실무 판단 기준을 종합하면 핵심은 특정 기술을 맹목적으로 채택하는 것이 아니라 시스템 전체 경로에서 병목과 제약을 함께 읽는 데 있다.

또한 실제 효과는 주변 계층과의 정합성이 확보될 때 비로소 나타난다. 하드웨어 단독 최적화만으로는 충분하지 않으며, 소프트웨어 스택·운영 정책·검증 체계·배치 환경까지 함께 맞물려야 안정적인 개선으로 연결된다.

향후에는 더 높은 집적도, 이기종 결합, 자동화된 제어, 보안 강화 요구가 커지면서 ACPI S-States (S0 ~ S5) 역시 정적 규칙보다 적응형 정책과 도메인 특화 구조 쪽으로 발전할 가능성이 높다. 따라서 실무에서는 개별 장점보다 전체 시스템 균형 속의 채택 타당성을 최종 판단해야 한다.
