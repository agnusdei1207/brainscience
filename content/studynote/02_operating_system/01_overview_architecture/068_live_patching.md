## 0. 핵심 인사이트

> **핵심**: Live Patching은 커널 재부팅 없이 취약점이나 버그를 패치하는 기술이다.
> **비유**: 동적 커널 패치 (Live Patching)은(는) 복잡한 교통을 한 번에 통제해 전체 흐름을 맞추는 신호 체계와 같다.

---

📝 모범 답안

## 1. 개요 및 필요성

운영 중인 서버를 재부팅하면 서비스가 끊길 수 있다. Live Patching은 이 문제를 줄이기 위해 등장했다.

그래서 고가용성 환경에서 특히 중요하다.

---

## 2. 구성요소

```text
Kernel Bug
  ↓
Live Patch
  ↓
Redirect / Replace
  ↓
Patched Kernel
```

| 구성 요소 | 역할 |
| :-- | :-- |
| Patch Module | 수정 코드 |
| Hot Update | 실시간 적용 |
| Consistency | 일관성 유지 |

Live Patching은 기존 커널 함수 실행을 새 코드로 전환하는 방식으로 동작한다. 커널 상태를 깨지 않도록 설계하는 것이 중요하다.

---

## 3. 구조 및 원리

**핵심 조건**: 운영체제의 해당 메커니즘은 현재 상태 정보, 자원 제약, 정책 기준이 함께 정합성을 가질 때 안정적으로 동작한다.

동작 순서:
1. **요청 또는 이벤트 발생**: 사용자 요청, 인터럽트, 시스템 호출 등으로 커널이 해당 기능을 처리할 필요가 생긴다.
2. **현재 상태 확인**: 커널은 큐, 제어 블록, 메타데이터, 자원 가용량을 확인해 실행 가능 여부와 우선순위를 판단한다.
3. **정책 적용 및 자원 배정**: 해당 주제의 핵심 정책에 따라 상태 전이, 자원 할당, 보호 검사를 수행한다.
4. **결과 반영 및 후속 처리**: 처리 결과를 시스템 상태에 기록하고 다음 인터럽트·스케줄링·복구 단계로 연결한다.

| 방식 | 재부팅 | 장점 | 한계 |
| :-- | :-- | :-- | :-- |
| Reboot Patch | 필요 | 단순 | 다운타임 |
| Live Patching | 불필요 | 가용성 유지 | 적용 범위 제한 |
| LKM | 불필요 | 모듈화 | 기능 추가 중심 |

| 구현 | 특징 |
| :-- | :-- |
| kpatch | 커널 패치 프레임워크 |
| kGraft | 실시간 커널 업데이트 |

Live Patching은 장애 대응보다 예방적 보안 패치에 특히 유용하다.

## 5. 실무 적용 및 판단

### 체크리스트

1. 재부팅 없이 패치 가능한가?
2. 패치 적용 범위가 명확한가?
3. 커널 상태 안전성을 보장하는가?
4. 롤백 전략이 있는가?
5. 지원 환경과 버전 제약을 아는가?

### 안티패턴

- 모든 패치를 라이브로 해결하려는 설계
- 적용 범위와 호환성을 무시하는 설계
- 롤백 계획 없이 적용하는 설계
- 안정성 검증 없이 운영하는 설계

기술사 관점에서는 Live Patching을 "무중단 패치"로 설명하되, 제약과 운영 절차까지 함께 말해야 한다.

---

## 6. 기대효과 및 결론

Live Patching은 커널 취약점 대응과 가용성 유지에 도움이 된다. 그래서 운영 환경에서 매우 유용하다.

결론적으로 Live Patching은 재부팅 없이 커널을 수정하는 기술이다.
