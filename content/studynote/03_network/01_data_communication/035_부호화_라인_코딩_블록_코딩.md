## 0. 핵심 인사이트

> **핵심**: **핵심 인사이트**
> **비유**: 035. 부호화 — 라인 코딩 & 블록 코딩은(는) 데이터통신 기초와 신호 처리 안에서 데이터와 제어 규칙을 질서 있게 맞춰 주는 교통 체계와 같다.

> 📝 모범 답안

## 1. 개요 및 필요성

```
코딩 방식     신호 파형 예시 (0과 1이 교대)
────────────────────────────────────────
NRZ-L:      ─┐  ┌─ ─┐  ┌─    (Low=0, High=1)
             └──┘   └──┘

NRZ-I:      ─┐  ──┐  ──┐     (변화=1, 유지=0)
             └──   └──   └──

Manchester: ─┐ ┌┐ ┌┐ ┌─      (하강엣지=1, 상승엣지=0)
             └─┘ └─┘ └─

4B/5B+NRZ-I: 4비트를 5비트로 변환 후 NRZ-I
```

| 방식       | DC 성분 | 동기화 | 효율      | 사용처        |
|------------|---------|--------|-----------|---------------|
| NRZ-L      | 있음    | 불량   | 100%      | 단거리        |
| NRZ-I      | 있음    | 보통   | 100%      | USB 2.0       |
| Manchester | 없음    | 우수   | 50%       | 이더넷 10BASE |
| AMI        | 없음    | 보통   | 100%      | T1 라인       |
| MLT-3      | 적음    | 보통   | 100%      | Fast Ethernet |

## 2. 구성요소

```
원본 데이터 (m비트)
      │ 변환 테이블 참조
      ▼
부호화된 코드워드 (n비트, n > m)
      │ 라인 코딩 적용
      ▼
물리 신호 전송
```

### 4B/5B 코딩 (Fast Ethernet)

| 4B 입력 | 5B 출력 | 의미          |
|---------|---------|---------------|
| 0000    | 11110   | 유효 코드     |
| 0001    | 01001   | 유효 코드     |
| ...     | ...     | (32개 중 16개 사용) |
| 11111   | —       | (연속 1 금지) |

- 5비트 중 연속 0이 3개 이상인 조합을 제외 → 동기화 보장
- 전송 오버헤드: 25% (m=4→n=5)

### 8B/10B 코딩 (Gigabit Ethernet, Fibre Channel)

- 8비트 → 10비트 (오버헤드 25%)
- **RD (Running Disparity)**: +RD/-RD 상태 교대로 DC 균형 유지
- 최대 연속 동일 비트: 5개 이하 보장

### 64B/66B 코딩 (10G+ Ethernet)

- 오버헤드 3.125% (8B/10B 대비 대폭 감소)
- 2비트 헤더(10 또는 01)로 프레임 경계 표시

## 3. 구조 및 원리

**핵심 조건**: 035. 부호화 — 라인 코딩 & 블록 코딩은(는) 대역폭, 지연, 신호 대 잡음비 조건을 함께 만족할 때 안정적으로 동작한다.

동작 순서:

```
연속 0만 전송 시 문제:
물리 신호 = 계속 낮은 전압
    → 수신측 클럭 회로가 엣지 감지 불가 → 동기 손실
    → 직류 결합(DC coupling) 회로 포화

해결책:
① 라인 코딩으로 전압 변화 강제 (Manchester)
② 블록 코딩으로 연속 동일비트 패턴 제거 (8B/10B)
③ 스크램블링(Scrambling): XOR 기반 의사 랜덤 패턴
```

## 4. 비교 및 연결

| 비교 항목   | 블록 코딩 (8B/10B) | 스크램블링 (PRBS) |
|------------|-------------------|-------------------|
| 방식        | 변환 테이블        | XOR 패턴          |
| DC 균형    | 보장               | 확률적            |
| 오버헤드   | 25%               | 0%                |
| 복잡도     | 높음               | 낮음              |
| 사용처     | Fibre Channel, PCIe | 100G+ Ethernet   |

## 5. 실무 적용 및 판단

| 세대             | 라인 코딩         | 블록 코딩  | 효율     |
|-----------------|-------------------|-----------|---------|
| 10BASE-T        | Manchester        | —         | 50%     |
| 100BASE-TX      | MLT-3             | 4B/5B     | 80%     |
| 1000BASE-T      | PAM-5             | 8B/10B    | 80%     |
| 10GBASE-R       | NRZ               | 64B/66B   | 96.875% |
| 400GBASE        | PAM-4             | RS-FEC    | ~97%    |

## 6. 기대효과 및 결론

035. 부호화 — 라인 코딩 & 블록 코딩을 적용하면 대역폭과 지연에 대한 통제력이 높아지고, 운영 일관성과 성능 예측 가능성을 확보할 수 있다. 반면 설정 복잡도, 표준 호환성, 장비 비용, 운영 숙련도라는 전제가 뒤따르므로 무조건적인 도입이 정답은 아니다. 결론적으로 이 주제는 데이터통신 기초와 신호 처리를 이해하는 기준점이며, 최근에는 자동화·가상화·지능형 제어와 결합해 더 세밀한 최적화 방향으로 진화하고 있다.

## 7. 발전 흐름도

```
[초기 디지털 통신]
NRZ-L: 단순 전압 변환, DC 문제 심각
      │
      ▼
[Manchester 코딩]
엣지 = 클럭 정보 내포, 오버헤드 50%
      │
      ▼
[4B/5B + NRZ-I]
Fast Ethernet 100Mbps, 오버헤드 25% 절충
      │
      ▼
[8B/10B]
GbE / Fibre Channel / PCIe, RD 균형, 25% 오버헤드
      │
      ▼
[64B/66B 스크램블]
10G+ Ethernet, 오버헤드 3%, 스크램블 병용
      │
      ▼
[PAM-4 + RS-FEC]
400G/800G 이더넷, 물리층 고밀도 변조 + FEC 조합
```
