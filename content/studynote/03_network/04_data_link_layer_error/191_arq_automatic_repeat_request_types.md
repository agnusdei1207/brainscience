## 0. 핵심 인사이트

> **핵심**: **💡 핵심 인사이트**
> **비유**: 역방향 에러 수정 / 자동 재전송 요청 (ARQ, Automatic Repeat reQuest)은(는) 데이터 링크 계층과 오류 제어 안에서 데이터와 제어 규칙을 질서 있게 맞춰 주는 교통 체계와 같다.

> 📝 모범 답안

## 1. 개요 및 필요성

수신기가 "다시 보내!"라고 말하려면, 송신기와 수신기 사이에 치밀한 신호 체계가 필요합니다.

1. **ACK (Acknowledge, 긍정 응답)**: 수신기가 "이번 프레임 에러 없이 완벽하게 잘 받았어! 다음 거 보내줘"라고 송신기에 보내는 확인 도장입니다.
2. **NAK (Negative Acknowledge, 부정 응답)**: 수신기가 "야! 방금 받은 거 깨져서 왔어. 버렸으니까 다시 쏴!"라고 에러를 통보하는 신호입니다.
3. **타이머 (Timeout)**: 송신기는 데이터를 쏘고 나서 초시계를 켭니다. 만약 가던 데이터가 아예 증발하거나 ACK가 오는 길에 사라지면, 송신기는 영원히 기다릴 수 없으므로 **일정 시간(Timeout)이 지나면 "아, 못 받았구나" 하고 스스로 묻지도 따지지도 않고 똑같은 데이터를 재전송**합니다.

---

- **방식**: 송신기가 데이터 프레임 1개를 쏘고, 수신기의 ACK가 올 때까지 **무작정 아무것도 안 하고 멍때리며 기다립니다.** ACK가 오면 그제야 2번 프레임을 쏩니다.
- **특징**: 만들기는 세상에서 제일 쉽지만, 핑퐁을 기다리는 동안 회선이 텅텅 비어있어 속도가 끔찍하게 느립니다. (효율 최악).

## 2. 구성요소

네트워크 속도와 효율성을 높이기 위해 ARQ는 진화해 왔습니다.

- **방식**: 답답해서 한 번에 여러 개를 쏘기로 합니다(슬라이딩 윈도우 도입). 1, 2, 3, 4, 5번을 다다닥 쏩니다.
- 그런데 3번이 깨졌습니다. 수신기는 3번이 깨졌다고 NAK를 보냅니다.
- **특징**: 송신기는 "3번이 깨졌네? 그럼 3번부터 5번까지 싹 다 다시 보낼게!"라며, **에러가 난 3번(N) 시점으로 뒤로 돌아가서(Go-Back) 그 뒤에 보냈던 멀쩡한 4, 5번까지 무식하게 싹 다 버리고 다시 전송**합니다. (구현은 쉽지만 멀쩡한 데이터까지 재전송하는 낭비 발생).

## 3. 구조 및 원리

**핵심 조건**: 역방향 에러 수정 / 자동 재전송 요청 (ARQ, Automatic Repeat reQuest)은(는) 프레이밍, 오류 검출, 재전송 조건을 함께 만족할 때 안정적으로 동작한다.

동작 순서:

- **방식**: GBN의 무식함을 개선한 끝판왕입니다. 1, 2, 3, 4, 5를 보냈는데 3번만 깨졌다면?
- **특징**: 송신기는 4번, 5번은 수신기가 잘 받았다고 킵(버퍼)해두게 하고, **오직 에러가 났던 '3번 프레임 딱 하나만 핀셋으로 선택해서(Selective) 다시 재전송'**해 줍니다.
- 네트워크 효율은 최고로 좋지만, 수신기가 도착 순서가 꼬인 프레임들(1, 2, 4, 5, 3)을 원래 순서대로 재조립해야 하므로 하드웨어(버퍼)와 알고리즘이 매우 복잡해집니다.

## 5. 실무 적용 및 판단

**채택 조건**
- 프레이밍과 오류 검출을 동시에 관리해야 할 때
- 운영 자동화 또는 표준화된 제어가 필요할 때
- 장애 분석 시 원인 구분이 명확해야 할 때

**회피 조건**
- 단순 환경이라 오버헤드가 더 큰 경우
- 장비·프로토콜 호환성이 확보되지 않은 경우
- 측정 지표 없이 관행적으로만 적용하는 경우

**체크리스트**
1. 요구 성능과 허용 지연이 정의되었는가?
2. 오류·혼잡·보안 처리 경계가 명확한가?
3. 표준·벤더 구현 차이를 검증했는가?
4. 운영 관측성 및 장애 대응 절차가 준비되었는가?

## 6. 기대효과 및 결론

역방향 에러 수정 / 자동 재전송 요청 (ARQ, Automatic Repeat reQuest)을 적용하면 프레이밍과 오류 검출에 대한 통제력이 높아지고, 운영 일관성과 성능 예측 가능성을 확보할 수 있다. 반면 설정 복잡도, 표준 호환성, 장비 비용, 운영 숙련도라는 전제가 뒤따르므로 무조건적인 도입이 정답은 아니다. 결론적으로 이 주제는 데이터 링크 계층과 오류 제어를 이해하는 기준점이며, 최근에는 자동화·가상화·지능형 제어와 결합해 더 세밀한 최적화 방향으로 진화하고 있다.
