## 0. 핵심 인사이트

> **핵심**: 이더넷 프레임 헤더의 목적지/출발지 MAC 주소 바로 다음에 위치하는 2바이트(16비트) 공간은, Ethernet II 프레임에서는 **Type(Ethertype)**으로 쓰이고, IEEE 802.3 프레임에서는 **Length(길이)**로 쓰여 데이터의 정체를 밝히는 다중화(Multiplexing)의 핵심 키(Key)다.
> **비유**: Type 필드 (Ethertype) / Length 필드 (IPv4 = 0x0800, ARP = 0x0806)은(는) LAN/WAN 구조와 2계층 장비 안에서 데이터와 제어 규칙을 질서 있게 맞춰 주는 교통 체계와 같다.

> 📝 모범 답안

## 1. 개요 및 필요성

- **개념**: 이더넷 통신에서 MAC 주소 필드가 "누구에게(Who)"를 나타낸다면, Type/Length 2바이트 필드는 "무엇을(What)" 혹은 "얼마나(How much)"를 나타낸다. 현재 대부분의 통신은 Ethernet II 기반이므로 이 필드는 **Ethertype (이더타입)**이라고 널리 불린다.
- **필요성**: 컴퓨터의 네트워크 인터페이스(NIC)는 케이블에서 0과 1의 전기 신호를 받아 조립한 뒤, 껍데기(MAC 헤더)를 벗기고 알맹이(페이로드)를 CPU(운영체제)로 올려보내야 한다. 그런데 알맹이가 IP 주소 기반의 데이터인지, 아니면 MAC 주소를 묻는 ARP 요청인지 구별할 수 없다면 운영체제는 이 데이터를 처리할 수 없다. Ethertype은 운영체제에게 "이건 IP 관련 부서로 보내라"라고 지시하는 라우팅 태그 역할을 한다.

---

데이터 링크(L2) 계층에서 네트워크(L3) 계층으로 데이터를 올려보낼 때, Ethertype은 **역다중화(Demultiplexing)**의 스위치 역할을 한다. 하위 계층(이더넷 하나)이 상위 계층(IP, ARP, IPv6 등 여러 개)을 지원할 수 있게 해 주는 아키텍처의 핵심이다.

```text
 ┌─────────────────────────────────────────────────────────────┐
 │                 Ethertype에 의한 상위 계층 역다중화            │
 ├─────────────────────────────────────────────────────────────┤
 │                                                             │
 │   OSI 3계층 (네트워크)        [ IPv4 모듈 ]  [ ARP 모듈 ]  [ IPv6 모듈 ] │
 │                                   ▲            ▲            ▲      │
 │                                   │            │            │      │
 │                            0x0800 │     0x0806 │     0x86DD │      │
 │                                   │            │            │      │
 │   OSI 2계층 (데이터 링크)      [    MAC 계층 (Ethertype 확인)    ] │
 │                                   ▲                                │
 │                                   │                                │
 │   OSI 1계층 (물리)             [ 이더넷 케이블 (010101...) ]         │
 │                                                             │
 └─────────────────────────────────────────────────────────────┘
```

## 2. 구성요소

이더타입은 IEEE에서 표준으로 관리하며, 실무에서 패킷을 덤프 뜨거나 방화벽(ACL) 룰을 짤 때 이 16진수 코드를 직접 다뤄야 할 때가 많다.

| Ethertype (Hex) | 설명 (프로토콜) | 비고 |
|:---|:---|:---|
| **`0x0800`** | **IPv4** (Internet Protocol version 4) | 현재 인터넷 트래픽의 대다수 |
| **`0x0806`** | **ARP** (Address Resolution Protocol) | IP로 MAC을 찾기 위한 필수 프로토콜 |
| **`0x86DD`** | **IPv6** (Internet Protocol version 6) | 차세대 IP 주소 체계 |
| **`0x8100`** | **VLAN Tag** (IEEE 802.1Q) | 스위치 포트 가상화 (VLAN) 태그 삽입 시 |

## 3. 구조 및 원리

**핵심 조건**: Type 필드 (Ethertype) / Length 필드 (IPv4 = 0x0800, ARP = 0x0806)은(는) Ethernet, MAC 주소, 스위칭 조건을 함께 만족할 때 안정적으로 동작한다.

동작 순서:

만약 2바이트 값이 `0x05DC` (10진수로 1500) 이하라면, 이는 내용물이 무엇인지 알려주는 Type이 아니라 페이로드의 크기(바이트)를 의미하는 Length 필드로 동작한다. 이 경우 "내용물이 무엇인가?"에 대한 정보는 페이로드 내부에 숨어 있는 802.2 LLC(Logical Link Control) 헤더의 DSAP/SSAP 필드를 열어봐야만 알 수 있다. (현대에는 Spanning Tree Protocol 등 구형 네트워킹 제어 메시지에서나 드물게 볼 수 있다.)

## 4. 비교 및 연결

| 관점 | Type 필드 (Ethertype) / Length 필드 (IPv4 = 0x0800, ARP = 0x0806) | 인접 기술/대안 | 판단 포인트 |
|:---|:---|:---|:---|
| 적용 범위 | LAN/WAN 구조와 2계층 장비의 특정 문제를 직접 해결 | 상위·하위 계층 또는 대체 방식이 일부 기능을 분담 | 요구사항과 계층 경계 확인 |
| 장점 | Ethernet과 MAC 주소을 구조적으로 통제 | 범용성 또는 단순성이 강점 | 목적에 맞는 선택 필요 |
| 한계 | 스위칭·운영 복잡도 증가 가능 | 기능은 단순하지만 제어력 제한 | 비용·표준 호환성 검토 |

핵심은 단순 우열 비교가 아니라, Type 필드 (Ethertype) / Length 필드 (IPv4 = 0x0800, ARP = 0x0806)이 어떤 맥락에서 더 적합한지와 인접 기술과의 역할 분담을 해석하는 데 있다.

## 5. 실무 적용 및 판단

**채택 조건**
- Ethernet과 MAC 주소을 동시에 관리해야 할 때
- 운영 자동화 또는 표준화된 제어가 필요할 때
- 장애 분석 시 원인 구분이 명확해야 할 때

**회피 조건**
- 단순 환경이라 오버헤드가 더 큰 경우
- 장비·프로토콜 호환성이 확보되지 않은 경우
- 측정 지표 없이 관행적으로만 적용하는 경우

**체크리스트**
1. 요구 성능과 허용 지연이 정의되었는가?
2. 오류·혼잡·보안 처리 경계가 명확한가?
3. 표준·벤더 구현 차이를 검증했는가?
4. 운영 관측성 및 장애 대응 절차가 준비되었는가?

## 6. 기대효과 및 결론

Type 필드 (Ethertype) / Length 필드 (IPv4 = 0x0800, ARP = 0x0806)을 적용하면 Ethernet과 MAC 주소에 대한 통제력이 높아지고, 운영 일관성과 성능 예측 가능성을 확보할 수 있다. 반면 설정 복잡도, 표준 호환성, 장비 비용, 운영 숙련도라는 전제가 뒤따르므로 무조건적인 도입이 정답은 아니다. 결론적으로 이 주제는 LAN/WAN 구조와 2계층 장비를 이해하는 기준점이며, 최근에는 자동화·가상화·지능형 제어와 결합해 더 세밀한 최적화 방향으로 진화하고 있다.
