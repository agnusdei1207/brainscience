## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 스튜어드(Data Steward)는 현업 부서의 데이터 품질과 사용 규칙을 실무적으로 책임지는 역할이다.
> 2. **가치**: 데이터 오너가 정책과 책임을, 스튜어드가 품질 운영을 맡아 거버넌스를 현실화한다.
> 3. **판단**: 데이터 품질은 IT만의 일이 아니므로, 현업과 IT의 역할 분담이 명확해야 한다.

---

## Ⅰ. 개요 및 필요성

데이터 거버넌스는 정책만으로는 작동하지 않는다. 현업 데이터가 실제로 입력되고 수정되는 곳에 책임자가 필요하다.

그 역할이 데이터 스튜어드다. 품질, 정의, 코드값, 사용 규칙을 현장에서 관리한다.

- **📢 섹션 요약 비유**: 책을 쓰는 사람과 책장을 정리하는 사람이 따로 있는 것과 같다.

---

## Ⅱ. 아키텍처 및 핵심 원리

```text
Business Data
  ↓
Data Steward
  ↓
Quality Rules
  ↓
Governed Data
```

| 역할 | 의미 |
| :-- | :-- |
| Data Owner | 최종 책임 |
| Data Steward | 실무 품질 관리 |
| Data Custodian | 기술적 보관/운영 |

데이터 스튜어드는 현업 관점에서 데이터 정의와 품질 규칙을 관리한다. 그래서 IT만으로는 놓치기 쉬운 의미 오류를 줄인다.

- **📢 섹션 요약 비유**: 물건을 쓰는 사람 옆에서, 어디에 놓고 어떻게 써야 하는지 챙겨 주는 사람이다.

---

## Ⅲ. 비교 및 연결

| 역할 | 초점 | 차이 |
| :-- | :-- | :-- |
| Data Owner | 책임과 승인 | 정책 책임 |
| Data Steward | 품질 운영 | 현업 실무 |
| Data Custodian | 시스템 운영 | IT 기술 |

| 관리 대상 | 예 |
| :-- | :-- |
| 코드값 | 표준화 |
| 품질 규칙 | 검증 |
| 변경 이력 | 추적 |

데이터 스튜어드는 데이터 품질을 일상적으로 유지하는 사람이다. 정책이 현장에서 작동하려면 이 역할이 매우 중요하다.

- **📢 섹션 요약 비유**: 법을 만드는 사람, 집행하는 사람, 현장에서 정리하는 사람이 다르다.

---

## Ⅳ. 실무 적용 및 기술사 판단

### 체크리스트

1. 현업에 데이터 스튜어드가 지정되어 있는가?
2. 품질 규칙이 문서가 아니라 운영되는가?
3. 코드값/정의/용어가 통일되는가?
4. 변경 요청과 승인 절차가 있는가?
5. 데이터 오너와 역할이 충돌하지 않는가?

### 안티패턴

- IT만으로 품질을 책임지려는 설계
- 현업 책임자 없이 데이터 규칙만 만드는 설계
- 품질 문제를 발견해도 수정 담당이 없는 설계
- 역할을 이름만 두고 실제 권한이 없는 설계

기술사 관점에서는 데이터 스튜어드를 "현업 품질 관리자"로 보고, 데이터 거버넌스를 실행 가능하게 만드는 핵심 역할로 설명해야 한다.

- **📢 섹션 요약 비유**: 정리 담당이 있어야 방이 계속 깔끔하다.

---

## Ⅴ. 기대효과 및 결론

데이터 스튜어드가 있으면 데이터 품질과 정의가 현업에서 지속적으로 관리된다. 그래서 분석과 운영 신뢰도가 올라간다.

결론적으로 데이터 스튜어드는 현업 데이터 품질의 책임자다.

- **📢 섹션 요약 비유**: 쓰는 사람이 옆에서 바로 고쳐 주면 책상이 늘 정돈된다.
