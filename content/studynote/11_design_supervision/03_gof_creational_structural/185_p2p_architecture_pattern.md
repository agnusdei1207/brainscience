## 0. 핵심 인사이트

> **핵심**: P2P (Peer-to-Peer) Architecture Pattern은 중앙 서버 의존을 줄이고 각 노드가 동시에 클라이언트이자 서버로 동작하며 자원을 직접 공유하는 분산 구조다.
> **비유**: 모든 요청을 중앙 창구로 모으지 않고 참여자들이 서로 직접 자료를 주고받는 협업망과 같다.

## 1. 개요 및 필요성

185. 피어투피어 아키텍처 패턴 (P2P Architecture Pattern)은 동등한 피어 노드들이 직접 자원을 공유하는 분산 아키텍처를 다루는 주제다.
이 패턴이 중요한 직접 배경은 중앙 서버 중심 구조는 확장성과 단일 장애점 문제가 생길 수 있다.
이를 해결하기 위한 구조적 가치로는 자원 분산, 확장성, 내결함성, 참여자 직접 교환을 지원한다.
설계자가 집중해야 하는 관점은 핵심 초점은 피어 발견, 라우팅, 일관성, 신뢰, NAT (Network Address Translation) 극복이다.
이 섹션에서는 왜 이 구조가 필요해졌는지와, 어떤 비용을 줄이기 위해 등장했는지를 논리적으로 정리한다.

## 2. 구성요소

| 요소 | 역할 | 핵심 포인트 |
|:---|:---|:---|
| Peer Node | 자원 제공과 소비 동시 수행 | 역할 동등성 |
| Discovery Mechanism | 피어 탐색 | Tracker, DHT 등 |
| Overlay Network | 논리적 연결망 | 라우팅 최적화 |
| Distributed Hash Table | 키 기반 위치 조회 | 중앙 인덱스 대체 |
| Replication | 자원 복제 | 가용성 향상 |
| Trust/Security | 신뢰와 검증 | 악성 노드 대응 |
| NAT Traversal | 직접 연결 지원 | STUN/TURN 등 |

구성요소는 개별 기능보다 상호작용을 통해 의미를 가진다.
각 요소가 어떤 경계에서 책임을 갖고, 어디까지 추상화를 제공하는지가 설계 품질을 좌우한다.

## 3. 구조 및 원리
**핵심 조건**: 중앙 제어 없이도 피어 발견, 라우팅, 신뢰, 데이터 복제가 자율적으로 작동해야 한다.

P2P는 자원과 책임을 네트워크 가장자리로 분산한다.
중앙 서버 제거가 곧 단순함을 의미하지 않으며, 발견과 신뢰 문제가 새롭게 중요해진다.
순수 P2P와 하이브리드 P2P는 중앙 보조 인프라 의존 정도가 다르다.
데이터 복제와 가용성은 일관성 모델과 직접 연결된다.
네트워크 환경 제약으로 NAT Traversal이 실무 핵심 이슈가 된다.
블록체인, 파일 공유, 협업 네트워크 등에서 다양한 변형이 나타난다.
이 조건이 지켜질 때 구조는 단순 분할이 아니라 실제 동작 원리로 기능한다.

동작 순서:
1. **피어 참가**: 새 노드가 네트워크에 조인한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
2. **피어 탐색**: Tracker 또는 DHT를 통해 이웃 피어를 찾는다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
3. **오버레이 형성**: 논리 네트워크 연결을 구성한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
4. **자원 탐색**: 필요한 데이터 또는 서비스 위치를 조회한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
5. **직접 교환**: 피어 간 데이터 블록이나 메시지를 주고받는다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
6. **복제·복구**: 가용성을 위해 자원을 복제하고 장애 시 대체 경로를 찾는다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.
7. **평판·보안**: 악성 노드와 무결성 검증 문제를 관리한다.
   - 이 단계는 앞 단계의 결과를 제약 조건으로 이어받으며, 누락되면 전체 흐름의 안정성이 떨어진다.

```
[Peer A] <----> [Peer B]
   ^  \           /  ^
   |   \         /   |
   |    v       v    |
[Peer C] <----> [Peer D]
    \             /
     \--> [DHT / Tracker(optional)]
```

- 블록체인·엣지 네트워크 확장 단계는 이전 구조의 한계를 보완하며 나타난 진화다.

## 8. 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| DHT | 분산 위치 조회 메커니즘 |
| Overlay Network | 논리 네트워크 계층 |
| Replication | 가용성 확보 |
| Consensus | 강한 합의가 필요한 특수 P2P 영역 |
| NAT Traversal | 실제 연결 문제 해결 |
| Trust Model | 보안·평판 설계 |
| Client-Server | 대조 구조 |
| WebRTC | 브라우저 기반 P2P 구현 |
| Blockchain | 분산 신뢰형 P2P 사례 |
| Mesh Network | 근접 통신형 변형 |

### 정리 메모
- P2P의 핵심 가치는 중앙 병목 제거이지만, 동시에 피어 발견과 신뢰 설계라는 새로운 난제를 감수해야 한다.
  - 관련 개념까지 함께 묶어 이해하면 주제의 실전 활용도가 높아진다.
