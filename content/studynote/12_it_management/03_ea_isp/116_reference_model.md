## 0. 핵심 인사이트

> **핵심**: 참조 모델 (Reference Model)의 본질은 개별 조직이 제로베이스로 아키텍처를 만들지 않도록 공통 분류 기준과 설계 방향을 제공하는 재사용 가능한 표준 틀이다.

> **비유**: 빈 종이에 도시를 설계하는 대신 이미 검증된 도시 구획도를 참고해 도로와 공공시설의 기본 배치를 잡는 것과 같다.

---

📝 모범 답안

## 1. 개요 및 필요성

참조 모델 (Reference Model)은 아키텍처를 설계하거나 평가할 때 공통으로 사용할 수 있는 표준 분류 체계이자 가이드다. 조직마다 업무와 시스템이 다르더라도 기능, 데이터, 기술, 성과를 일정한 기준으로 정리해야 비교와 표준화가 가능하다. 이 역할을 수행하는 것이 참조 모델이다.

참조 모델이 없으면 각 조직은 같은 개념을 다른 이름으로 정의하고, 유사 기능을 중복 개발하며, 기술 표준도 제각각 선택하게 된다. 반대로 참조 모델이 있으면 공통 언어가 생겨 EA 산출물의 재사용성과 상호운용성이 높아진다. 따라서 참조 모델은 EA의 설계 지침이자 거버넌스의 판단 기준이다.

---

## 2. 구성요소

| 요소 | 역할 | 핵심 포인트 |
|:---|:---|:---|
| 분류 체계 | 공통 범주와 계층 정의 | 기능·데이터·기술을 비교 가능하게 만듦 |
| 표준 용어 | 동일 개념의 명칭 통일 | 기관 간 커뮤니케이션 비용 절감 |
| 매핑 규칙 | 개별 산출물을 참조 모델에 대응 | 현행과 표준의 차이 분석 가능 |
| 활용 지침 | 설계·심의·현행화에 적용 | 문서가 아닌 운영 기준으로 활용 |

분류 체계가 참조 모델의 뼈대라면 표준 용어는 이를 이해하게 하는 언어다. 매핑 규칙은 개별 조직의 아키텍처를 참조 모델 위에 올려놓게 만들고, 활용 지침은 그 결과를 사업 심의와 현행화에 연결한다. 네 요소가 함께 있어야 참조 모델이 실무에서 작동한다.

---

## 3. 구조 및 원리

**핵심 조건**: 참조 모델은 충분히 범용적이면서도 실제 매핑 가능한 수준의 계층과 용어를 가져야 하며, 개별 조직 산출물과의 대응 규칙이 존재해야 한다.

참조 모델의 작동 원리는 추상화와 표준화다. 먼저 다양한 조직에서 공통으로 관찰되는 요소를 추상화해 상위 분류 체계를 만든다. 이후 개별 조직의 업무, 데이터, 시스템, 기술 산출물을 이 체계에 매핑해 중복·누락·비표준 영역을 파악한다. 이렇게 하면 서로 다른 조직도 동일한 기준으로 비교할 수 있다.

동작 순서:
1. 표준 범주 정의: 공통 기능·데이터·기술 요소를 계층적으로 정의한다.
2. 용어·코드 통일: 동일 개념에 대한 명칭과 기준을 표준화한다.
3. 기관/조직 산출물 매핑: 현행 아키텍처를 참조 모델에 대응시킨다.
4. 차이 활용: 비표준, 중복, 누락 영역을 찾아 설계와 심의 기준으로 활용한다.

```text
[Reference Model]
   ├─ 표준 분류
   ├─ 표준 용어
   └─ 매핑 규칙
            ↓
 [조직 A EA] [조직 B EA] [조직 C EA]
            ↓
     비교·표준화·심의
```

참조 모델은 구체 설계를 대신하지 않는다. 너무 추상적이면 활용도가 떨어지고, 너무 상세하면 특정 조직의 모델을 일반화한 것에 불과해진다. 따라서 공통성 확보와 현장 적용성 사이의 균형이 중요하다.

---

## 4. 비교 및 연결

| 항목 | Reference Model | Framework | Template |
|:---|:---|:---|:---|
| 목적 | 표준 분류와 가이드 제공 | 방법론·거버넌스 제공 | 문서 형식 제공 |
| 핵심 가치 | 비교 가능성·재사용성 | 운영 절차 통일 | 작성 편의성 |
| 예시 | BRM, DRM, TRM | TOGAF, GEA | 산출물 양식 |
| 한계 | 구체 설계는 별도 필요 | 무거울 수 있음 | 의미 구조가 약함 |

참조 모델은 프레임워크의 일부로 사용되기도 하지만, 둘은 다르다. 프레임워크가 “어떻게 운영할 것인가”를 다룬다면 참조 모델은 “어떤 분류 기준을 사용할 것인가”를 다룬다. 템플릿은 형식만 제공하므로 의미 구조를 담지 못한다.

---

## 5. 실무 적용 및 판단

**채택 조건**:
- 공공부문과 대기업처럼 여러 조직을 같은 기준으로 비교해야 할 때
- 기능·데이터·기술 표준화를 추진할 때
- EA 심의와 현행화의 공통 기준이 필요할 때

**회피 조건**:
- 특정 조직 구조를 그대로 일반화해 범용 모델이라 부르는 경우
- 매핑 규칙 없이 분류표만 제시하는 경우
- 구체 설계를 대체할 것으로 오해하는 경우

체크리스트:
1. 표준 분류 계층이 일관적인가?
2. 용어 정의와 매핑 규칙이 존재하는가?
3. 조직 산출물과 실제로 대응 가능한가?
4. 심의·표준화·현행화에 활용되는가?

공공부문에서는 BRM, DRM, TRM, PRM 같은 참조 모델을 통해 기관별 사업과 산출물을 비교한다. 민간 그룹사도 공통 기능 분류와 기술 표준 체계를 참조 모델 형태로 운영해 계열사 간 중복 투자를 줄인다.

---

## 6. 기대효과 및 결론

참조 모델은 EA를 재사용 가능하고 비교 가능한 자산으로 만드는 핵심 장치다. 이를 통해 조직은 공통 언어로 아키텍처를 설명하고, 비표준 영역을 체계적으로 통제할 수 있다. 앞으로는 메타모델과 자동 매핑 도구가 결합되면서 참조 모델의 활용성이 더 커질 것이다.

|:---|:---|
| BRM | 업무 기능에 대한 참조 모델 |
| DRM | 데이터 표준과 분류를 위한 참조 모델 |
| TRM | 기술 표준을 위한 참조 모델 |
| Meta-model | 참조 모델 요소 간 관계 정의 |
| Compliance | 참조 모델 준수 여부를 판단하는 활동 |
