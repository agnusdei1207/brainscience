## 0. 핵심 인사이트

> **핵심**: DRM (Data Reference Model)의 본질은 데이터를 공통 구조와 의미로 분류해 기관·시스템 간 교환과 공유를 가능하게 만드는 표준 체계다.

> **비유**: 각 나라의 언어가 달라도 공항 표지판 규격을 통일해 누구나 같은 의미로 읽게 만드는 국제 표준과 같다.

---

📝 모범 답안

## 1. 개요 및 필요성

DRM (Data Reference Model)은 데이터의 분류, 정의, 교환 기준을 표준화하는 참조 모델이다. 데이터는 시스템보다 오래 남고, 조직 간 연계에서 가장 큰 마찰을 만든다. 같은 고객, 주소, 계약, 자산 데이터라도 기관이나 시스템마다 정의와 코드 체계가 다르면 연계 비용이 급증한다. DRM은 이런 문제를 줄이기 위한 공통 기준이다.

특히 공공부문에서는 기관 간 데이터 연계와 대국민 서비스 통합이 중요하므로, 데이터의 의미적 표준화가 필수다. DRM은 데이터 교환 표준, 분류 체계, 메타데이터 기준을 통해 상호운용성의 기반을 제공한다.

---

## 2. 구성요소

| 요소 | 역할 | 핵심 포인트 |
|:---|:---|:---|
| 데이터 분류 | 핵심 데이터 도메인 계층화 | 공통 개체와 속성 범주 정의 |
| 표준 정의 | 용어, 코드, 도메인 규칙 규정 | 의미적 불일치 제거 |
| 교환 기준 | 기관 간 데이터 연계 형식 정의 | 인터페이스 표준의 의미 기준 |
| 메타데이터 관리 | 데이터 사전과 품질 기준 연계 | 지속적 현행화 기반 |

데이터 분류는 무엇을 표준화할지 정하고, 표준 정의는 각 데이터의 의미를 고정한다. 교환 기준은 연계 시 어떤 형식과 의미로 전달할지 정하며, 메타데이터 관리는 이 표준을 지속적으로 유지하게 만든다. 이 연결이 있어야 DRM이 단순 사전이 아니라 연계 표준으로 기능한다.

---

## 3. 구조 및 원리

**핵심 조건**: 동일 데이터 개체는 기관과 시스템을 넘어 일관된 정의와 코드 체계를 가져야 하며, 교환 시 표준 메타데이터가 함께 관리되어야 한다.

DRM은 의미적 상호운용성을 목표로 한다. 기술적으로 API가 연결되어도 데이터의 의미가 다르면 실제 연계는 실패한다. לכן DRM은 데이터의 이름뿐 아니라 개념, 코드, 속성, 품질, 교환 맥락까지 함께 표준화한다. 이는 데이터 허브나 연계 플랫폼의 선행 조건이다.

동작 순서:
1. 핵심 데이터 도메인 정의: 공통으로 사용하는 개체와 속성을 분류한다.
2. 표준 용어와 코드 정의: 명칭, 코드, 형식, 도메인 규칙을 표준화한다.
3. 교환 기준 수립: 기관 간 전달 구조와 의미 기준을 정의한다.
4. 메타데이터 운영: 데이터 사전, 품질, 변경 이력을 관리한다.

```text
[기관 A 데이터] ─┐
[기관 B 데이터] ─┼─▶ [DRM 표준 정의] ─▶ [공통 교환/공유]
[기관 C 데이터] ─┘         │
                           └─ 메타데이터·코드·도메인 규칙
```

DRM은 파일 형식이나 API 명세만 표준화한다고 완성되지 않는다. 가장 어려운 부분은 의미 충돌 해결이다. 예를 들어 “고객”이라는 단어가 개인만 포함하는지 법인까지 포함하는지 기관별로 다를 수 있으므로, 정의 수준의 합의가 필수다.

## 4. 비교 및 연결

| 항목 | DRM | DA 현황 분석 | 메시지/인터페이스 표준 |
|:---|:---|:---|:---|
| 관점 | 표준 분류와 교환 의미 | 현행 데이터 구조 진단 | 기술 형식 규격 |
| 핵심 질문 | 무엇을 어떤 의미로 교환할 것인가? | 현재 데이터가 어떻게 구성되어 있는가? | 어떤 포맷으로 보낼 것인가? |
| 주요 산출물 | 데이터 분류, 용어, 코드 규칙 | ERD, 흐름도, 품질 진단 | API/메시지 스키마 |
| 가치 | 의미적 상호운용성 | 현행 문제 식별 | 기술적 연계 구현 |

인터페이스 표준이 기술 형식을 정의한다면 DRM은 그 안에 실리는 데이터 의미를 정의한다. DA 현황 분석은 현재 상태를 진단하고, DRM은 목표 표준 기준을 제시한다. 따라서 데이터 통합 사업에서는 두 접근이 함께 필요하다.

---

## 5. 실무 적용 및 판단

**채택 조건**:
- 기관 간 데이터 연계, 데이터 허브, 공공데이터 통합 시
- 용어·코드 불일치가 심각한 조직에서
- MDM, 데이터 표준화, 메타데이터 관리 추진 시

**회피 조건**:
- 형식 표준만 만들고 의미 정의를 생략하는 경우
- 현업 합의 없이 기술 부서만으로 표준을 확정하는 경우
- 메타데이터 현행화 책임 없이 일회성으로 정의하는 경우

체크리스트:
1. 핵심 데이터 도메인과 표준 정의가 존재하는가?
2. 용어·코드·도메인 규칙이 통일되는가?
3. 기관 간 교환 기준과 매핑 규칙이 있는가?
4. 메타데이터와 품질 관리 체계가 운영되는가?

주민·사업자·주소·재정 데이터처럼 공통 활용도가 높은 정보는 DRM 기반 표준화의 대표 대상이다. 민간에서도 그룹 고객·상품·조직 정보 표준화와 외부 제휴 데이터 연계에 DRM 관점이 적용된다.

---

## 6. 기대효과 및 결론

DRM은 데이터 교환의 기술적 연결을 의미적 연결로 완성하는 핵심 체계다. 이를 통해 기관과 시스템은 같은 데이터를 같은 의미로 사용하고, 연계 비용과 오류를 줄일 수 있다. 앞으로는 데이터 계보, 메타데이터 자동 수집, 의미론적 모델링이 DRM의 실효성을 더욱 높일 것이다.

## 7. 발전 흐름도

```text
기관별 데이터 정의 상이
    ↓
DRM 기반 공통 데이터 분류/교환 기준
    ↓
메타데이터·품질 연계 운영
    ↓
의미 기반 자동 연계와 데이터 패브릭
```

## 8. 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| Metadata | DRM 운영의 핵심 관리 대상 |
| Code Standard | 기관 간 의미를 맞추는 기준 |
| Interoperability | DRM이 지향하는 상호운용성 |
| MDM | 핵심 데이터 일관성을 유지하는 체계 |
| Data Lineage | 표준 데이터 흐름과 변경 추적 |
