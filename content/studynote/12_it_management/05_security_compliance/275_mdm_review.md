## 0. 핵심 인사이트

> **핵심**: MDM 마스터 데이터 관리의 본질은 MDM 마스터 데이터 관리의 목적·구성·운영 기준을 명확히 설명하는 주제를 비즈니스 가치, 통제, 실행 관점에서 일관되게 연결하는 데 있다.
> **비유**: 대형 프로젝트의 건강 상태를 수치로 읽어 내는 계기판과 같다.

---

> 📝 모범 답안

## 1. 개요 및 필요성

마스터 데이터(Master Data)는 거래(Transaction)를 지원하는 핵심 비즈니스 개체—고객, 제품, 공급업체, 직원, 계정—를 말한다. 기업이 ERP·CRM·SCM·DW 등 여러 시스템을 운영할 때, 각 시스템이 동일한 고객을 다르게 저장하면 360도 고객 뷰(Single Customer View)가 불가능하다.

MDM(Master Data Management)은 이 마스터 데이터를 전사적으로 단일 정의·단일 버전(Single Version of Truth)으로 관리하는 프로세스·기술·거버넌스 체계다. 황금 레코드(Golden Record)는 중복 데이터를 통합해 만들어진 가장 정확한 단일 레코드다.

---

## 2. 구성요소

| 구현 방식 | 설명 | 장점 | 단점 |
|:---|:---|:---|:---|
| 통합형 (Consolidation) | 모든 시스템 데이터를 MDM 허브로 모아 황금 레코드 생성 | 단일 진실 소스 | 대규모 통합 필요 |
| 연합형 (Federation) | 각 시스템 데이터를 실시간 연결해 통합 뷰 제공 | 낮은 초기 투자 | 레이턴시, 복잡성 |
| 허브앤스포크 (Registry) | 참조 인덱스만 MDM에, 실제 데이터는 원본 시스템 유지 | 비침투적 | 데이터 이동 없음, 품질 제한 |

## 3. 구조 및 원리

MDM 마스터 데이터 관리의 구조를 이해할 때 중요한 것은 구성요소를 나열하는 것이 아니라, 어떤 입력이 어떤 판단 규칙을 거쳐 어떤 결과와 증빙으로 이어지는지를 보는 것이다. 즉 MDM 마스터 데이터 관리는 기준선, 실행 경로, 피드백 루프가 결합된 운영 메커니즘으로 이해해야 한다.

**핵심 조건**: 측정값이 동일한 정의와 시점으로 수집되고, 임계치와 해석 기준이 사전에 합의되어야 한다.

동작 순서:
1. **측정 범위 정의**: 이 단계는 MDM 마스터 데이터 관리가 단순 개념이 아니라 실제 통제와 실행으로 이어지게 만드는 연결점이다.
2. **원천 데이터 수집**: 이 단계는 MDM 마스터 데이터 관리가 단순 개념이 아니라 실제 통제와 실행으로 이어지게 만드는 연결점이다.
3. **지표 계산**: 이 단계는 MDM 마스터 데이터 관리가 단순 개념이 아니라 실제 통제와 실행으로 이어지게 만드는 연결점이다.
4. **결과 해석 및 조치**: 이 단계는 MDM 마스터 데이터 관리가 단순 개념이 아니라 실제 통제와 실행으로 이어지게 만드는 연결점이다.

```text
[기준선 설정] -> [원천 데이터 수집] -> [MDM 마스터 데이터 관리 계산] -> [임계치 비교] -> [조치 결정]
```

이 구조에서 핵심은 선행 조건이 충족되지 않으면 뒤 단계의 효율이 높아도 전체 품질이 보장되지 않는다는 점이다. 예를 들어 지표 정의가 불명확하거나 승인 경계가 흐리면, 자동화가 오히려 오류를 빠르게 확산시키는 결과가 된다. 따라서 구조 설계에서는 속도보다 정합성, 개별 최적화보다 전체 제어성을 함께 고려해야 한다.

---

## 4. 비교 및 연결

MDM 프로젝트의 핵심 성공 요인은 기술이 아닌 거버넌스—데이터 스튜어드 지정, 황금 레코드 규칙 합의, 데이터 품질 KPI 설정—다. 기업 인수합병(M&A) 시 양사의 고객·제품 마스터 데이터 통합이 최대 난관으로, MDM 전략이 사전에 수립되어 있으면 통합 기간을 절반으로 단축할 수 있다. 클라우드 MDM 솔루션(Informatica IDMC, SAP MDG, Stibo STEP)은 API 기반 실시간 데이터 동기화와 AI 기반 중복 제거를 제공한다.

## 5. 실무 적용 및 판단

**채택 조건**:
- MDM 마스터 데이터 관리가 해결하려는 문제의 범위와 책임 주체가 명확할 때
- 정책·프로세스·도구·지표를 함께 설계할 수 있을 때
- 운영 증빙과 사후 개선 루프를 지속적으로 유지할 수 있을 때

**회피 조건**:
- 용어만 도입하고 실제 권한·책임 구조를 바꾸지 않을 때
- 정량 기준 없이 선언적 문구만 남는 경우
- 자동화가 필요한데 표준 데이터와 인터페이스가 준비되지 않은 경우

체크리스트:
1. 목표와 범위가 문서화되어 있는가?
2. 승인·예외 처리·에스컬레이션 경로가 정의되어 있는가?
3. 운영 데이터와 감사 증빙을 수집할 수 있는가?
4. 성과 지표가 비즈니스 영향과 연결되는가?
5. 실패 시 롤백·보완·재평가 절차가 준비되어 있는가?

실무에서는 MDM 마스터 데이터 관리를 독립 프로젝트로 보는 것보다, 기존 거버넌스·보안·개발·운영 체계와 어떻게 접합할지를 함께 설계해야 성공 확률이 높다.

## 6. 기대효과 및 결론

MDM 마스터 데이터 관리를 올바르게 적용하면 의사결정의 일관성, 운영의 재현성, 통제의 추적성이 동시에 향상된다. 즉 “누가 무엇을 왜 했는가”가 남기 때문에 조직이 커질수록 효과가 커진다.

다만 MDM 마스터 데이터 관리는 문서만 잘 만들어도 성공하는 영역이 아니다. 정의와 실행이 분리되면 형식주의가 되고, 자동화만 앞서면 통제 목적이 사라진다. 따라서 표준화와 민첩성, 통제와 생산성 사이의 균형이 항상 필요하다.

향후에는 정책 코드화(Policy as Code), 실시간 관측성(Observability), AI 기반 이상 탐지와 의사결정 지원이 결합되면서 관리 체계가 더 자동화되고 증거 중심으로 진화할 가능성이 크다. 결론적으로 핵심은 도구가 아니라 기준선이며, 기준선이 명확할 때만 자동화와 확장이 의미를 가진다.

| 개념 | 설명 | 연관 키워드 |
|:---|:---|:---|
| 황금 레코드 (Golden Record) | 중복 제거 후 생성된 단일 정확 레코드 | MDM, 데이터 품질 |

| Single Customer View | 고객 데이터 360도 통합 뷰 | 고객 MDM, CRM |
| 데이터 중복 제거 (Deduplication) | 중복 레코드 탐지·통합 | MDM, 데이터 품질 |
