## 0. 핵심 인사이트

> **핵심**: CDC(Change Data Capture)는 소스 DB의 INSERT·UPDATE·DELETE 변경 이벤트를 실시간으로 캡처해 다운스트림 시스템에 전파하는 데이터 통합 기법이다.
> **비유**: 여러 공정이 연결된 생산 라인처럼, 앞단의 입력 품질과 중간 단계의 흐름 제어가 최종 결과를 좌우하는 구조와 같다.

---

> 📝 모범 답안

## 1. 개요 및 필요성

CDC(Change Data Capture, 변경 데이터 캡처)는 **데이터베이스의 모든 변경 사항을 감지·캡처·전달하는 기술**이다.

---

## 2. 구성요소

| 항목          | 배치 ETL              | CDC (실시간)           |
|-------------|----------------------|----------------------|
| 처리 방식    | 주기적 (야간 배치)    | 이벤트 기반 실시간     |
| 데이터 신선도 | 시간~일 단위          | 밀리초~초 단위         |
| 소스 DB 부하 | 쿼리 부하 높음        | 로그 기반 시 낮음      |
| 복잡도       | 단순                  | 높음 (스키마 변경 관리) |
| 사용 사례    | 보고서·분석           | 실시간 대시보드·동기화  |

---

## 3. 구조 및 원리

**핵심 조건**: CDC (Change Data Capture, 변경 데이터 캡처)은 입력 데이터의 품질, 처리 단계의 일관성, 결과 활용 단계의 운영 제어가 동시에 맞아야 기대 효과를 낸다.

```
PostgreSQL WAL / MySQL Binlog
         ↓
     Debezium (오픈소스 CDC)
         ↓
     Apache Kafka (이벤트 스트림)
         ↓
  다운스트림: DWH / 검색 / 캐시
```
- 장점: 소스 DB 부하 없음, 모든 변경 캡처, 서브밀리초
- 단점: DB 로그 설정 필요, 복잡한 운영

```
┌──────────────────────────────────────────────────────────────┐
│                   CDC 데이터 파이프라인                        │
│                                                              │
│  PostgreSQL ──→ Debezium ──→ Kafka Topic ──→ Flink/Spark    │
│    (WAL)       Connector    (변경 이벤트)    (스트림 처리)    │
│                                  │                          │
│                            Kafka Connect │                  │
│                            Sink Connector│                  │
│                                  ↓                          │
│                    Elasticsearch / Snowflake / Redis        │
└──────────────────────────────────────────────────────────────┘
```

## 5. 실무 적용 및 판단

```sql
-- 마지막 추출 시각 이후 변경된 행 조회
SELECT * FROM orders
WHERE updated_at > :last_extract_time
ORDER BY updated_at;
```
- 장점: 구현 간단, 기존 DB 변경 불필요
- 단점: 삭제 감지 불가, DB 부하, 밀리초 지연 불가

```sql
CREATE TRIGGER orders_cdc
AFTER INSERT OR UPDATE OR DELETE ON orders
FOR EACH ROW
INSERT INTO cdc_log VALUES (NOW(), TG_OP, OLD/NEW데이터);
```
- 장점: 삭제 감지 가능
- 단점: DB 성능 저하, 스키마 변경 시 트리거 관리 복잡

```json
{
  "op": "u",          // c=create, u=update, d=delete
  "before": { "id": 1, "status": "pending" },
  "after":  { "id": 1, "status": "shipped" },
  "source": {
    "table": "orders",
    "ts_ms": 1700000000000,
    "lsn": 12345678
  }
}
```

```
Phase 1: CDC로 구 DB → 신 DB 동기화
Phase 2: 읽기 트래픽 신 DB로 전환 (테스트)
Phase 3: 쓰기 트래픽도 신 DB로 완전 전환
Phase 4: CDC 중단, 구 DB 폐기
```

```
소스 DB 컬럼 추가 시:
  Debezium → Kafka Schema Registry (Avro/Protobuf)
  → 컨슈머는 새 필드를 Optional로 처리 (하위 호환)
```

| 보장 수준         | 방법                          |
|-----------------|-------------------------------|
| At-Least-Once   | Kafka + 멱등성 소비자          |
| Exactly-Once    | Kafka Transactions + 2PC      |

## 6. 기대효과 및 결론

장점: 구현 간단, 기존 DB 변경 불필요 단점: 삭제 감지 불가, DB 부하, 밀리초 지연 불가 장점: 삭제 감지 가능 단점: DB 성능 저하, 스키마 변경 시 트리거 관리 복잡

CDC (Change Data Capture, 변경 데이터 캡처)의 효과는 성능 향상 자체보다도 예측 가능성과 운영 일관성을 확보하는 데 있다. 반대로 데이터 품질, 거버넌스, 모니터링 없이 도입하면 복잡도만 늘고 실질 가치는 줄어든다. 따라서 이 주제는 기능 도입이 아니라 구조적 운영 역량과 함께 판단해야 하며, 향후에는 자동화·실시간성·설명 가능성·비용 최적화와 결합된 방향으로 발전한다.

## 7. 발전 흐름도

```
┌─────────────────────────────────────────────────────────────────┐
│                 CDC 기술 발전 흐름                               │
├──────────────┬────────────────────┬─────────────────────────────┤
│ 2000년대 초  │ 쿼리 기반 CDC      │ Timestamp 폴링, 야간 배치   │
│ 2010년대     │ GoldenGate·Attunity │ 상용 로그 기반 CDC 성숙    │
│ 2015년       │ Debezium 등장      │ 오픈소스 로그 CDC + Kafka   │
│ 2018년       │ AWS DMS·GCP Datastream │ 관리형 CDC 서비스        │
│ 2020년대     │ 실시간 Lakehouse   │ CDC + Delta Lake/Iceberg   │
└──────────────┴────────────────────┴─────────────────────────────┘

핵심 키워드 연결:
소스 DB → WAL/Binlog → Debezium → Kafka → 싱크
  ↓              ↓           ↓         ↓
PostgreSQL    Replication  커넥터   스트림 처리
  ↓
실시간 DWH → 분석 대시보드 실시간 업데이트
```

## 8. 관련 개념 맵

```
CDC (Change Data Capture)
├── 구현 방식
│   ├── 쿼리 기반 (Timestamp Poll)
│   ├── 트리거 기반 (DB Trigger)
│   └── 로그 기반 (WAL/Binlog) ← 현대 표준
├── 핵심 도구
│   ├── Debezium (오픈소스 CDC)
│   ├── Apache Kafka (스트리밍)
│   └── AWS DMS (관리형 CDC)
├── 활용 패턴
│   ├── 실시간 DWH 동기화
│   ├── 이벤트 드리븐 MSA
│   └── Zero-downtime 마이그레이션
└── 관련 개념
    ├── WAL (Write-Ahead Log)
    ├── Binlog (MySQL)
    └── Schema Registry (Avro)
```
