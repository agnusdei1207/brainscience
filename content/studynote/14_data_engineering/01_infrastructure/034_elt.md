## 0. 핵심 인사이트

> **핵심**: ELT(Extract·Load·Transform)는 원시 데이터를 먼저 클라우드 DWH에 적재한 뒤 강력한 컴퓨팅 파워로 변환을 수행하는 현대 데이터 파이프라인 패턴으로, ETL의 중간 변환 서버 병목을 제거했다.
> **비유**: 여러 공정이 연결된 생산 라인처럼, 앞단의 입력 품질과 중간 단계의 흐름 제어가 최종 결과를 좌우하는 구조와 같다.

---

> 📝 모범 답안

## 1. 개요 및 필요성

ELT (Extract, Load, Transform) 현대 데이터 스택은 데이터 엔지니어링에서 입력 데이터의 특성, 처리 방식, 운영 제어를 함께 다루는 주제다. 이 개념이 필요한 이유는 시스템이 커질수록 데이터 규모와 변화 속도, 품질 요구가 동시에 증가하기 때문이다. 따라서 이 주제를 이해할 때는 정의만 암기할 것이 아니라, 어떤 한계를 해결하려고 등장했고 어떤 조건에서 효과가 나는지까지 함께 봐야 한다.

```
ETL (전통):
  원본 → ETL 서버 (변환) → DWH
         ↑ 병목: 서버 용량 한계
         ↑ 원시 데이터 보존 안 됨

ELT (현대):
  원본 → EL 도구 → DWH (원시 레이어) → dbt 변환 → 마트
         (Fivetran)  (Snowflake)           (SQL 모델)
         ↑ DWH 컴퓨팅 파워 활용
         ↑ 원시 데이터 항상 보존 → 재처리 가능
```

## 2. 구성요소

| 요소 | 역할 | 핵심 포인트 |
|:---|:---|:---|
| 핵심 대상 | 해당 주제가 직접 다루는 데이터·모델·인프라의 중심 객체 | 무엇을 저장·처리·최적화하는지가 기술의 경계를 결정한다 |
| 제어 메커니즘 | 처리 순서, 규칙, 알고리즘, 오케스트레이션 | 성능·정합성·확장성은 제어 방식에 따라 달라진다 |
| 운영 레이어 | 모니터링, 품질 검증, 거버넌스, 비용 관리 | 실무에서는 기능보다 운영 가능성이 채택 여부를 좌우한다 |

```
계층                 대표 도구
─────────────────────────────────────────────
소스 시스템          RDBMS, API, Kafka, 파일
  ↓
EL (추출·적재)       Fivetran, Airbyte (커넥터 기반 자동화)
  ↓
클라우드 DWH         Snowflake, BigQuery, Redshift, Databricks
  ↓
변환 (T)            dbt (SQL 모델링, 테스트, 계보)
  ↓
의미 레이어          Looker LookML, dbt Semantic Layer
  ↓
시각화·BI           Looker, Tableau, Metabase, Superset
  ↓
역방향 ETL          Hightouch, Census (마트 → CRM/광고 시스템)
```

## 3. 구조 및 원리

**핵심 조건**: ELT (Extract, Load, Transform) 현대 데이터 스택은 입력 데이터의 품질, 처리 단계의 일관성, 결과 활용 단계의 운영 제어가 동시에 맞아야 기대 효과를 낸다.

```
데이터 레이크 한계: 스키마 없음, ACID 트랜잭션 불가, 성능 낮음
데이터 DWH 한계: 비정형·반정형 데이터 불가, 비싼 저장 비용

레이크하우스 = 레이크 + 웨어하우스:
```

| 기능              | 데이터 레이크  | 데이터 DWH  | 레이크하우스  |
|-----------------|-------------|------------|------------|
| 비정형 데이터     | ✅          | ❌          | ✅          |
| ACID 트랜잭션    | ❌          | ✅          | ✅          |
| SQL 쿼리 성능    | 낮음         | 높음         | 높음         |
| 저장 비용        | 낮음         | 높음         | 낮음         |
| 스트리밍         | ✅          | 제한         | ✅          |

## 4. 비교 및 연결

| 포맷         | 주도           | 핵심 특성                      |
|-----------|-------------|-------------------------------|
| Delta Lake | Databricks  | 타임 트래블, ACID, Z-Order     |
| Apache Iceberg | Netflix  | 스키마 진화, 시간 여행, 멀티클라우드|
| Apache Hudi | Uber       | 증분 처리, CDC 최적화           |

```
타임 트래블 예시 (Delta Lake):
  SELECT * FROM orders TIMESTAMP AS OF '2024-01-01'
  -- 과거 시점 데이터 조회 가능 (실수 복구·감사)

스키마 진화 (Iceberg):
  ALTER TABLE orders ADD COLUMN promo_code STRING
  -- 기존 파티션과 하위 호환 유지
```

## 5. 실무 적용 및 판단

역방향 ETL(Reverse ETL)은 **DWH에 정제된 데이터를 운영 시스템(CRM·광고·Slack)으로 역전송**하는 패턴이다.

```
일반 흐름: 소스 → DWH → BI (분석)
역방향 ETL: DWH → CRM (Salesforce) / 광고 (Facebook Ads)
                → 이메일 (Mailchimp) / Slack 알림

예시: BigQuery의 "고가치 고객 세그먼트" → Salesforce 영업팀 자동 배정
```

**도구**: Hightouch, Census, dbt + Airflow 커스텀

## 6. 기대효과 및 결론

역방향 ETL(Reverse ETL)은 **DWH에 정제된 데이터를 운영 시스템(CRM·광고·Slack)으로 역전송**하는 패턴이다.

ELT (Extract, Load, Transform) 현대 데이터 스택의 효과는 성능 향상 자체보다도 예측 가능성과 운영 일관성을 확보하는 데 있다. 반대로 데이터 품질, 거버넌스, 모니터링 없이 도입하면 복잡도만 늘고 실질 가치는 줄어든다. 따라서 이 주제는 기능 도입이 아니라 구조적 운영 역량과 함께 판단해야 하며, 향후에는 자동화·실시간성·설명 가능성·비용 최적화와 결합된 방향으로 발전한다.

## 7. 발전 흐름도

```
┌─────────────────────────────────────────────────────────────────┐
│              ELT / 데이터 스택 발전 흐름                         │
├──────────────┬────────────────────┬─────────────────────────────┤
│ 2012년       │ 클라우드 DWH 등장  │ Redshift 출시, ELT 가능성    │
│ 2016년       │ Snowflake 성장     │ 데이터 공유·클라우드 DWH 혁신 │
│ 2019년       │ Fivetran·dbt 부상  │ Modern Data Stack 형성       │
│ 2020년       │ Delta Lake OSS     │ Databricks, 레이크하우스 개념 │
│ 2021년       │ Apache Iceberg     │ 멀티클라우드 오픈 포맷 표준화  │
│ 2023년~      │ AI/ML + ELT        │ Feature Store → ML 파이프라인 통합|
└──────────────┴────────────────────┴─────────────────────────────┘

핵심 키워드 연결:
ETL 서버 병목 → ELT 전환 → 클라우드 DWH 변환 파워
    ↓               ↓                   ↓
전통 온프레미스   Fivetran/Airbyte    Snowflake/BigQuery
    ↓
dbt 변환 표준화 → 레이크하우스 → Delta/Iceberg → 통합 아키텍처
```

## 8. 관련 개념 맵

```
ELT / 현대 데이터 스택
├── ELT 패턴
│   ├── EL: Fivetran·Airbyte (커넥터 자동화)
│   └── T: dbt (SQL 변환·테스트·계보)
├── 저장 계층
│   ├── 클라우드 DWH (Snowflake·BigQuery)
│   └── 레이크하우스 (Delta·Iceberg·Hudi)
├── 소비 계층
│   ├── BI (Looker·Tableau·Metabase)
│   └── 역방향 ETL (Hightouch·Census)
└── 핵심 기능
    ├── 타임 트래블 (시간 여행)
    ├── ACID 트랜잭션
    └── 스키마 진화
```
