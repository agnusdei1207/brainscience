## 0. 핵심 인사이트

> **핵심**: 에어 갭 (Air-gapped) 환경의 CI/CD는 외부 인터넷과 물리적으로 단절된 폐쇄망에서 애플리케이션 빌드, 반입, 배포를 안전하게 자동화하는 특수 파이프라인 전략이다.
> **비유**: 일반 CI/CD가 수도관을 연결해 물을 콸콸 틀어 쓰는 방식이라면, 에어 갭 CI/CD는 밖에서 생수통을 안전하게 포장해 검문소를 거친 뒤 격리된 벙커 안으로 직접 들고 들어가는 생수 배달 방식입니다.

---

> 📝 모범 답안

## 1. 개요 및 필요성

일반적인 클라우드 네이티브 CI/CD 환경은 GitHub에서 코드를 가져오고, Docker Hub나 NPM (Node Package Manager) 같은 외부 퍼블릭 저장소에 상시 연결되어 라이브러리를 동적으로 다운로드한다. 그러나 국가 안보 시설, 금융 코어 망, 원자력 발전소와 같은 에어 갭 (Air-gapped) 환경은 보안상의 이유로 외부 인터넷과의 물리적 연결이 완벽하게 차단되어 있다.

이러한 망분리 환경에서는 `npm install`이나 `docker pull` 같은 일상적인 명령어가 모두 실패한다. 외부 통신이 불가능하다는 제약 조건 속에서도 개발 생산성을 유지하고 수동 배포로 인한 인적 오류 (Human Error)를 막기 위해서는, 오프라인 반입을 전제로 한 정적 패키징 및 자체 미러 (Mirror) 저장소 구축 중심의 특수한 CI/CD 아키텍처가 반드시 필요하다.

---

## 2. 구성요소

에어 갭 배포 아키텍처는 크게 외부망에서의 '정적 패키징', 물리적 '반입 및 검증', 내부망에서의 '로컬 미러링 및 배포' 3단계로 나뉜다. 모든 의존성은 외부망에서 하나의 아카이브 (Tarball 등)로 병합되어 반입된다.

```text
┌──────────────────────────────────────────────────────────────┐
│           에어 갭 (Air-gapped) CI/CD 반입 워크플로우           │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  [ 외부 인터넷 망 ]         [ 물리적 격리 구간 ]       [ 내부 폐쇄 망 ]  │
│                                                              │
│  1. 빌드 및 패키징         2. 보안 스캔/반입          3. 내부 배포       │
│  ┌────────────┐         ┌──────────────┐         ┌────────────┐  │
│  │ 외부 라이브러리│         │ 안티바이러스 │         │ 로컬 레지스트리│  │
│  │ 도커 베이스 이미지├─포장─▶ │ 단방향 전송망 │ ─반입─▶ │ 헬름 (Helm)  │  │
│  │ 자체 소스코드 │ (.tar) │ (Data Diode) │         │ K8s 클러스터 │  │
│  └────────────┘         └──────────────┘         └────────────┘  │
│      (모든 종속성              (물리적 망연계            (완전 오프라인    │
│       미리 포함)                 망분리 솔루션)            자동화 배포)    │
└──────────────────────────────────────────────────────────────┘
```

가장 핵심적인 원리는 벤더링 (Vendoring)이다. 외부망 빌드 단계에서 필요한 모든 라이브러리를 애플리케이션 디렉터리에 다운로드하여 묶고, 도커 이미지 역시 `docker save` 명령을 통해 `.tar` 파일로 구워낸다. 이후 일방향 통신 장비 (Data Diode)나 승인된 USB를 통해 반입되며, 폐쇄망 내부에 구축된 프라이빗 레지스트리 (예: Harbor, Nexus)에 로드 (Load)되어 내부 쿠버네티스가 이를 당겨간다.

| 배포 단계 | 주요 작업 | 사용 도구 및 기술 |
| :--- | :--- | :--- |
| **외부 준비** | 코드/이미지 빌드, 패키지 종속성 완전 다운로드 | `docker save`, `npm pack`, Skopeo |
| **반입/검사** | 악성코드 검사, 무결성 해시(SHA) 검증, 단방향 전송 | Data Diode, 망연계 솔루션 |
| **내부 배포** | 로컬 레지스트리 업로드, GitOps 동기화 | Harbor, ArgoCD, `docker load` |

## 3. 구조 및 원리

**핵심 조건**: 모든 변경이 버전 관리되고, 자동 검증을 통과하며, 배포 상태와 롤백 경로가 추적 가능해야 한다.

동작 순서:
1. 코드와 배포 정의를 저장소에 커밋해 변경 이력을 단일 진실 공급원으로 만든다.
2. 빌드·테스트·보안 검사를 자동 수행해 배포 가능 아티팩트를 만든다.
3. 환경별 설정을 분리하면서도 동일한 파이프라인으로 일관성을 유지한다.
4. 배포 후 메트릭과 로그를 확인하고 이상 시 즉시 롤백하거나 다음 단계 승인을 중단한다.

```text
소스 변경
   ↓
CI 검증
   ↓
아티팩트 저장
   ↓
CD/GitOps 동기화
   ↓
운영 반영·롤백
```

클라우드 네이티브 환경과 에어 갭 환경의 CI/CD는 속도와 보안의 트레이드오프를 명확히 보여준다.

| 항목 | 일반 클라우드 CI/CD | 에어 갭 (Air-gapped) CI/CD |
| :--- | :--- | :--- |
| **의존성 해결** | 파이프라인 실행 시 동적 다운로드 | 사전 다운로드 후 정적 반입 (Vendoring) |
| **보안 통제** | 방화벽, VPN, 클라우드 IAM | 망연계 솔루션, 물리적 매체 (USB, Data Diode) |
| **배포 지연** | 코드 커밋 후 수 분 내 즉각 배포 | 반입 심사 및 물리적 이동으로 인한 배치 (Batch) 지연 |
| **무결성 검증** | 런타임 보안 스캐닝 활용 | 반입 전 아카이브 해시(SHA) 및 악성코드 전수 검사 |

일반 환경이 파이프라인의 속도(Agility)에 집중한다면, 에어 갭 환경은 반입되는 아티팩트 (Artifact)가 변조되지 않았다는 확신(Trust)을 얻는 데 집중한다. 이는 최근 부상하는 SBOM (소프트웨어 자재 명세서)을 통한 공급망 보안 정책과도 직접적으로 연결된다.

## 4. 비교 및 연결

폐쇄망 환경에서 아키텍처를 설계할 때는 "실수로 인터넷을 찾으려는 행위를 어떻게 방어할 것인가"가 가장 큰 판단 포인트다.

### 체크리스트
1. **베이스 이미지 최소화**: 반입 용량을 줄이기 위해 Distroless나 Alpine Linux 같이 불필요한 OS 패키지가 제거된 초경량 베이스 이미지를 사용하는가?
2. **로컬 미러 (Local Mirror) 구성**: 폐쇄망 내부에 NPM, Maven, Docker Image를 캐싱하는 통합 아티팩트 저장소 (Artifactory, Nexus 등)가 구성되어 있는가?
3. **오프라인 헬름 차트 (Helm Chart)**: 쿠버네티스 배포 시 헬름 차트 내부에 외부 이미지 저장소 URL이 하드코딩되지 않고 내부 레지스트리를 바라보도록 값이 치환되는가?

### 안티패턴
- 개발자가 외부망에서 빌드된 `node_modules`를 OS 환경(Mac/Windows)이 다른 폐쇄망 리눅스 서버에 그대로 복사하여 실행 오류를 유발하는 방식
- 변경된 레이어 (Layer)만 추출하지 않고 매번 수 GB 단위의 전체 도커 이미지를 반입하여 망연계 장비의 대역폭을 마비시키는 설계

## 5. 실무 적용 및 판단

에어 갭 CI/CD 전략을 구축하면 최고 수준의 보안 요구사항을 충족하면서도, 단절된 환경 내에서 컨테이너 기반의 현대적인 애자일 (Agile) 배포 프로세스를 실현할 수 있다. 이는 외부 위협으로부터 시스템을 완전히 분리하면서도 개발팀의 릴리즈 일관성을 보장한다.

향후 폐쇄망 CI/CD는 단순히 파일을 옮기는 수준을 넘어, SBOM 명세서를 통해 반입되는 모든 오픈소스의 취약점을 내부망에서 오프라인 데이터베이스로 매핑하여 능동적으로 방어하는 제로 트러스트 (Zero Trust) 공급망 보안 생태계로 진화할 것이다. 결국 에어 갭 환경에서도 자동화는 불가능한 것이 아니라 정밀한 통제가 추가될 뿐이다.

---

## 6. 기대효과 및 결론

에어 갭 (Air-gapped) 환경의 CI/CD: 폐쇄망 배포 전략을(를) 도입하면 자동화와 표준화를 통해 속도·안정성·가시성의 균형을 높일 수 있다. 다만 효과를 얻으려면 모든 변경이 버전 관리되고, 자동 검증을 통과하며, 배포 상태와 롤백 경로가 추적 가능해야 한다는 전제가 충족되어야 하며, 도구만 도입하고 운영 원칙을 바꾸지 않으면 기대 효과가 빠르게 한계에 부딪힌다.

결론적으로 에어 갭 (Air-gapped) 환경의 CI/CD: 폐쇄망 배포 전략은(는) 개별 기능이 아니라 운영 체계 전체의 품질을 재정렬하는 방식이며, 향후에는 플랫폼화·정책화·AI 기반 최적화와 결합해 더 높은 수준의 자동 운영으로 확장된다.

## 7. 발전 흐름도

```text
망분리 · 에어 갭 (Air-gapped) 환경 제약
    │
    ▼
오프라인 패키징 · 벤더링 (Vendoring) 적용
    │
    ▼
타르볼 (Tarball) 반입 · 망연계 솔루션 통과
    │
    ▼
프라이빗 레지스트리 구축 (Nexus, Harbor)
    │
    ▼
SBOM 기반 공급망 보안 · 내부 GitOps 배포 자동화
```

## 8. 관련 개념 맵

| 개념 | 연결 포인트 |
| :--- | :--- |
| **망연계 시스템 (Data Diode)** | 외부망에서 내부망으로 단방향으로만 데이터를 전송하여 침입을 물리적으로 차단하는 보안 기술 |
| **벤더링 (Vendoring)** | 외부 의존성 패키지를 프로젝트 디렉터리 내부에 포함하여 오프라인 빌드를 가능하게 하는 기법 |
| **프라이빗 레지스트리 (Private Registry)** | 폐쇄망 내부에 구축되어 외부 Docker Hub의 역할을 대신하는 내부 이미지 저장소 |
| **SBOM (Software Bill of Materials)** | 폐쇄망 내부로 반입되는 소프트웨어 구성 요소의 투명성과 취약점 추적을 위한 명세서 |
