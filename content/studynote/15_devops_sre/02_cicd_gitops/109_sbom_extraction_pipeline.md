## 0. 핵심 인사이트

> **핵심**: SBOM(Software Bill of Materials)은 소프트웨어를 구성하는 **모든 오픈소스 라이브러리·버전·의존성 관계를 기계 판독 가능한 표준 포맷(SPDX, CycloneDX)으로 기록한 디지털 자재 명세서**다.
> **비유**: SBOM은 식품 뒷면의 **성분표**다. 나쁜 재료(취약점)가 발견되면 성분표를 보고 우리 과자가 안전한지 즉시 확인한다.

---

> 📝 모범 답안

## 1. 개요 및 필요성

소프트웨어의 80~90%는 오픈소스 컴포넌트로 구성된다. 직접 설치한 라이브러리뿐 아니라 그것이 끌어오는 하위 의존성(Transitive Dependency)까지 합치면 수백~수천 개에 달한다. Log4Shell(2021) 사태에서 전 세계 기업이 "우리 시스템에 Log4j가 있는가?"라는 질문에 수주간 답하지 못한 것이 SBOM 의무화의 직접적 계기다.

```text
┌───────────────────────────────────────────────────────┐
│              SBOM 추출 파이프라인 흐름도                │
├───────────────────────────────────────────────────────┤
│  [Source Code]  →  [Build Engine]  →  [SBOM Generator]│
│  (pom, npm)       (Maven, npm)      (Syft, Trivy)    │
│                                          │            │
│                         ┌────────────────▼──────────┐ │
│                         │ Standard SBOM Format      │ │
│                         │ - SPDX (ISO 5962:2021)    │ │
│                         │ - CycloneDX (OWASP)       │ │
│                         └────────────┬──────────────┘ │
│                                      │                │
│                    ┌─────────────────▼──────────┐     │
│                    │ CVE DB 대조 (취약점 스캔)    │     │
│                    │ + VEX (악용 가능성 평가)     │     │
│                    │ + Sigstore 서명 (무결성)     │     │
│                    └─────────────────────────────┘     │
└───────────────────────────────────────────────────────┘
```

## 2. 구성요소

### SBOM 표준 포맷

| 포맷 | 주관 | 특징 | 형식 |
|:---|:---|:---|:---|
| **SPDX** | Linux Foundation (ISO 5962) | 법적 라이선스 추적에 강점 | JSON, RDF, Tag-Value |
| **CycloneDX** | OWASP | 보안 취약점 연계에 강점 | JSON, XML, Protobuf |

| 요소 | 설명 |
|:---|:---|
| **Inventory** | 포함된 모든 컴포넌트(이름·버전·해시) 목록 |
| **Dependency Graph** | 직접·간접 의존성의 트리 구조 |
| **License Info** | 각 컴포넌트의 라이선스 유형 (MIT, GPL 등) |
| **Provenance** | 소스 출처, 빌드 환경, 빌더 정보 |

### 3단 보안 결합

1. **SBOM**: "우리가 뭘 쓰고 있는가?" → 재고 파악
2. **VEX (Vulnerability Exploitability eXchange)**: "취약하지만 우리 코드에서 실제 실행되는가?" → 오탐 제거
3. **Sigstore/Cosign**: "이 SBOM은 위조되지 않았는가?" → 무결성 보증

## 3. 구조 및 원리

**핵심 조건**: 모든 변경이 버전 관리되고, 자동 검증을 통과하며, 배포 상태와 롤백 경로가 추적 가능해야 한다.

동작 순서:
1. 코드와 배포 정의를 저장소에 커밋해 변경 이력을 단일 진실 공급원으로 만든다.
2. 빌드·테스트·보안 검사를 자동 수행해 배포 가능 아티팩트를 만든다.
3. 환경별 설정을 분리하면서도 동일한 파이프라인으로 일관성을 유지한다.
4. 배포 후 메트릭과 로그를 확인하고 이상 시 즉시 롤백하거나 다음 단계 승인을 중단한다.

```text
소스 변경
   ↓
CI 검증
   ↓
아티팩트 저장
   ↓
CD/GitOps 동기화
   ↓
운영 반영·롤백
```

| 비교 | SAST (정적 분석) | SCA (오픈소스 스캔) | SBOM 추출 |
|:---|:---|:---|:---|
| **분석 대상** | 내가 짠 코드 | 사용 중 라이브러리 CVE | **전체 구성요소 명세** |
| **목적** | 코딩 실수 탐지 | 알려진 취약점 탐지 | **투명성·공급망 관리** |
| **산출물** | 취약점 리포트 | 패치 권고 | **표준 명세서 (JSON)** |
| **상호작용** | - | SBOM을 입력으로 사용 | SCA의 기초 데이터 |

## 4. 비교 및 연결

### 파이프라인 통합 체크리스트
1. **Syft/Trivy**를 CI 빌드 스텝에 추가하여 매 빌드마다 SBOM 자동 생성.
2. **Full Inventory**: 직접 의존성뿐 아니라 Transitive Dependency까지 포함.
3. **서명**: Cosign으로 SBOM에 디지털 서명 부착 → 배포 시 검증.
4. **저장**: OCI Registry에 SBOM을 컨테이너 이미지와 함께 Attestation으로 첨부.

### 안티패턴
- **빌드 후 수동 생성**: 빌드 환경과 불일치하는 SBOM → 신뢰도 0.
- **SBOM 생성만 하고 스캔 미연동**: 명세서를 만들어놓고 CVE 대조를 안 하면 의미 없음.

## 5. 실무 적용 및 판단

| 지표 | SBOM 미도입 | SBOM 파이프라인 | 개선 |
|:---|:---|:---|:---|
| Log4j 포함 확인 | **수주** (수동 조사) | **수초** (자동 대조) | 99.9% 단축 |
| 라이선스 컴플라이언스 | 사후 감사 | **빌드 시 자동 검증** | 법적 리스크 제거 |
| 공급망 투명성 | 블랙박스 | **완전 가시성** | 고객 신뢰 확보 |

SBOM은 Google SLSA 프레임워크와 결합하여 빌드 전 과정의 무결성을 증명하는 핵심 증거로 진화하고 있으며, 모든 소프트웨어 납품 시 '영양성분표'처럼 SBOM 제출을 요구하는 시대가 도래했다.

## 6. 기대효과 및 결론

SBOM 추출 파이프라인 (Software Bill of Materials)을(를) 도입하면 자동화와 표준화를 통해 속도·안정성·가시성의 균형을 높일 수 있다. 다만 효과를 얻으려면 모든 변경이 버전 관리되고, 자동 검증을 통과하며, 배포 상태와 롤백 경로가 추적 가능해야 한다는 전제가 충족되어야 하며, 도구만 도입하고 운영 원칙을 바꾸지 않으면 기대 효과가 빠르게 한계에 부딪힌다.

결론적으로 SBOM 추출 파이프라인 (Software Bill of Materials)은(는) 개별 기능이 아니라 운영 체계 전체의 품질을 재정렬하는 방식이며, 향후에는 플랫폼화·정책화·AI 기반 최적화와 결합해 더 높은 수준의 자동 운영으로 확장된다.

## 8. 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| **Supply Chain Security** | SBOM이 해결하려는 전체 맥락 |
| **SPDX / CycloneDX** | SBOM 데이터의 표준 포맷 |
| **CVE (Common Vulnerabilities)** | SBOM과 대조하는 취약점 데이터베이스 |
| **VEX** | 취약점의 실제 악용 가능성을 평가하는 보충 문서 |
| **SLSA (Supply-chain Levels)** | 빌드 무결성 보안 등급 체계 |
| **Sigstore / Cosign** | SBOM 및 컨테이너 이미지의 디지털 서명 도구 |
