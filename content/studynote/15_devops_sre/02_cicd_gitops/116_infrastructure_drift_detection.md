## 0. 핵심 인사이트

> **핵심**: 인프라 드리프트(Drift)란 **IaC 코드(Terraform/CloudFormation)에 정의된 기대 상태와 실제 클라우드 인프라 상태가 불일치**하는 현상이며, Drift Detection은 이를 자동으로 탐지·알림·복원하는 프로세스다.
> **비유**: 드리프트는 건축 대장(IaC)과 실제 건물(인프라)이 다른 상태다. 건축 대장대로 리모델링하면 몰래 만든 방이 철거된다.

```text
│     Terraform 코드: [22, 443]                         │
│     → 드리프트 발생!                                  │
│  4. terraform apply 실행 시:                          │
│     8080이 코드에 없으므로 삭제됨 → 서비스 장애!     │
│                                                       │
│  해결: 주기적 terraform plan으로 Diff 감지            │
│     → 코드 동기화 또는 수동 변경 되돌리기             │
└───────────────────────────────────────────────────────┘
```

## 2. 구성요소

### 드리프트 감지 도구

| 도구 | 방식 | 특징 |
|:---|:---|:---|
| **terraform plan** | State vs 실제 비교 | 기본, 수동/크론 실행 |
| **Driftctl** | IaC 미관리 리소스 탐지 | OSS, 커버리지 높음 |
| **CloudFormation Drift** | CF 스택 vs 실제 비교 | AWS 네이티브 |
| **Spacelift** | 자동 드리프트 스캔 + 알림 | SaaS |

### 드리프트 대응 전략

| 전략 | 설명 |
|:---|:---|
| **Reconcile** | IaC 코드를 실제 상태에 맞춰 수정 (코드 동기화) |
| **Remediate** | 실제 상태를 IaC 코드에 맞춰 복원 (자동 적용) |
| **Alert** | 드리프트 감지 시 알림만 (수동 판단) |

## 3. 구조 및 원리

**핵심 조건**: 모든 변경이 버전 관리되고, 자동 검증을 통과하며, 배포 상태와 롤백 경로가 추적 가능해야 한다.

동작 순서:
1. 코드와 배포 정의를 저장소에 커밋해 변경 이력을 단일 진실 공급원으로 만든다.
2. 빌드·테스트·보안 검사를 자동 수행해 배포 가능 아티팩트를 만든다.
3. 환경별 설정을 분리하면서도 동일한 파이프라인으로 일관성을 유지한다.
4. 배포 후 메트릭과 로그를 확인하고 이상 시 즉시 롤백하거나 다음 단계 승인을 중단한다.

```text
소스 변경
   ↓
CI 검증
   ↓
아티팩트 저장
   ↓
CD/GitOps 동기화
   ↓
운영 반영·롤백
```

| 비교 | 드리프트 미감지 | 주기적 Plan | 자동 감지+복원 |
|:---|:---|:---|:---|
| **코드 신뢰** | ✗ | 수동 확인 | **100%** |
| **사고 위험** | 높음 | 중간 | **낮음** |

## 4. 비교 및 연결

### 자동화 파이프라인
```yaml
schedule:
  - cron: '0 9 * * *'
steps:
  - run: terraform plan -detailed-exitcode
```

### 안티패턴
- **콘솔 수동 변경 허용**: IaC GitOps 원칙 파괴. 콘솔 변경 시 반드시 IaC 코드에 반영.

## 5. 실무 적용 및 판단

| 지표 | 드리프트 미감지 | 드리프트 감지 | 개선 |
|:---|:---|:---|:---|
| IaC 코드 신뢰도 | 불확실 | **100%** | 단일 진실 원천 |
| 예기치 않은 변경 | 빈번 | **즉시 감지** | 사고 예방 |

드리프트 감지는 IaC GitOps의 **필수 보완 장치**이며, OPA(Open Policy Agent)와 결합하여 드리프트 유형별 자동 정책(허용/거부/알림)을 적용하는 방향으로 진화하고 있다.

## 6. 기대효과 및 결론

인프라 드리프트 감지 (Infrastructure Drift Detection)을(를) 도입하면 자동화와 표준화를 통해 속도·안정성·가시성의 균형을 높일 수 있다. 다만 효과를 얻으려면 모든 변경이 버전 관리되고, 자동 검증을 통과하며, 배포 상태와 롤백 경로가 추적 가능해야 한다는 전제가 충족되어야 하며, 도구만 도입하고 운영 원칙을 바꾸지 않으면 기대 효과가 빠르게 한계에 부딪힌다.

결론적으로 인프라 드리프트 감지 (Infrastructure Drift Detection)은(는) 개별 기능이 아니라 운영 체계 전체의 품질을 재정렬하는 방식이며, 향후에는 플랫폼화·정책화·AI 기반 최적화와 결합해 더 높은 수준의 자동 운영으로 확장된다.
