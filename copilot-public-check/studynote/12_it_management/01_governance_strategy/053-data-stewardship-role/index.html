핵심 인사이트 (3줄 요약)

  1. 본질: 데이터 스튜어드 (Data Steward)는 데이터 정의, 품질, 표준, 사용 규칙을 현장에서 관리하는 역할이다.
  2. 가치: 데이터 오너 (Owner)와 현업 사이를 연결해 책임 공백을 줄이고, 데이터 거버넌스를 실행 가능하게 만든다.
  3. 판단 포인트: 스튜어드는 권한이 아니라 운영 책임을 맡는다. 용어 관리, 이슈 처리, 품질 규칙 적용이 핵심이다.

Ⅰ. 개요 및 필요성

거버넌스가 있어도 현장에서 누가 데이터를 돌볼지 정하지 않으면 실행되지 않는다. 데이터 스튜어드는 바로 그 빈칸을 메우는 역할이다.

스튜어드는 현업에서 데이터를 가장 잘 아는 사람과 시스템 규칙을 연결해, 정의 불일치와 품질 문제를 줄인다.

  • 📢 섹션 요약 비유: 데이터 스튜어드는 도서관에서 책 위치와 이름표를 정리하는 사서 도우미다.

Ⅱ. 아키텍처 및 핵심 원리

스튜어드는 오너와 달리 최종 책임자는 아니지만, 운영의 첫 번째 실무 담당자다. 카탈로그, 품질 규칙, 메타데이터, 이슈 트래킹을 현장에서 다룬다.

Data Owner → Policy / Accountability
Data Steward → Definition / Quality / Issue Handling
Data Custodian → System Operation
역할책임예시
Owner최종 책임부서장
Steward운영 관리표준 용어 관리
Custodian시스템 운영DB/플랫폼 관리자

핵심은 스튜어드가 데이터에 대한 "의미"와 "운영 상태"를 계속 최신으로 유지하는 것이다. 그래서 현업과 IT를 이어 주는 접점이 된다.

  • 📢 섹션 요약 비유: 데이터 스튜어드는 교실에서 출석부를 정리하고 이름이 바뀌면 바로 고쳐 주는 반장이다.

Ⅲ. 비교 및 연결

스튜어드는 데이터 오너, 데이터 거버넌스 위원회, 데이터 관리자와 연결된다. 오너가 방향을 정하고 스튜어드가 실행을 돕고, 시스템 관리자는 인프라를 지킨다.

항목OwnerStewardCustodian
초점책임운영시스템
질문왜 필요한가어떻게 유지할까어떻게 안전하게 돌릴까

스튜어드가 잘 작동하면 데이터 카탈로그와 데이터 품질 규칙이 현실과 맞게 유지된다. 반대로 스튜어드가 없으면 표준은 문서에만 남는다.

  • 📢 섹션 요약 비유: 오너는 반장, 스튜어드는 생활지도 선생님, 캐스터디언은 학교 시설 관리자다.

Ⅳ. 실무 적용 및 기술사 판단

실무에서는 도메인별 스튜어드를 지정하고, 용어집, 품질 규칙, 문제 티켓, 승인 절차를 연결한다. 데이터 변경이 일어나면 스튜어드가 영향도를 살펴야 한다.

체크리스트

  1. 데이터 도메인별 스튜어드가 지정되어 있는가?
  2. 용어 정의와 품질 규칙이 관리되는가?
  3. 데이터 이슈가 스튜어드에게 연결되는가?
  4. 오너와 스튜어드의 역할이 구분되는가?

안티패턴

  • 스튜어드를 이름만 두고 권한을 주지 않는 경우
  • 현업이 아닌 IT만 스튜어드 역할을 떠안는 경우
  • 책임과 운영을 분리하지 않고 한 사람에게 과도하게 몰아주는 경우

기술사 관점에서는 데이터 스튜어드가 거버넌스의 실행 책임자라는 점을 설명해야 한다. 정책은 오너가 만들고, 현장은 스튜어드가 움직인다.

  • 📢 섹션 요약 비유: 데이터 스튜어드는 반에서 칠판 내용을 바로 정리해 주는 친구다.

Ⅴ. 기대효과 및 결론

데이터 스튜어드는 데이터 품질과 표준의 실무 접점을 만든다. 결국 거버넌스가 문서에서 운영으로 바뀌는 핵심 역할이다.

정리하면, 스튜어드가 있어야 데이터가 "누가 관리하지?"라는 질문에 답할 수 있다.

  • 📢 섹션 요약 비유: 데이터 스튜어드는 책장마다 붙은 이름표를 직접 관리하는 사람이다.
