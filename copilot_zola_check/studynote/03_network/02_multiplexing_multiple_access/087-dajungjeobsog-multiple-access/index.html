핵심 인사이트 (3줄 요약)

> 1. **본질**: 다중 접속 (Multiple Access)은 MAC (Medium Access Control) 계층에서 여러 사용자가 하나의 공유 매체를 어떻게 나눠 쓰는지 정하는 기술이다.
> 2. **가치**: FDMA, TDMA, CDMA, OFDMA, CSMA 계열은 자원을 나누는 기준이 달라서 충돌, 지연, 효율의 균형이 서로 다르다.
> 3. **판단 포인트**: 무선·유선·실시간 환경마다 적합한 방식이 다르므로, 공유 매체의 물리적 제약을 먼저 봐야 한다.

---

## Ⅰ. 개요 및 필요성

다중 접속 (Multiple Access)은 한정된 채널을 여러 단말이 함께 사용할 때 충돌과 혼잡을 줄이는 방법이다. MAC (Medium Access Control) 계층은 누가, 언제, 어떤 자원을 사용할지 정한다.

이 기술이 중요한 이유는 대역폭이 항상 부족하기 때문이다. 유선이든 무선이든 같은 매체를 동시에 쓰려 하면 충돌이 생기므로, 시간을 나누거나 주파수를 나누거나 코드를 나누는 방식이 필요하다.

- **📢 섹션 요약 비유**: 하나의 운동장을 여러 반이 함께 쓰되, 줄과 시간표를 정하는 느낌이다.

---

## Ⅱ. 아키텍처 및 핵심 원리

다중 접속 방식은 크게 채널 분할형, 경쟁형, 통제형으로 나눌 수 있다.
분류대표 방식충돌 처리특징
채널 분할형FDMA, TDMA, CDMA, OFDMA사전 자원 할당예측 가능, 스케줄링 친화적
경쟁형ALOHA, CSMA/CD, CSMA/CA충돌과 백오프단순하지만 혼잡에 약함
통제형polling, token passing순번 통제지연 예측이 쉽다
시간 분할: | A | B | C | D |
주파수 분할: | A | B | C | D |
코드 분할:   codeA codeB codeC codeD

핵심은 자원을 단순히 나누는 것이 아니라, 충돌이 생기기 쉬운 조건을 미리 설계로 흡수하는 데 있다.

- **📢 섹션 요약 비유**: 같은 간식을 나눌 때, 먼저 줄을 설지 시간표를 만들지 방법이 다르다.

---

## Ⅲ. 비교 및 연결

경쟁형과 스케줄형을 비교하면 선택 기준이 분명해진다.
항목경쟁형스케줄형
충돌발생 가능거의 없음
지연 예측어려움쉬움
구현단순복잡
적합 환경트래픽이 가변적인 공유 매체QoS가 중요한 관리형 네트워크

예를 들어 Wi-Fi는 충돌 감지가 어렵기 때문에 CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance)를 쓴다. 반면 LTE/5G는 중앙 스케줄러가 자원을 배분하는 OFDMA (Orthogonal Frequency Division Multiple Access) 계열을 활용해 더 정교한 QoS를 제공한다. 유선 Ethernet의 과거 CSMA/CD (Carrier Sense Multiple Access with Collision Detection)는 충돌 검출이 가능했지만, 반이중 환경에서만 의미가 있었다.

- **📢 섹션 요약 비유**: Wi-Fi는 피해서 들어가고, 5G는 먼저 자리를 배정받는 방식에 가깝다.

---

## Ⅳ. 실무 적용 및 기술사 판단

실무에서는 트래픽 성격과 물리 매체가 먼저다. 실시간 제어처럼 지연 상한이 중요하면 TDMA나 token 방식이 맞고, 사용량이 급변하는 무선 환경이면 경쟁형과 스케줄형을 혼합한 설계가 필요하다.

체크리스트

  1. 매체가 충돌 검출을 지원하는가, 아니면 회피만 가능한가?
  2. 지연 상한과 처리량 중 무엇이 더 중요한가?
  3. 숨은 단말(hidden node)이나 노출 단말(exposed node) 문제가 있는가?
  4. 사용량 패턴이 예측 가능한가, 버스트형인가?

안티패턴

  • 모든 환경에 동일한 접근 방식을 적용하는 것

  • 무선에서 CSMA/CD처럼 충돌 검출을 기대하는 것

  • 실시간 서비스에 경쟁형 접속만 두는 것

    • 📢 섹션 요약 비유: 줄을 못 보면 서로 부딪히고, 줄을 잘 세우면 덜 기다린다.

    Ⅴ. 기대효과 및 결론

    다중 접속은 공유 매체를 효율적으로 쓰게 하지만, 물리적 한계를 없애지는 못한다. 따라서 좋은 방식이란 "모든 상황에 가장 빠른 것"이 아니라 "해당 환경의 제약을 가장 잘 감당하는 것"이다.

결국 MAC 계층의 설계는 자원 분배, 충돌 제어, 지연 예측을 동시에 다루는 균형 문제로 기억해야 한다.

- **📢 섹션 요약 비유**: 놀이터를 같이 쓰되, 누가 언제 그네를 탈지 정하는 규칙이 필요하다.
