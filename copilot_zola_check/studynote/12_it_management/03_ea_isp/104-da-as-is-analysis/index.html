0. 핵심 인사이트

핵심: 데이터 아키텍처 (DA: Data Architecture) 현황 분석의 본질은 조직의 데이터를 저장 구조, 이동 경로, 표준 수준으로 해부해 데이터 사일로와 품질 리스크를 드러내는 것이다.

비유: 도시의 도로만 보는 것이 아니라 상수도와 하수도, 배관 규격, 분기 지점을 함께 점검하는 기반 시설 조사와 같다.

📝 모범 답안

1. 개요 및 필요성

데이터 아키텍처 (DA: Data Architecture) 현황 분석은 전사 정보자산이 어디에 저장되고, 어떤 표준을 따르며, 시스템 사이를 어떻게 흐르는지 파악하는 과정이다. 많은 정보화 사업이 화면과 기능은 잘 구현하지만 데이터 구조가 제각각이라 통합 분석, 자동화, AI 활용에서 막힌다. 이는 현행 데이터 구조와 흐름을 먼저 이해하지 못했기 때문이다.

DA 분석이 없으면 TO-BE 설계에서 데이터 허브, MDM, 데이터 레이크 같은 해법이 왜 필요한지 설명할 수 없다. 또한 인터페이스 수가 많고 중복 코드가 늘어나 운영비와 장애 확률도 함께 증가한다. 그래서 ISP의 AS-IS 단계에서는 데이터 모델, 데이터 흐름, 표준·품질 수준을 함께 진단해야 한다.

2. 구성요소

요소역할핵심 포인트
전사 ERD핵심 엔터티와 관계 구조 파악중복 엔터티와 비정상 관계 식별
데이터 흐름생성·변환·전달 경로 파악배치, 실시간, 수기 연계 구분
표준화 진단용어, 코드, 도메인 규칙 확인동일 개념의 상이한 정의 탐지
품질 지표정합성, 정확성, 적시성 측정오류 데이터와 책임 주체 확인

전사 ERD는 정적인 구조를 설명하고, 데이터 흐름은 그 구조가 실제 운영에서 어떻게 이동하는지 보여준다. 표준화 진단은 동일 개념이 여러 시스템에서 어떻게 달리 표현되는지 드러내며, 품질 지표는 이런 차이가 어떤 운영 위험으로 이어지는지 계량화한다. 네 요소가 모이면 “어떤 데이터를 어디서 표준화할 것인가”가 स्पष्ट해진다.

3. 구조 및 원리

핵심 조건: 데이터 구조, 흐름, 표준, 품질이 동일한 데이터 도메인 기준으로 추적 가능해야 하며, 핵심 마스터 데이터의 원천과 책임 주체가 식별되어야 한다.

DA 현황 분석은 데이터베이스 스키마 수집만으로 끝나지 않는다. 동일한 고객, 상품, 계약, 자산 데이터가 시스템마다 어떻게 다르게 정의되는지 비교해야 하고, 생성-가공-소비 경로를 따라 데이터의 이동 비용과 왜곡 지점을 확인해야 한다. 특히 수기 업로드, 엑셀 중계, 배치 변환은 표준화 문제를 증폭시키는 대표 구간이다.

동작 순서:

  1. 핵심 데이터 도메인 선정: 고객, 제품, 거래, 조직 등 전사 핵심 개체를 우선 정리한다.
  2. ERD 및 스키마 진단: 엔터티 중복, 키 정의, 관계 구조, 정규화 수준을 확인한다.
  3. 데이터 흐름 파악: 원천 시스템에서 소비 시스템까지 배치/실시간/수기 흐름을 정리한다.
  4. 표준·품질 평가: 용어, 코드, 도메인, 품질 지표를 비교해 정합성 문제와 표준화 우선순위를 도출한다.
[원천 시스템] ──▶ [중계/배치] ──▶ [업무 시스템] ──▶ [분석/보고]
     │                 │                  │
     ├─ ERD 구조       ├─ 변환 규칙       ├─ 코드/용어 차이
     └────────────── 데이터 품질·표준 점검 ───────────────┘

DA 분석에서는 “어디에 저장되는가”보다 “누가 원천을 책임지는가”가 더 중요하다. 원천이 불명확하면 같은 데이터를 여러 부서가 각자 관리하게 되고, 이후 MDM이나 데이터 허브를 도입해도 지속적으로 품질이 무너진다. 따라서 기술 구조와 함께 데이터 거버넌스 책임 체계를 확인해야 한다.

4. 비교 및 연결

항목DA 현황 분석DB 모델링DRM
초점전사 데이터 구조·흐름·표준개별 시스템 스키마 설계참조 분류와 교환 표준
범위전사프로젝트/시스템기관·산업 표준 수준
주요 산출물전사 ERD, 데이터 흐름도논리/물리 모델데이터 참조 체계
의사결정통합·표준화 우선순위성능/정규화 설계표준 분류 적용

DB 모델링이 개별 시스템 최적화라면 DA 현황 분석은 전사 정보자산 관점의 구조 진단이다. DRM은 표준 분류와 교환 기준을 제공하고, DA 분석은 현행 데이터가 그 기준에서 얼마나 이탈했는지 보여준다. 따라서 DA 분석은 TO-BE 데이터 통합 과제의 근거가 된다.

5. 실무 적용 및 판단

채택 조건:

  • 데이터 표준화, MDM, 데이터 허브, DW/레이크 추진 전
  • 시스템 간 인터페이스가 많고 데이터 불일치가 잦을 때
  • AI/분석 활용을 위해 신뢰 가능한 데이터 기반이 필요할 때

회피 조건:

  • ERD만 수집하고 실제 데이터 이동 경로를 보지 않는 경우
  • 업무 용어와 코드 체계를 무시한 채 기술 구조만 보는 경우
  • 품질 문제를 시스템 오류로만 보고 책임 체계를 분석하지 않는 경우

체크리스트:

  1. 핵심 마스터 데이터의 원천 시스템과 책임 부서가 정의되었는가?
  2. 동일 개념의 용어·코드 불일치가 식별되었는가?
  3. 수기 파일, 배치 중계, 중복 저장 경로가 드러나는가?
  4. 정확성·완전성·적시성 같은 품질 지표가 있는가?

그룹사 통합 고객 정보 구축, 공공 데이터 표준화, 제조 기준정보 통합 같은 과제에서 DA 현황 분석은 필수다. 특히 고객·상품·조직 마스터가 시스템마다 다를 때 전사 ERD와 흐름도를 통해 통합 우선순위를 정한다.

6. 기대효과 및 결론

DA 현황 분석은 정보화 사업의 품질과 확장성을 좌우하는 기반 진단이다. 이를 통해 데이터 사일로, 중복 저장, 인터페이스 복잡도를 구조적으로 설명할 수 있고, 이후 TO-BE 데이터 표준과 통합 아키텍처를 설계할 수 있다. 앞으로는 메타데이터 수집 자동화와 데이터 계보(Lineage) 관리가 결합되어 현행 데이터 구조의 실시간 가시성이 중요해질 것이다.
