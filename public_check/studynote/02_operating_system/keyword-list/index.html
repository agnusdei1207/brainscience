5. 교착 상태 (Deadlock) (40개)🔗

  1. 교착 상태 (Deadlock) 정의 - 대기 중인 프로세스들이 자원을 점유한 채로 결코 일어나지 않을 사건을 기다리는 상태
  2. 교착 상태 발생 4가지 필요조건 (모두 만족해야 발생)
  3. 상호 배제 (Mutual Exclusion) - 자원은 비공유 모드로만 사용 가능
  4. 점유하며 대기 (Hold-and-Wait) - 자원을 보유한 상태로 다른 자원 대기
  5. 비선점 (No Preemption) - 다른 프로세스의 자원을 강제로 뺏을 수 없음
  6. 순환 대기 (Circular Wait) - 대기 그래프가 사이클(Cycle)을 형성
  7. 자원 할당 그래프 (Resource-Allocation Graph) - 정점(프로세스, 자원)과 간선(요청, 할당)
  8. 단일 인스턴스 자원 환경 - 사이클 존재 = 교착 상태
  9. 다중 인스턴스 자원 환경 - 사이클 존재 != 교착 상태 (필요 조건일 뿐)
  10. 교착 상태 처리 방법 3가지 - 예방/회피, 탐지/복구, 무시
  11. 타조 알고리즘 (Ostrich Algorithm) - 대부분의 OS가 채택하는 무시 전략
  12. 교착 상태 예방 (Deadlock Prevention) - 4조건 중 하나를 원천적 부정 (효율성 매우 낮음)
  13. 상호 배제 부정 - 모든 자원 공유 (현실성 없음)
  14. 점유 대기 부정 - 실행 전 모든 자원 일괄 할당, 또는 자원 없을 때만 요청 (기아 가능성, 자원 낭비)
  15. 비선점 부정 - 자원 요청 대기 시 보유 자원 강제 반납
  16. 순환 대기 부정 - 자원에 고유 번호(순서) 부여, 오름차순으로만 요청 (가장 현실적 예방책)
  17. 교착 상태 회피 (Deadlock Avoidance) - 실행 전 자원 할당 상태를 검사하여 안전한 경우에만 승인
  18. 안전 상태 (Safe State) - 모든 프로세스가 정상 종료될 수 있는 안전 순서(Safe Sequence)가 존재
  19. 불안전 상태 (Unsafe State) - 교착 상태가 발생할 가능성이 있는 상태
  20. 단일 인스턴스 환경의 회피 - 자원 할당 그래프 알고리즘 (예약 간선/Claim Edge 활용)
  21. 다중 인스턴스 환경의 회피 - 은행원 알고리즘 (Banker's Algorithm, 에츠허르 데이크스트라 제안)
  22. 은행원 알고리즘 자료구조 - Available, Max, Allocation, Need 행렬
  23. 은행원 알고리즘 한계 - 프로세스 수, 최대 자원량 사전 숙지 불가, 오버헤드 큼
  24. 교착 상태 탐지 (Deadlock Detection) - 알고리즘을 주기적으로 실행하여 데드락 확인
  25. 대기 그래프 (Wait-for Graph) - 자원 정점을 제거하고 프로세스 간 간선만 남긴 그래프 (단일 자원 탐지용)
  26. 탐지 알고리즘의 오버헤드 - 언제, 얼마나 자주 실행할 것인가?
  27. 교착 상태 복구 (Recovery from Deadlock) - 데드락 해소 조치
  28. 프로세스 종료 방식 - 교착 상태 프로세스 전체 강제 종료 (Abort all)
  29. 프로세스 순차 종료 방식 - 하나씩 종료하며 사이클 해소 여부 확인
  30. 종료 대상 선택 (희생자 선택) 기준 - 프로세스 중요도, 연산 시간, 보유 자원 수
  31. 자원 선점 (Resource Preemption) 방식 - 다른 프로세스의 자원을 강제로 뺏음
  32. 희생자 선택 (Victim Selection) 최소 비용 기준
  33. 후퇴 (Rollback) - 프로세스를 안전한 상태로 롤백 후 재시작
  34. 기아 상태 (Starvation) 발생 방지 (희생자 선택에 횟수 제한)
  35. 라이브락 (Livelock)과 교착 상태의 차이점
  36. 동기화 결함 (순환 의존성) 코드 레벨 디버깅 기법
  37. 락 오더링 (Lock Ordering) 다이나믹 검증 도구 (Lockdep in Linux)
  38. 분산 시스템에서의 교착 상태 탐지 - 분산 교착 상태 그래프
  39. 교착 상태 예방 메커니즘을 위한 타임아웃 (Timeout) 활용
  40. 2단계 잠금 프로토콜 (2PL)과 데드락 (데이터베이스 연관)

  10. 한계 레지스터 (Limit Register) - 메모리 보호, 주소 범위 검사
  11. 동적 적재 (Dynamic Loading) - 루틴 호출 시점에 메모리 적재 (효율성)
  12. 동적 연결 (Dynamic Linking) - 실행 시점에 라이브러리 연결 (.dll, .so)
  13. 공유 라이브러리 (Shared Library) 스터브 (Stub) 코드
  14. 정적 연결 (Static Linking)

  16. 스왑 아웃 (Swap out) / 스왑 인 (Swap in)
  17. 표준 스와핑 (전체 프로세스) vs 페이징 시스템 스와핑 (페이지 단위)
  18. 연속 메모리 할당 (Contiguous Memory Allocation)
  19. 고정 분할 방식 (Fixed Partition)
  20. 가변 분할 방식 (Variable Partition)
  21. 내부 단편화 (Internal Fragmentation) - 할당된 공간 내 남는 공간
  22. 외부 단편화 (External Fragmentation) - 가용 공간은 충분하나 불연속적이라 할당 불가
  23. 동적 메모리 할당 문제 (가변 분할 배치 알고리즘)
  24. 최초 적합 (First-Fit) - 첫 번째 충분한 공간 할당 (속도 빠름)
  25. 최적 적합 (Best-Fit) - 가장 크기가 비슷한 공간 (자투리 최소화, 검색 시간 소요)
  26. 최악 적합 (Worst-Fit) - 가장 큰 공간 할당 (큰 가용 공간 남김)
  27. 압축 (Compaction) - 외부 단편화 해결, 동적 재배치 시에만 가능, 오버헤드 막심
  28. 버디 시스템 (Buddy System) 할당기 - 2의 승수로 분할 및 병합 (외부 단편화 절충)
  29. 슬랩 할당기 (Slab Allocator) - 커널 객체 캐싱, 단편화 방지 및 속도 향상
  30. 비연속 메모리 할당 (Non-contiguous Memory Allocation)
  31. 페이징 (Paging) - 물리 메모리를 프레임(Frame), 논리 메모리를 페이지(Page)로 고정 크기 분할
  32. 페이지 크기 (Page Size) - 주로 4KB. 커지면 내부 단편화 증가, 테이블 크기 감소

  36. 페이징에서의 공유 페이지 (Shared Pages) - 읽기 전용 코드(Reentrant code) 공유

  40. ASID (Address-Space Identifier) - TLB 내 프로세스 식별, 플러시(Flush) 최소화
  41. 다단계 페이징 (Hierarchical Paging) - 페이지 테이블 크기 문제 해결 (2단계, 3단계...)
  42. 해시 페이지 테이블 (Hashed Page Table) - 주소 공간이 64비트 이상일 때 사용
  43. 역 페이지 테이블 (Inverted Page Table) - 시스템 내 단 하나의 페이지 테이블, 프레임 중심
  44. 세그멘테이션 (Segmentation) - 사용자 관점의 가변 크기 논리적 단위(함수, 객체) 분할
  45. 세그먼트 테이블 (Segment Table) - 기준(Base) 주소와 한계(Limit) 길이
  46. 세그멘테이션과 외부 단편화 (가변 크기이므로 재발생)
  47. 세그멘테이션 기반 페이징 (Paged Segmentation) - 인텔 x86 아키텍처 (세그먼트를 다시 페이지로)
  48. 커널 메모리 할당 방식 (kmalloc, vmalloc)
  49. 메모리 풀 (Memory Pool) 기법
  50. 파편화 관리 및 조각 모음 - 리눅스 메모리 컴팩션 (Memory Compaction)
  51. 거대 페이지 (Huge Pages / Transparent Huge Pages) - TLB 미스 감소
  52. 아키텍처 종속적인 MMU 인터페이스
  53. ARM / x86의 메모리 매핑 아키텍처 차이
  54. 주소 공간 무작위 배치 (ASLR, Address Space Layout Randomization)
  55. 메모리 보호 키 (Memory Protection Keys)
  56. 캐시 인식 데이터 구조 (Cache-aware Data Structures)
  57. NUMA (Non-Uniform Memory Access) 아키텍처와 메모리 할당 정책
  58. 로컬 노드 할당 vs 인터리브 할당
  59. 캐시 컬러링 (Cache Coloring) / 페이지 컬러링
  60. 가비지 컬렉션 (Garbage Collection) 기초 - 참조 카운팅, Mark-and-Sweep

  24. FIFO (First-In, First-Out) 교체 - 가장 먼저 들어온 페이지 교체 (벨라디 모순 발생)
  25. LRU (Least Recently Used) 교체 - 가장 오랫동안 사용되지 않은 페이지 교체 (타임스탬프, 스택 하드웨어 지원 필요)
  26. LRU 근사 알고리즘 (LRU Approximation) - 참조 비트 (Reference Bit) 사용
  27. 2차 기회 알고리즘 (Second-Chance / Clock Algorithm) - 참조 비트가 1이면 0으로 바꾸고 통과, 0이면 교체

  29. LFU (Least Frequently Used) 알고리즘 - 참조 횟수가 가장 적은 페이지 교체
  30. MFU (Most Frequently Used) 알고리즘

  32. 스래싱 (Thrashing) - 프로세스가 실제 실행보다 페이징(스와핑)에 더 많은 시간을 보내는 현상
  33. 다중 프로그래밍 정도 (Degree of Multiprogramming)와 CPU 이용률 관계 그래프

8. 저장장치 및 입출력 (I/O) 시스템 (60개)🔗

  1. I/O 장치의 분류 - 블록 장치 (Block Device) vs 문자 장치 (Character Device)
  2. 블록 장치 - 하드 디스크, SSD (블록 단위 읽기/쓰기, 랜덤 액세스 가능)
  3. 문자 장치 - 키보드, 마우스, 직렬 포트 (스트림 단위, 순차 접근)
  4. 네트워크 장치 (소켓 인터페이스)
  5. I/O 하드웨어 인터페이스 요소 - 데이터 레지스터, 상태 레지스터, 제어 레지스터
  6. 포트 (Port) / 버스 (Bus) - PCIe, USB, SATA, NVMe
  7. 메모리 맵 I/O (Memory-mapped I/O) vs 분리된 I/O (Isolated I/O / Port I/O)
  8. 폴링 (Polling / Programmed I/O) - 상태 비트를 지속적으로 호스트가 읽음 (바쁜 대기)
  9. 인터럽트 구동 I/O (Interrupt-driven I/O) - 완료 시 장치가 CPU에 인터럽트 발생
  10. 직접 메모리 접근 (DMA, Direct Memory Access) - CPU 개입 없이 장치와 메모리 간 직접 데이터 전송
  11. 사이클 스틸링 (Cycle Stealing) - DMA 컨트롤러가 CPU의 버스 사용을 일시 중지시키고 전송
  12. DMA 산란-수집 (Scatter-Gather) - 불연속적 물리 메모리 블록을 한 번의 DMA로 전송
  13. I/O 서브시스템의 커널 서비스 - I/O 스케줄링, 버퍼링, 캐싱, 스풀링, 오류 처리
  14. 버퍼링 (Buffering) - 송수신자 간 데이터 전송 속도 차이, 전송 단위 차이 극복
  15. 이중 버퍼링 (Double Buffering)
  16. 캐싱 (Caching) - 자주 사용하는 데이터 복사본 유지 (속도 빠른 메모리 활용)
  17. 스풀링 (Spooling, Simultaneous Peripheral Operation On-Line) - 디스크를 대형 버퍼로 사용 (프린터 큐)
  18. 예약 및 단독 장치 접근 제어
  19. 블로킹 I/O (Blocking I/O) - I/O 완료 시까지 프로세스 대기
  20. 논블로킹 I/O (Non-blocking I/O) - 데이터가 없어도 즉시 반환 (오류/0 바이트 반환)
  21. 비동기 I/O (Asynchronous I/O, AIO) - I/O 요청 후 즉시 작업 진행, 완료 시 시그널/콜백 알림
  22. I/O 완료 포트 (IOCP, I/O Completion Port) - Windows 비동기 I/O 스케일링
  23. epoll / kqueue - 리눅스/BSD 다중 I/O 이벤트 통지 (고성능 소켓 서버)
  24. io_uring - 최신 리눅스 커널 비동기 I/O 프레임워크 (링 버퍼 기반, 제로 시스템콜 목표)
  25. 하드 디스크 드라이브 (HDD) 구조 - 플래터, 트랙, 실린더, 섹터, 헤드
  26. 논리적 블록 주소 (LBA, Logical Block Address) - 1차원 배열로 매핑
  27. 디스크 접근 시간 = 탐색 시간(Seek Time) + 회전 지연(Rotational Latency) + 전송 시간(Transfer Time)
  28. 디스크 스케줄링 (Disk Scheduling) 목적 - 탐색 시간 최소화, 처리량 극대화
  29. FCFS (First-Come, First-Served) 스케줄링
  30. SSTF (Shortest Seek Time First) - 현재 헤드 위치에서 가장 가까운 요청 처리 (기아 발생 가능)
  31. SCAN 스케줄링 (엘리베이터 알고리즘) - 한 방향으로 이동하며 끝까지 처리 후 역방향
  32. C-SCAN (Circular SCAN) - 한 방향으로만 처리하고 끝에 도달하면 시작점으로 빠르게 복귀 (대기 시간 균등화)
  33. LOOK 및 C-LOOK - 양 끝까지 가지 않고 마지막 요청까지만 이동 후 턴 (SCAN/C-SCAN 최적화)
  34. 리눅스 I/O 스케줄러 - NOOP, CFQ(Completely Fair Queuing), Deadline, BFQ
  35. 솔리드 스테이트 드라이브 (SSD, Solid State Drive) 구조 - NAND 플래시, 페이지(Page), 블록(Block)
  36. 플래시 메모리 한계 - 덮어쓰기 불가(Erase-before-write), 쓰기 횟수 제한(Wear-out)
  37. 가비지 컬렉션 (Garbage Collection in SSD) - 유효 페이지 복사 후 블록 전체 지우기
  38. FTL (Flash Translation Layer) - LBA를 플래시의 물리 주소(PBA)로 매핑하는 펌웨어
  39. 마모 평준화 (Wear Leveling) - 수명 연장을 위해 쓰기 작업을 전체 블록에 고르게 분산
  40. 쓰기 증폭 (Write Amplification) 현상
  41. TRIM 명령어 - OS가 삭제된 파일의 LBA를 SSD에 알려주어 GC 효율 향상
  42. NVMe (Non-Volatile Memory Express) - PCIe 버스 기반 고속 플래시 프로토콜 (다중/깊은 큐 지원)
  43. RAID (Redundant Array of Independent Disks) - 성능 향상 및 신뢰성(중복성) 확보
  44. RAID 0 (스트라이핑, Striping) - 블록 분산 저장, 성능 최고, 신뢰성 없음
  45. RAID 1 (미러링, Mirroring) - 데이터 중복 복사, 신뢰성 최고, 용량 효율 50%
  46. RAID 4 (블록 단위 스트라이핑 + 단일 패리티 디스크) - 병목 발생
  47. RAID 5 (블록 단위 스트라이핑 + 분산 패리티) - 성능/신뢰성 절충, 가장 대중적, 디스크 1개 고장 허용
  48. RAID 6 (분산 이중 패리티) - 디스크 2개 고장 허용
  49. RAID 10 (1+0) / RAID 01 (0+1) 혼합형 구조
  50. 소프트웨어 RAID vs 하드웨어 RAID (컨트롤러 캐시/BBU 장착)
  51. 핫 스페어 (Hot Spare) 디스크 자동 재구성

9. 파일 시스템 (File System) 관리 (70개)🔗

  1. 파일 (File)의 정의 - 논리적 레코드의 연속, OS가 관리하는 정보의 기본 단위

  11. 하드 링크 (Hard Link) - 동일한 물리 데이터(i-node) 가리킴, 디렉터리 링크 불가

  17. VFS (Virtual File System) - 다양한 파일 시스템(ext4, NTFS, FAT)을 추상화하는 공통 인터페이스 객체 모델

  24. 연결 할당 (Linked Allocation) - 블록들이 포인터로 연결됨, 외부 단편화 없음, 랜덤 접근 불가, 포인터 오버헤드
  25. FAT (File Allocation Table) - MS-DOS 기반, 포인터들을 별도의 테이블에 모아 캐싱하여 랜덤 접근 문제 완화
  26. 색인 할당 (Indexed Allocation) - 모든 블록 포인터를 색인 블록(Index Block) 하나에 모아 저장
  27. 색인 블록 크기 한계 해결 - 연결 색인, 다중 수준 색인 (Multilevel Index)
  28. 유닉스 i-node (Index Node) 매커니즘 - 파일 메타데이터 및 다중 접근 포인터 보유

  30. i-node 단일/이중/삼중 간접 블록 (Indirect Blocks) - 대용량 파일 확장 지원 체계
  31. 익스텐트 (Extent) - 연속된 여러 블록의 묶음 할당 기법 (ext4, XFS 적용 - 메타데이터 감소 효과)

  43. NFS (Network File System) - 원격 디렉터리 마운트 프로토콜 (상태 비저장, UDP/TCP 지원)
