핵심: 핵심 인사이트 3줄 비유: 회선 제어 규약 (Line Control Protocol)은(는) 데이터통신 기초와 신호 처리 안에서 데이터와 제어 규칙을 질서 있게 맞춰 주는 교통 체계와 같다.

📝 모범 답안

1. 개요 및 필요성

회선 제어 규약(Line Control Protocol)은 물리 링크 위에서 데이터 전송을 신뢰성 있게 수행하기 위한 규약이다. 크게 문자 지향(Character-Oriented)과 비트 지향(Bit-Oriented) 방식으로 분류된다.

분류대표 프로토콜특징
문자 지향BSC제어 문자(STX/ETX) 기반
비트 지향HDLC, SDLC플래그(01111110) 기반 프레임
바이트 카운트DDCMP헤더에 바이트 수 명시

회선 제어 5대 기능

  1. 회선 접속 — 논리적 연결 설정 (Setup)
  2. 동기 제어 — 비트/문자/프레임 동기 맞춤
  3. 흐름 제어 — 수신자 버퍼 넘침 방지
  4. 오류 제어 — CRC 검출 + ARQ 재전송
  5. 회선 해제 — 전송 완료 후 논리 연결 해제

2. 구성요소

BSC는 IBM이 1960년대 개발한 문자 지향 반이중 프로토콜이다.

[STX] [데이터] [ETX] [BCC]
 시작   본문   종료  오류검사
제어 문자의미
STX본문 시작 (Start of Text)
ETX본문 종료 (End of Text)
ENQ회선 확인 요청
ACK긍정 응답
NAK부정 응답 (재전송 요청)
SYN동기 문자

BSC 한계: 반이중, 포인트-투-포인트만, 다중점 제한, 에러 제어 취약

3. 구조 및 원리

핵심 조건: 회선 제어 규약 (Line Control Protocol)은(는) 대역폭, 지연, 신호 대 잡음비 조건을 함께 만족할 때 안정적으로 동작한다.

동작 순서:

HDLC는 ISO가 정의한 비트 지향 전이중 프로토콜로, X.25·ISDN·PPP의 기반이 된다.

HDLC 프레임 구조

┌────────┬──────────┬────────────┬──────────┬────────┐
│ Flag   │ Address  │  Control   │  Data    │  FCS   │
│01111110│  8 bit   │  8/16 bit  │ 가변 길이 │ 16/32b │
└────────┴──────────┴────────────┴──────────┴────────┘

프레임 종류

프레임기호기능
I-Frame000정보 전송 + 피기백 ACK/NAK
S-Frame01감시 (RR/RNR/REJ/SREJ)
U-Frame11비번호 (설정·해제·초기화)

HDLC 스테이션 모드

  • NRM (Normal Response Mode): 마스터-슬레이브, 폴링 방식
  • ARM (Asynchronous Response Mode): 슬레이브 자발 전송 가능
  • ABM (Asynchronous Balanced Mode): 양방향 대등 전송 → LAP-B, PPP

4. 비교 및 연결

슬라이딩 윈도우 (Sliding Window) 프로토콜

송신측 윈도우: [ 3 | 4 | 5 | 6 | 7 ]  (미확인 전송 가능 프레임)
수신측:        ACK3 수신 → 윈도우 이동 → [ 4 | 5 | 6 | 7 | 8 ]
ARQ 방식재전송 방식효율
Stop-and-Wait1프레임씩 ACK 대기낮음 (1/RTT)
Go-Back-N오류 이후 전부 재전송중간
Selective Repeat오류 프레임만 재전송높음 (버퍼↑)

윈도우 크기: n비트 순서번호 → Go-Back-N: 2ⁿ-1, SR: 2ⁿ⁻¹

5. 실무 적용 및 판단

PPP (Point-to-Point Protocol)

HDLC 기반에서 발전한 PPP는 인터넷 다이얼업·DSL·LCP/NCP 협상을 지원한다.

PPP 연결 설정 과정:
Dead → Establish (LCP) → Authenticate → Network (NCP) → Open
프로토콜계층특징
PPPL2다중 프로토콜, 인증(PAP/CHAP)
PPPoEL2이더넷 위 PPP (DSL)
MLPPPL2다중 링크 묶음
L2TPL2VPN 터널링

6. 기대효과 및 결론

회선 제어 규약 (Line Control Protocol)을 적용하면 대역폭과 지연에 대한 통제력이 높아지고, 운영 일관성과 성능 예측 가능성을 확보할 수 있다. 반면 설정 복잡도, 표준 호환성, 장비 비용, 운영 숙련도라는 전제가 뒤따르므로 무조건적인 도입이 정답은 아니다. 결론적으로 이 주제는 데이터통신 기초와 신호 처리를 이해하는 기준점이며, 최근에는 자동화·가상화·지능형 제어와 결합해 더 세밀한 최적화 방향으로 진화하고 있다.

7. 발전 흐름도

┌─────────────────────────────────────────────────────────────────┐
│             회선 제어 규약 발전 흐름                             │
├──────────────┬──────────────────┬───────────────────────────────┤
│ 1960년대     │ BSC (IBM)        │ 문자 지향, 반이중, 포인트 간   │
│ 1970년대     │ SDLC → HDLC     │ 비트 지향, 전이중, ISO 표준화  │
│ 1980년대     │ X.25 / LAPB      │ 패킷 교환망 링크 계층          │
│ 1990년대     │ PPP / ISDN BRI  │ 다중 프로토콜, 다이얼업 인터넷 │
│ 2000년대     │ PPPoE / L2TP    │ DSL 광대역, VPN 터널           │
│ 2010~현재    │ MPLS / Ethernet │ 링크 제어 → 이더넷 지배        │
└──────────────┴──────────────────┴───────────────────────────────┘
