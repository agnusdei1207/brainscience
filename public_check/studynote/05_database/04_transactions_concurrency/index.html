04. 트랜잭션, 동시성 제어 및 회복

191. 트랜잭션 (Transaction) - 논리적 작업의 기본 단위, 분할할 수 없는 일련의 연산 2026-05-05

193. 원자성 (Atomicity) - All or Nothing (모두 반영되거나 모두 취소) - 회복(Recovery) 관리자가 보장 2026-05-05
194. 일관성 (Consistency) - 트랜잭션 전후에 데이터베이스 제약조건(무결성) 유지 - 병행제어/무결성 제약조건 보장 2026-05-05
195. 격리성 (Isolation) - 실행 중인 트랜잭션 연산에 다른 트랜잭션 간섭 불가 - 병행 제어(Concurrency Control) 보장 2026-05-05
196. 영속성 (Durability) - 성공 완료된 트랜잭션 결과는 영구 반영 - 회복(Recovery) 관리자가 보장 2026-05-05

199. ROLLBACK 명령어 - 트랜잭션 취소, 이전 상태로 복구 2026-05-05
200. SAVEPOINT - 트랜잭션 내 중간 복구 지점 설정 2026-05-05
201. 동시성 제어 (Concurrency Control / 병행 제어)의 목적 - 데이터 일관성 유지, 다중 사용자 처리량 극대화 2026-05-05
202. 병행 수행 시 문제점 (격리성 위배 시) 2026-05-05
203. 갱신 손실 (Lost Update) - 둘 이상의 트랜잭션이 동시 갱신 시, 이전 값이 덮어써져 손실 2026-05-05
204. 모순성 (Inconsistency / Unrepeatable Read) - 동일 데이터 반복 읽기 시 값이 달라지는 현상 2026-05-05
205. 오손 읽기 (Dirty Read) - 다른 트랜잭션이 아직 커밋하지 않은 미확정 데이터를 읽음 2026-05-05
206. 연쇄 복귀 (Cascading Rollback) - 한 트랜잭션 취소 시, 의존하던 다른 트랜잭션도 연쇄 취소 2026-05-05
207. 유령 읽기 (Phantom Read) - 이전 읽기에 없던 새로운 행(INSERT)이 반복 읽기 시 나타남 2026-05-05
208. 스케줄 (Schedule / History) - 트랜잭션 연산의 실행 순서 2026-05-05
209. 직렬 스케줄 (Serial Schedule) - 트랜잭션을 순차적으로 실행 (동시성 0) 2026-05-05
210. 비직렬 스케줄 (Non-serial Schedule) - 인터리빙 방식 병행 실행 2026-05-05
211. 직렬 가능 스케줄 (Serializable Schedule) - 비직렬이지만 결과가 직렬 스케줄과 동일한 스케줄 보장 2026-05-05
212. 충돌 직렬 가능성 (Conflict Serializable) 2026-05-05
213. 락킹 (Locking) 기법 - 상호 배제를 위한 잠금 2026-05-05
214. 공유 락 (Shared Lock / Read Lock, S-Lock) - 읽기 허용, 쓰기 불가 2026-05-05
215. 배타 락 (Exclusive Lock / Write Lock, X-Lock) - 읽기/쓰기 모두 불가 독점 2026-05-05
216. 2단계 락킹 프로토콜 (2PL, Two-Phase Locking) - 직렬 가능성 보장을 위한 락 프로토콜 2026-05-05
217. 확장 단계 (Growing Phase) - 락 획득만 가능, 반납 불가 2026-05-05
218. 축소 단계 (Shrinking Phase) - 락 반납만 가능, 획득 불가 2026-05-05
219. 2PL의 한계 - 교착 상태(Deadlock) 발생 가능성, 연쇄 복귀 위험 2026-05-05
220. 엄격한 2PL (Strict 2PL) - X-Lock을 커밋 전까지 보유 (연쇄 복귀 방지) 2026-05-05
221. 강건한 2PL (Rigorous 2PL) - S-Lock, X-Lock 모두 커밋 전까지 보유 2026-05-05
222. 타임스탬프 순서 (Timestamp Ordering) 기법 - 트랜잭션 진입 시간에 맞춰 직렬화 (비관적 제어 아님, 락 없음) 2026-05-05
223. 낙관적 동시성 제어 (Optimistic Concurrency Control) - 작업 먼저 수행 후 종료(Validation) 시점에 충돌 검사 2026-05-05

226. 블로킹 (Blocking) 현상 완화 (MVCC의 가장 큰 장점 - 읽기가 쓰기를 막지 않고, 쓰기가 읽기를 막지 않음) 2026-05-05
227. 트랜잭션 고립화 수준 (Isolation Level) - ANSI/ISO SQL 표준 4단계 2026-05-05

230. Repeatable Read (레벨 2) - 트랜잭션 내에서 읽은 데이터 락 유지 (MySQL 기본, Phantom Read 발생 가능성) 2026-05-05
231. Serializable (레벨 3) - 완벽한 직렬화, 가장 엄격 (모든 이상현상 방지, 동시성 최저) 2026-05-05
232. 데이터베이스 장애 유형 - 트랜잭션 장애, 시스템 장애, 미디어 장애 2026-05-05
233. 회복 (Recovery) - 장애 발생 전 일관된 상태로 DB 복원 (원자성, 영속성 보장 기법) 2026-05-05
234. Redo (재실행) - 장애 발생 후 커밋된 트랜잭션을 로그 참조하여 재반영 (영속성 보장) 2026-05-05
235. Undo (취소) - 장애 발생 후 커밋 안된 트랜잭션을 이전 상태로 원복 (원자성 보장) 2026-05-05
