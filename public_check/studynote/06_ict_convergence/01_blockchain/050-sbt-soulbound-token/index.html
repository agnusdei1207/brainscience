0. 핵심 인사이트

핵심: 년 Vitalik Buterin, E. 비유: NFT는 팔 수 있는 트로피, SBT는 박힌 훈장 — 남에게 못 주고 본인을 증명하는 데만 쓴다.

📝 모범 답안

1. 개요 및 필요성

  • 2022년 Vitalik Buterin, E. Glen Weyl, Puja Ohlhaver의 논문 "Decentralized Society: Finding Web3's Soul"에서 제안
  • 기존 NFT의 문제: 모든 가치가 시장 가격(양도 가능성)에만 집중 → 사회적 신뢰, 자격 증명 표현 불가
특성NFTSBT
양도성가능 (marketplace 거래)불가 (발행 지갑에 귀속)
표현 대상소유권, 자산신원, 자격, 성취
취소 가능성불가 (소각 외)발행자가 회수 가능
금전 가치주요 목적부차적

2. 구성요소

Soul (지갑/DID)
├── 학력 SBT (발행: 대학)
├── 직업 이력 SBT (발행: 회사)
├── 의료 기록 SBT (발행: 병원)
├── DAO 투표권 SBT (발행: DAO)
└── 범죄 기록 SBT (발행: 법원)

각 SBT는 발행자(Issuer)와 수신자(Soul) 모두 서명.

  • 담보 없는 대출: Soul이 보유한 커뮤니티 SBT → 신용 평가 대체
  • DAO 투표 조작 방지: SBT 기반 고유 신원 → 시빌 공격 방지
  • 학력 인증: 대학이 발행한 학위 SBT → 위조 불가

3. 구조 및 원리

핵심 조건: ERC-721 기반에 locked() 함수 추가 → transferFrom 시 locked=true면 revert.

동작 순서:

// EIP-5192 인터페이스
interface IERC5192 {
    event Locked(uint256 tokenId);
    event Unlocked(uint256 tokenId);
    function locked(uint256 tokenId) external view returns (bool);
}

ERC-721 기반에 locked() 함수 추가 → transferFrom 시 locked=true면 revert.

발행자 → [서명 요청] → Soul 소유자
                              ↓
                      수락 서명 → 온체인 민팅
                              ↓
                      Soul 지갑에 귀속 (양도 불가)

4. 비교 및 연결

SBT가 퍼블릭 블록체인에 기록되면 누구나 해당 Soul의 모든 SBT를 볼 수 있다 → 프라이버시 침해.

증명 시나리오:
"나는 대학 졸업자다" → SBT 내용 공개 X
ZK 증명: 졸업 SBT 보유 증명 + 내용 숨김
         ↓
검증자: 졸업 여부만 확인, 학교 이름·성적 모름
  • 블록체인의 불변성 vs GDPR 망각권 충돌
  • 해결책: 오프체인에 SBT 데이터 저장 + 온체인에 해시만 → 오프체인 데이터 삭제 시 검증 불가 처리

결론적으로 SBT — 소울바운드 토큰 (Soulbound Token)는 기술 자체만으로 성과가 보장되지 않으며, 적용 맥락, 운영 역량, 데이터 품질, 보안·거버넌스 조건이 함께 충족될 때 비로소 실질적 가치가 구현된다.
