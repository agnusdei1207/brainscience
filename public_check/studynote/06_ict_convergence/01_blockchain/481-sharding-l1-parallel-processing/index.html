0. 핵심 인사이트

핵심: 샤딩(Sharding)은 블록체인 L1 네트워크를 여러 샤드(Shard, 파티션)로 분할하여 각 샤드가 병렬로 트랜잭션을 처리함으로써 TPS를 선형 확장하는 기술이다. 비유: 서로 모르는 사람들이 한 장부를 함께 들여다보며 누구도 몰래 숫자를 바꾸지 못하게 감시하는 공동 금고 운영 규칙과 같다.

📝 모범 답안

1. 개요 및 필요성

단일 체인의 확장성 한계

이더리움 모든 노드가 모든 트랜잭션을 처리하면 → 네트워크 최대 TPS = 개별 노드 TPS. 노드 수를 늘려도 TPS는 증가하지 않는다. 샤딩은 이 병목을 깨는 수평 분할(Horizontal Partitioning) 전략이다.

데이터베이스 샤딩 vs 블록체인 샤딩: DB 샤딩은 중앙화 조율자가 있지만, 블록체인 샤딩은 탈중앙화 상태에서 크로스-샤드 원자성(Atomicity)을 보장해야 하는 더 어려운 문제다.

DAS(Data Availability Sampling) 원리

완전 다운로드 없이 데이터 가용성 검증:
1. 데이터를 이레이저 코딩(Erasure Coding)으로 2배 확장
2. 경량 노드: 무작위 위치의 샘플 K개만 다운로드
3. K개 정상 수신 → 97%+ 확률로 전체 데이터 가용 판단
4. K ≈ 30 수준에서 충분한 신뢰도 달성

3. 구조 및 원리

핵심 조건: 샤딩과 다른 접근: 단일 체인 내에서 트랜잭션 의존성 그래프 분석 → 의존성 없는 트랜잭션 병렬 실행 → 이론적 TPS 65,000+.

4. 비교 및 연결

크로스-샤드 트랜잭션 문제

샤드 A → 샤드 B로 자산 이동 시 원자성 보장 필요:

  • 2단계 커밋(2PC): 잠금 → 확인 → 커밋, 지연 발생
  • 영수증 기반 비동기: 샤드 A 소각 증명 → 샤드 B 민팅, 복잡도 증가

기술사 핵심 판단

  1. 왜 이더리움이 실행 샤딩을 포기했나?: 크로스-샤드 원자성 해결 복잡도 + 롤업 생태계가 실행 계층을 대체
  2. Danksharding의 의의: L1은 데이터 가용성 전문화, L2는 실행 전문화 → 모듈러 아키텍처 완성
  3. EIP-4844 효과: 롤업 데이터 비용 10~100배 절감 실현 (2024년 실측)
  4. DAS와 경량 노드: 스마트폰도 블록체인 참여 가능 → 탈중앙화 확장

결론적으로 샤딩과 L1 병렬 처리 (Sharding and L1 Parallel Transaction Processing)는 기술 자체만으로 성과가 보장되지 않으며, 적용 맥락, 운영 역량, 데이터 품질, 보안·거버넌스 조건이 함께 충족될 때 비로소 실질적 가치가 구현된다.
