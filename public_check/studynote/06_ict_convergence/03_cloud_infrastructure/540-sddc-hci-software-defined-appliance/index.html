0. 핵심 인사이트

핵심: SDDC(Software-Defined Data Center)는 컴퓨팅, 스토리지, 네트워킹 전체를 소프트웨어로 추상화하여 하드웨어 벤더 종속성을 제거하고 자동화된 운영을 실현한다. 비유: 전통 데이터센터는 요리사, 웨이터, 청소부가 각각 다른 사장 밑에서 일하는 식당이다. SDDC는 한 매니저(소프트웨어 플랫폼)가 전체 직원을 통합 관리하는 체인 레스토랑이다.

📝 모범 답안

1. 개요 및 필요성

전통적인 데이터센터는 컴퓨팅(서버), 스토리지(SAN/NAS), 네트워크(스위치/라우터)가 벤더별 전용 하드웨어로 분리 운영된다. 이는 구매, 설치, 운영 각각에 전문 인력이 필요하고 자원 활용률이 낮다는 문제가 있다.

SDDC 개념:

  • SDC(Software-Defined Computing): 가상화(VMware vSphere, KVM)
  • SDS(Software-Defined Storage): Ceph, VMware vSAN
  • SDN(Software-Defined Networking): 제어 플레인과 데이터 플레인 분리

이 세 가지를 통합하여 단일 관리 플랫폼에서 전체 인프라를 소프트웨어로 정의하고 자동화하는 것이 SDDC다.

2. 구성요소

SDDC 레이어 구조:

┌──────────────────────────────────────────────────────────────┐
│              관리 플레인 (Management Plane)                    │
│  VMware vCenter / NSX-T / vSAN / Aria Automation             │
├──────────────────────────────────────────────────────────────┤
│              제어 플레인 (Control Plane)                       │
│  SDN 컨트롤러 (OpenDaylight / NSX)                            │
│  SDS 오케스트레이터 (Ceph Mgr / vSAN)                          │
├──────────────────────────────────────────────────────────────┤
│              데이터 플레인 (Data Plane)                        │
│  x86 서버 (vSphere ESXi + vSAN + vNIC)                       │
│  HCI 노드 (Nutanix AHV / VMware VSAN ReadyNode)              │
└──────────────────────────────────────────────────────────────┘
기술역할대표 솔루션
SDC (가상 컴퓨팅)VM, 컨테이너 실행 환경VMware vSphere, KVM
SDS (Software-Defined Storage)분산 스토리지 풀, RAID 소프트웨어화Ceph, VMware vSAN
SDN (Software-Defined Networking)가상 스위치, 방화벽, 라우팅 소프트웨어화NSX-T, OVN
HCI (Hyper-Converged Infrastructure)위 세 가지 통합 단일 어플라이언스Nutanix, VMware VSAN

HCI(Hyper-Converged Infrastructure) 특징:

  • 표준 x86 서버에 컴퓨팅(CPU/RAM) + 스토리지(SSD/HDD) + 네트워킹을 단일 노드로 통합
  • 노드 추가만으로 선형 확장(Scale-Out): 3노드 → 6노드 → N노드
  • 소프트웨어 정의 스토리지(vSAN, Nutanix AOS)로 노드 간 데이터 분산·복제

3. 구조 및 원리

핵심 조건: 기존 3계층 아키텍처 vs HCI**: SDS(Software-Defined Storage) — Ceph: 오픈소스 분산 스토리지.

동작 순서:

기존 3계층 아키텍처 vs HCI:

구분3계층 (서버+SAN+네트워크)HCI
구성전용 하드웨어 계층 분리단일 x86 노드 통합
확장각 계층 개별 확장 (복잡)노드 추가로 선형 확장 (단순)
비용높음 (전용 SAN, FC 스위치)낮음 (표준 x86 서버)
성능높음 (전용 스토리지 최적화)중간 (SDS 오버헤드)
관리복잡 (다수 관리 콘솔)단순 (단일 콘솔)

SDS(Software-Defined Storage) — Ceph: 오픈소스 분산 스토리지. 객체 스토리지(RADOS GW), 블록 스토리지(RBD), 파일 시스템(CephFS)을 동시 제공. Kubernetes 영구 스토리지(PV) 백엔드로 널리 사용.

하이브리드 클라우드 연장: VMware vSphere 기반 온프레미스 HCI를 AWS VMware Cloud로 연결하면 동일한 vSphere 관리 도구로 온프레미스와 AWS 클라우드를 함께 운영 가능.

4. 비교 및 연결

기술사 시험 판단 포인트:

  1. SDDC = SDC + SDS + SDN 세 요소의 결합임을 명확히 정의한다.
  2. HCI 확장 방식(노드 추가 = Scale-Out)을 기존 3계층의 각 계층 개별 확장과 대비한다.
  3. HCI 한계(SDS 오버헤드, 성능 예측 어려움, 초기 라이선스 비용)도 균형 있게 기술한다.

실무 시나리오: 병원의 전자의무기록(EMR) 인프라 현대화 — 레거시 3계층 아키텍처(서버 + NetApp SAN + Cisco FC 스위치)를 Nutanix HCI 4노드 클러스터로 교체. 관리 콘솔 통일, SAN 전문 인력 불필요, 99.99% 가용성 유지, 향후 노드 추가로 용량 선형 확장 가능.

5. 실무 적용 및 판단

SDDC/HCI 도입 기대 효과:

  • 관리 단순화: 단일 플랫폼에서 컴퓨팅/스토리지/네트워크 통합 관리
  • 비용 절감: 전용 SAN/FC 스위치 제거로 초기 구축 비용 30~50% 절감
  • 유연한 확장: 노드 추가로 온디맨드 확장, 과잉 구매 불필요
  • 하이브리드 연장: 온프레미스 HCI를 클라우드로 확장, 일관된 운영 경험

그러나 단일 벤더(VMware/Nutanix) 의존, SDS 오버헤드로 인한 성능 제약, 초기 라이선스 비용 등 한계도 명확히 인지하고 도입 결정해야 한다.

6. 기대효과 및 결론

SDDC/HCI 도입 기대 효과:

  • 관리 단순화: 단일 플랫폼에서 컴퓨팅/스토리지/네트워크 통합 관리
  • 비용 절감: 전용 SAN/FC 스위치 제거로 초기 구축 비용 30~50% 절감
  • 유연한 확장: 노드 추가로 온디맨드 확장, 과잉 구매 불필요
  • 하이브리드 연장: 온프레미스 HCI를 클라우드로 확장, 일관된 운영 경험

그러나 단일 벤더(VMware/Nutanix) 의존, SDS 오버헤드로 인한 성능 제약, 초기 라이선스 비용 등 한계도 명확히 인지하고 도입 결정해야 한다.

결론적으로 SDDC와 HCI 소프트웨어 정의 데이터센터 (SDDC HCI Software-Defined Datacenter)는 기술 자체만으로 성과가 보장되지 않으며, 적용 맥락, 운영 역량, 데이터 품질, 보안·거버넌스 조건이 함께 충족될 때 비로소 실질적 가치가 구현된다.
