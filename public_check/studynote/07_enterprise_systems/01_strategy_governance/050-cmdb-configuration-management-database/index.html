0. 핵심 인사이트

핵심: CMDB — 구성 관리 데이터베이스 (Configuration Management Database)은 조직 운영의 목표, 기준, 실행을 하나의 관리 체계로 연결하는 핵심 개념이다. 비유: CMDB는 건물 설계도 — 각 방(CI)의 위치와 배관(관계)을 모두 기록해서 수리 시 영향도 파악.

📝 모범 답안

1. 개요 및 필요성

CMDB
├── 하드웨어 CI: 서버, 네트워크 장비, 스토리지
├── 소프트웨어 CI: OS, 미들웨어, 애플리케이션
├── 서비스 CI: 비즈니스 서비스, IT 서비스
├── 계약 CI: 라이선스, SLA
└── 관계(Relationship): CI 간 의존성, 위치, 소유
항목자산 관리 (Asset Mgmt)CMDB
초점재무·계약 정보기술 구성·관계
범위구매~폐기 생애주기운영 중 구성 관계
관계 표현미흡핵심 기능

3. 구조 및 원리

핵심 조건: 이 주제는 서비스 정의, 책임 주체, 운영 절차, 측정 기준이 표준화되고 예외 처리 경로까지 설계될 때 안정적으로 작동한다.

동작 순서:

  1. 수요 또는 장애 인지: 요청, 이벤트, 인시던트, 변경 수요를 표준 채널로 수집한다.
  2. 분류와 우선순위 결정: 영향도와 긴급도를 기준으로 처리 경로를 정한다.
  3. 복구·변경·지식 활용: 담당 조직이 해결 절차와 CMDB, 지식 베이스를 활용해 대응한다.
  4. 검증과 개선: SLA 충족 여부와 재발 방지 대책을 확인해 운영 기준을 갱신한다.
방법설명
에이전트 기반CI에 에이전트 설치 → 실시간 정보 수집
에이전트리스SSH/WMI/SNMP로 원격 탐색
API 통합클라우드(AWS, Azure) API로 리소스 수집
네트워크 스캔NMAP 등으로 IP 범위 스캔

여러 탐색 소스의 중복·충돌 데이터를 통합:

소스1 (에이전트): hostname=web01, IP=10.0.0.1
소스2 (네트워크 스캔): IP=10.0.0.1, MAC=aa:bb:cc
조정 결과: CI{hostname=web01, IP=10.0.0.1, MAC=aa:bb:cc}

  • 정확성: 실제 환경과 데이터 일치도
  • 완전성: 필수 속성 채워진 비율
  • 적시성: 데이터 갱신 주기 준수 여부

5. 실무 적용 및 판단

실패 원인해결책
수동 입력 의존자동 탐색 의무화
오너십 불명확CI Owner 지정 + 책임 체계
과도한 CI 범위핵심 CI 우선 정의 후 확장
업데이트 프로세스 미비변경 관리와 CMDB 연동 의무화
Level 1: 기본 하드웨어 CI 수동 관리
Level 2: 자동 탐색 도입, 소프트웨어 CI 추가
Level 3: ITSM 전 프로세스 연계
Level 4: 동적 클라우드 CI 자동 갱신
Level 5: AI 기반 이상 CI 탐지·자동 교정

6. 기대효과 및 결론

이 주제는 조직의 목표와 실행 사이에 공통 기준을 세워 의사결정 일관성, 협업 효율, 변화 대응력을 높인다는 점에서 의미가 크다.

다만 데이터 품질, 책임 분리, 현행화 체계가 약하면 형식적 절차만 늘고 실제 효과는 작아질 수 있다. 향후에는 관측 가능성(Observability), 자동 복구, AIOps와 결합해 더 빠른 탐지와 선제적 운영으로 진화하겠지만, 서비스 관점의 책임 정의가 여전히 핵심이다.

     │  클라우드 확산
     ▼

     │  AI/ML 적용
     ▼
지능형 CMDB (이상 탐지, 자동 교정, 2020s~)
