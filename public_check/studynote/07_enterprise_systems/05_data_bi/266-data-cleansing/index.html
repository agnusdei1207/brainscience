0. 핵심 인사이트

핵심: 데이터 정제는 잘못된 값을 예쁘게 고치는 작업이 아니라, 데이터가 실제 세계를 왜곡하지 않도록 오류·중복·불일치를 통제해 신뢰 가능한 분석 단위로 만드는 품질 공학이다. 비유: 흙이 묻고 부품이 섞인 자재를 그대로 조립하지 않고, 검사·분류·보정해 사용 가능한 자재로 만드는 품질 검사 라인과 같다.

📝 모범 답안

1. 개요 및 필요성

데이터 정제(Data Cleansing)는 원천 데이터에 존재하는 결측, 오류, 중복, 형식 불일치, 표준 불일치 등을 식별하고 교정하여 데이터 품질을 향상시키는 활동이다. DW, ODS, MDM, 머신러닝, 규제 보고 등 어떤 활용 목적이든 입력 데이터가 불량하면 결과 역시 왜곡된다. 따라서 정제는 분석 전 단계의 부수 업무가 아니라 데이터 활용의 신뢰 기반이다.

정제가 필요한 배경은 원천 데이터가 현실을 완벽히 반영하지 못하기 때문이다. 사람 입력 오류, 시스템 간 코드 불일치, 마스터 데이터 불일치, 시간 경과로 인한 값 노후화, 통합 과정의 중복 생성 등이 대표적이다. 이런 문제를 방치하면 동일 고객이 여러 명으로 집계되거나, 금액 단위가 혼합되거나, 휴면 상품이 활성 상품으로 분석되는 오류가 발생한다.

정제는 단일 함수 호출이 아니라 규칙 체계다. 예를 들어 고객 데이터 정제는 이름 표준화, 주소 분해, 전화번호 포맷 통일, 휴면 상태 판정, 중복 고객 병합 등 여러 작업이 순차적으로 결합된다. 따라서 정제 품질은 규칙 정확도뿐 아니라 적용 순서와 예외 처리 전략에 달려 있다.

3. 구조 및 원리

핵심 조건: 정제는 원본 보존, 규칙 기반 일관성, 자동화 가능한 재현성, 과도한 보정 방지라는 조건을 함께 만족해야 한다.

동작 순서:

  1. 프로파일링으로 어떤 컬럼에 어떤 결함이 얼마나 존재하는지 수치화한다. 문제를 모르면 정제 규칙도 설계할 수 없다.
  2. 형식 표준화와 파싱을 수행한다. 예를 들어 주소는 시/도·구·상세 주소로 분리하고, 전화번호는 국가코드 포함 표준 포맷으로 맞춘다.
  3. 검증 규칙을 적용한다. 허용 범위 밖 값, 존재하지 않는 코드, 잘못된 날짜, 필수값 누락을 식별한다.
  4. 중복 데이터를 매칭한다. 완전 일치뿐 아니라 이름+전화번호 유사도, 주소+생년월일 조합처럼 확률적 매칭이 필요할 수 있다.
  5. 생존 규칙(survivorship)에 따라 최종 값을 선택하거나 외부 기준정보로 보강한다. 이때 어떤 값이 왜 선택되었는지 이력을 남겨야 한다.

정제에서 가장 중요한 원리는 '자동 수정의 위험 통제'다. 잘못 설계된 규칙은 오류를 줄이는 대신 진짜 데이터를 훼손할 수 있다. 따라서 원본 보존, 예외 큐, 수동 검토 임계치, 정제 로그가 필수다. 특히 고객명, 주소, 상품 분류 같은 마스터 데이터는 MDM과 연계해 관리해야 지속 가능하다.

4. 비교 및 연결

구분데이터 프로파일링데이터 정제MDM
목적현황 진단문제 교정기준정보 통제
산출물품질 통계·규칙 후보정제 데이터Golden Record
시점정제 전/후적재·운영 중지속 운영

정제는 프로파일링과 분리될 수 없고, MDM과도 깊게 연결된다. 프로파일링이 진단이라면 정제는 치료이며, MDM은 기준정보를 조직 차원에서 안정적으로 유지하는 제도화 단계다. ETL/ELT는 이 정제 규칙을 실제 파이프라인에 탑재하는 실행 구조다.

5. 실무 적용 및 판단

채택 조건은 다중 시스템 통합, 규제 보고, 고객 통합, 캠페인 타기팅, AI 학습 데이터 구축처럼 품질 오차가 큰 비용으로 이어지는 경우다. 회피라는 표현보다, 과도한 자동 보정보다 예외 보류가 더 안전한 영역을 구분하는 판단이 중요하다.

실무 체크리스트:

  • 원본을 별도로 보존하는가
  • 정제 규칙이 수치 기준과 예외 정책을 갖는가
  • 중복 병합 기준과 생존 규칙이 합의되었는가
  • 정제 전후 품질 지표가 비교 가능한가
  • 자동 수정이 불확실한 데이터는 수동 검토로 분기되는가

대표 사례로 통신사는 고객 식별정보 정제를 통해 중복 가입자를 줄이고, 유통사는 상품 마스터 표준화를 통해 카테고리 분석 정확도를 높인다. 도구로는 Informatica DQ, Trillium, Talend, OpenRefine, Python 기반 품질 처리 파이프라인이 활용된다.

6. 기대효과 및 결론

데이터 정제는 분석 정확도 향상, 운영 오류 감소, 고객 통합, 규제 대응력 향상으로 이어진다. 그러나 정제는 한 번의 캠페인이 아니라 지속 운영이다. 데이터가 생성되는 한 오류도 계속 생기므로, 정제는 프로파일링·거버넌스·기준정보 관리와 함께 순환적으로 운영되어야 한다. 결국 좋은 정제는 데이터를 깨끗하게 만드는 것을 넘어, 조직이 데이터를 믿을 수 있게 만든다.
