0. 핵심 인사이트

핵심: 데이터 프로파일링은 데이터를 쓰기 전에 그 구조·분포·규칙 위반을 수치로 드러내어, 정제와 모델링이 감이 아니라 근거 위에서 이뤄지게 만드는 진단 과정이다. 비유: 건물을 수리하기 전에 어디가 기울었고 어디가 균열인지 계측 장비로 먼저 측정하는 정밀 안전진단과 같다.

📝 모범 답안

1. 개요 및 필요성

데이터 프로파일링(Data Profiling)은 데이터의 구조, 값 분포, 패턴, 중복, 결측, 관계, 규칙 위반 여부를 분석해 현재 품질 상태를 진단하는 활동이다. 데이터 통합이나 분석 프로젝트가 실패하는 대표 원인은 원천 데이터를 충분히 이해하지 못한 채 적재와 모델링을 시작하는 것이다. 프로파일링은 이러한 불확실성을 수치화하여 설계 리스크를 줄인다.

프로파일링이 필요한 이유는 메타데이터만으로 실제 데이터 품질을 알 수 없기 때문이다. 컬럼 정의가 NUMBER라고 해도 음수가 없어야 하는 값이 음수로 들어갈 수 있고, 고객ID가 유니크라고 문서에 적혀 있어도 실제로는 중복이 존재할 수 있다. 따라서 실제 값 수준의 탐색과 통계가 선행되어야 정제 규칙, 품질 기준, 적재 전략, 차원 모델링이 제대로 설계된다.

2. 구성요소

요소역할핵심 포인트
Column Profiling단일 컬럼 통계 분석null 비율, distinct, min/max
Pattern Profiling형식·문자열 패턴 분석전화번호, 이메일, 코드 체계
Relationship Profiling테이블 간 관계 분석PK/FK 후보, 참조 누락
Rule Profiling비즈니스 규칙 검증음수 금지, 상태값 범위
Dependency Analysis함수 종속성 탐색코드-명칭 일관성 확인
Quality Dashboard결과 시각화우선순위와 개선 추적

프로파일링은 단순 통계 집계보다 넓은 개념이다. distinct count가 높다는 사실만으로 끝나는 것이 아니라, 그것이 키 후보인지 중복 이상인지 해석해야 한다. 또한 컬럼 단위 진단과 함께 테이블 간 관계, 업무 규칙, 시간 흐름까지 봐야 실무적 가치가 생긴다.

3. 구조 및 원리

핵심 조건: 프로파일링은 대표성 있는 데이터 범위, 재현 가능한 측정 기준, 구조·내용·관계 차원의 다면 분석을 충족해야 한다.

동작 순서:

  1. 분석 범위를 정한다. 전체 데이터, 최근 6개월, 핵심 고객군 등 표본 범위가 잘못되면 진단도 왜곡된다.
  2. 컬럼 수준에서 null 비율, distinct count, 최대·최소값, 평균 길이, 패턴 분포를 측정한다. 이는 품질 문제의 1차 단서다.
  3. 테이블 간 관계를 분석한다. 후보키 중복 여부, 참조 누락, 코드-명칭 매핑 불일치 등을 확인해 정합성 문제를 찾는다.
  4. 비즈니스 규칙을 검증한다. 예를 들어 퇴사일은 입사일보다 뒤여야 하고, 환불 금액은 원주문 금액보다 클 수 없다.
  5. 결과를 규칙 후보와 개선 우선순위로 정리해 정제, ETL 설계, 품질 모니터링 지표로 연결한다.

프로파일링의 핵심은 '문제를 발견하는 것'에서 끝나지 않는다는 점이다. 어떤 문제가 얼마나 심각한지, 분석 결과에 어떤 왜곡을 주는지까지 해석해야 한다. 예를 들어 null 2%는 작아 보이지만 VIP 고객군에서만 집중되면 마케팅 분석에는 치명적일 수 있다.

4. 비교 및 연결

구분데이터 프로파일링데이터 정제데이터 품질 모니터링
목적현황 진단문제 교정지속 감시
시점프로젝트 초기/변경 시적재 전후운영 중 상시
산출물통계, 규칙 후보수정 데이터알림, SLA

프로파일링은 ETL 설계의 입력값이고, 정제의 선행 단계이며, 거버넌스의 객관적 근거가 된다. 또한 MDM에서 기준정보 중복과 불일치를 발견하는 수단으로도 활용된다. 즉 프로파일링은 품질 활동의 출발점이자 반복 개선의 측정 장치다.

5. 실무 적용 및 판단

채택 조건은 신규 DW 구축, 시스템 통합, 데이터 마이그레이션, AI 학습 데이터 준비처럼 원천 데이터 이해가 선행되어야 하는 경우다. 회피라기보다, 전수 분석이 어려운 초대형 데이터셋에서는 핵심 테이블·핵심 컬럼 중심으로 우선순위를 두는 판단이 필요하다.

실무 체크리스트:

  • 분석 범위와 표본 기준이 명확한가
  • 컬럼·관계·규칙 수준 분석을 모두 수행하는가
  • 결과가 정제 규칙과 ETL 설계로 이어지는가
  • 동일 지표를 반복 측정할 수 있는가
  • 품질 이슈가 업무 영향도와 함께 정리되는가

대표 사례로 고객 통합 프로젝트에서는 고객ID 유니크성, 연락처 패턴, 주소 완전성을 프로파일링하고, 금융 데이터 마이그레이션에서는 계좌 잔액의 이상치와 참조 무결성을 먼저 점검한다. 도구로는 Informatica DQ, Talend, Great Expectations, SQL 프로파일링 스크립트가 자주 쓰인다.

6. 기대효과 및 결론

데이터 프로파일링은 데이터 프로젝트의 불확실성을 낮추고, 정제와 적재 규칙을 근거 기반으로 설계하게 만든다. 또한 품질 이슈를 수치로 제시함으로써 거버넌스 의사결정을 돕는다. 결국 프로파일링은 데이터를 설명하는 작업이 아니라, 데이터를 믿어도 되는지 판단하는 진단 체계이며, 정제·ETL·MDM의 시작점이다.
