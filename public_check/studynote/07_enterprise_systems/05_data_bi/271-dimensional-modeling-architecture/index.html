0. 핵심 인사이트

핵심: 다차원 모델링은 비즈니스 사건을 '무엇을 셀 것인가'와 '어떤 관점에서 볼 것인가'로 분리해, 분석 질문이 곧 데이터 구조가 되도록 설계하는 방법론이다. 비유: 복잡한 창고를 상품 수량표와 상품 설명표로 나누어, 재고를 세는 일과 상품을 이해하는 일을 동시에 빠르게 하게 만드는 설계와 같다.

📝 모범 답안

1. 개요 및 필요성

다차원 모델링(Dimensional Modeling)은 분석 중심 데이터 웨어하우스와 데이터 마트를 설계하기 위한 대표 방법론으로, 팩트(Fact)와 차원(Dimension)을 분리해 사용자가 직관적으로 이해하고 빠르게 질의할 수 있게 한다. Ralph Kimball 계열의 데이터 웨어하우스 설계에서 핵심 위치를 차지하며, 비즈니스 프로세스 중심으로 모델을 구성한다.

이 방식이 필요한 이유는 전통적 정규화 모델이 운영 무결성에는 강하지만 분석에는 불리하기 때문이다. 분석 사용자는 주문, 고객, 상품, 시간 같은 친숙한 개념으로 질의하고 싶어 하지, 수십 개 엔터티를 조인해 의미를 해석하고 싶어 하지 않는다. 다차원 모델링은 이 문제를 해결해 비즈니스 질문과 데이터 구조 사이의 거리를 줄인다.

구성요소 중 특히 그레인이 설계의 중심이다. 그레인이 흔들리면 팩트의 의미가 모호해지고, 차원도 무엇을 참조해야 하는지 불명확해진다. 따라서 다차원 모델링은 테이블 이름보다 먼저 한 행의 의미를 정하는 작업이다.

3. 구조 및 원리

핵심 조건: 다차원 모델링은 비즈니스 프로세스 중심 선택, 단일 그레인 선언, 적절한 차원 식별, 측정값 가산성 검토를 충족해야 한다.

동작 순서:

  1. 어떤 비즈니스 프로세스를 모델링할지 정한다. 주문, 배송, 재고, 방문처럼 사건 중심으로 접근해야 분석 가치가 높다.
  2. 팩트 테이블의 그레인을 선언한다. 예를 들어 '주문서 한 줄'인지 '일별 상품 매출'인지 명확히 해야 한다.
  3. 그레인을 설명하는 차원을 식별한다. 언제, 어디서, 누가, 무엇을, 어떤 채널로 같은 관점이 차원이 된다.
  4. 해당 그레인에서 측정 가능한 값을 팩트로 정의한다. 매출액, 수량, 할인액 등이 여기에 해당한다.
  5. 차원 변경 관리(SCD), 역할 수행 차원, 일치 차원 여부를 판단해 장기 확장성을 확보한다.

이 순서가 중요한 이유는 차원과 측정값이 그레인에 종속되기 때문이다. 그레인이 '주문 라인'인데 월별 요약 수치를 팩트에 함께 넣으면 의미가 충돌한다. 반대로 올바른 그레인을 잡으면 스타 스키마, OLAP, 마트 설계까지 자연스럽게 이어진다.

다차원 모델링은 스타 스키마와 스노우플레이크 스키마의 상위 개념이며, 팩트·차원 테이블 설계의 원리적 기반이다. 또한 OLAP, 데이터 마트, semantic layer 구축의 출발점이 된다. 결국 물리 구조보다 먼저 '분석 관점의 논리 모델'을 만드는 단계라고 볼 수 있다.

5. 실무 적용 및 판단

채택 조건은 반복 분석 질문이 존재하고, 비즈니스 사용자가 데이터를 직접 이해하고 활용해야 하며, 지표와 차원 체계를 장기적으로 확장해야 하는 경우다. 회피 조건은 트랜잭션 일관성이 우선인 운영 DB 설계나, 아직 비즈니스 질문이 정리되지 않은 초기 단계다.

실무 체크리스트:

  • 그레인이 한 문장으로 설명되는가
  • 측정값의 가산성 유형이 정의되었는가
  • 차원 속성이 사용자 언어로 이해 가능한가
  • 공통 차원이 다른 팩트와 공유 가능한가
  • SCD 전략이 포함되었는가

대표 사례는 판매 분석 모델, 재고 스냅샷 모델, 고객 접점 분석 모델이다. 특히 Data Vault나 3NF EDW 위에 소비 계층으로 다차원 모델을 추가하는 하이브리드 구조도 실무에서 널리 사용된다.

6. 기대효과 및 결론

다차원 모델링은 분석 성능뿐 아니라 데이터 이해 가능성을 크게 높인다. 사용자가 질문을 차원과 측정값으로 자연스럽게 표현할 수 있어 셀프서비스 분석과 표준 지표 운영에 유리하다. 다만 초기 그레인 설계와 공통 차원 정의에 충분한 시간이 필요하다. 따라서 다차원 모델링은 '빠른 테이블 설계'가 아니라 '오래 사용할 분석 언어 설계'로 접근해야 한다.
