0. 핵심 인사이트

핵심: 스타 스키마는 하나의 팩트를 중심으로 필요한 차원을 단순 방사형으로 연결해, 분석 질의가 적은 조인으로 빠르게 끝나도록 설계한 대표적 다차원 구조다. 비유: 중앙 허브에서 각 목적지로 바로 가는 직항 노선망처럼, 중간 환승 없이 필요한 관점으로 곧바로 연결되는 구조와 같다.

📝 모범 답안

1. 개요 및 필요성

스타 스키마(Star Schema)는 중앙의 팩트 테이블과 주변의 차원 테이블이 방사형으로 연결된 다차원 모델 구조다. 분석 사용자가 이해하기 쉽고, 관계형 또는 컬럼형 엔진에서 조인 경로가 단순해 성능과 사용성이 모두 우수하다. 데이터 마트와 ROLAP 환경에서 가장 널리 쓰이는 이유도 여기에 있다.

스타 스키마가 필요한 이유는 분석 쿼리가 보통 여러 관점을 동시에 필터링하기 때문이다. 시간·지역·상품·고객을 기준으로 집계하려면, 중간 계층이 복잡한 정규화 구조보다 팩트에서 각 차원으로 바로 연결되는 편이 유리하다. 즉 스타 스키마는 일부 중복 저장을 감수하고 분석 단순성과 속도를 얻는 구조다.

스타 스키마의 구성은 단순해 보여도, 실제로는 그레인 정의와 차원 설계가 품질을 좌우한다. 특히 차원 비정규화 정도를 어디까지 허용할지, 공통 차원을 어떻게 공유할지에 따라 마트 간 통합 가능성이 달라진다.

3. 구조 및 원리

핵심 조건: 스타 스키마는 단일 그레인의 팩트, 비정규화 차원, 단순 조인 경로, 사용자 친화적 속성 구성을 만족해야 한다.

                 dim_date
                    |
                    |
 dim_customer -- fact_sales -- dim_product
                    |
                    |
                 dim_store
                    |
                 dim_channel

동작 순서:

  1. 중심이 되는 비즈니스 프로세스와 팩트 그레인을 정의한다. 예를 들어 판매 스타 스키마라면 '주문 라인 1건'이 기준이 된다.
  2. 팩트를 설명하는 차원을 주변에 배치한다. 날짜, 고객, 상품, 매장, 채널 등이 대표적이다.
  3. 차원은 사용자 질의에 필요한 속성을 한 테이블에 평탄화해 저장한다. 이때 과도한 정규화를 피한다.
  4. ETL/ELT가 원천 코드값을 차원 surrogate key로 lookup하여 팩트에 적재한다.
  5. 분석 질의는 차원에서 필터링 후 팩트를 집계하는 패턴으로 실행된다. 단순 조인 경로 덕분에 BI 도구도 쉽게 이해한다.

스타 스키마가 강한 이유는 질의가 예측 가능하기 때문이다. 대부분의 쿼리는 차원 속성으로 조건을 걸고 팩트의 수치를 집계한다. 이 패턴에 맞추어 구조를 미리 단순화했기 때문에 데이터 과학적 자유 탐색보다 반복 경영 분석에 특히 적합하다.

4. 비교 및 연결

스타 스키마는 다차원 모델링의 대표 구현체이며, OLAP, 데이터 마트, semantic layer와 잘 맞는다. 반면 차원 데이터가 지나치게 크거나 계층 분리가 꼭 필요한 경우에는 일부 차원만 스노우플레이크화할 수 있다. 즉 스타는 기본값, 스노우플레이크는 예외적 최적화로 보는 것이 일반적이다.

5. 실무 적용 및 판단

채택 조건은 셀프서비스 BI, 반복 경영 분석, 단순하고 빠른 질의가 필요한 대부분의 분석 환경이다. 회피 조건은 차원 계층이 지나치게 복잡하거나, 차원 중복 저장 비용이 매우 큰 특수 상황이다.

실무 체크리스트:

  • 팩트 그레인이 단일한가
  • 차원이 사용자 관점으로 충분히 평탄화되었는가
  • 공통 차원을 다른 마트와 공유하는가
  • BI 도구가 관계를 쉽게 인식하는가
  • 차원 중복 저장이 수용 가능한가

대표 사례는 판매 마트, 손익 마트, 생산 마트, 고객 행동 마트다. 특히 Tableau, Power BI, Looker 같은 도구는 스타 스키마 구조에서 메타데이터 이해와 성능 최적화가 상대적으로 쉽다.

6. 기대효과 및 결론

스타 스키마는 분석 구조를 단순화해 질의 성능과 사용자 이해도를 동시에 높인다. 이는 단지 조인이 적어서 빠른 것이 아니라, 데이터 모델 자체가 비즈니스 질문과 가까워지기 때문이다. 다만 비정규화로 인한 중복과 SCD 관리 복잡성이 있으므로, 품질 통제와 적재 설계가 뒷받침되어야 한다. 결국 스타 스키마는 분석 우선 환경에서 가장 실용적인 표준 구조다.
