0. 핵심 인사이트

핵심: 데이터 카탈로그는 데이터를 저장하는 시스템이 아니라, 데이터가 무엇이며 믿을 수 있는지 찾고 판단하게 해 주는 조직의 메타데이터 허브다. 비유: 책 자체가 아니라 책의 위치, 주제, 저자, 대출 이력을 알려주는 도서관 검색 시스템과 같다. 📝 모범 답안

1. 개요 및 필요성

데이터 카탈로그는 조직 내 데이터 자산에 대한 메타데이터를 중앙에서 관리하고 검색하게 해 주는 시스템이다. 데이터베이스 테이블, 파일, API, BI 리포트, 머신러닝 피처셋 등 다양한 자산의 위치, 설명, 오너, 품질, 리니지, 사용 이력을 연결해 보여준다.

카탈로그가 필요한 이유는 현대 조직의 데이터 규모와 다양성이 사람의 기억을 초과했기 때문이다. 수백 개 스키마와 수천 개 테이블이 존재하는 환경에서, 필요한 데이터를 찾기 위해 담당자에게 매번 물어보는 방식은 더 이상 작동하지 않는다. 또한 규제와 감사 요구가 커지면서 이 수치가 어디서 왔는가를 추적할 수 있어야 한다.

즉 데이터 카탈로그의 핵심 가치는 검색 편의성만이 아니다. 같은 지표를 여러 팀이 다르게 해석하지 않도록 비즈니스 용어를 표준화하고, 데이터의 신뢰 수준과 책임 주체를 명확히 하는 것이 더 본질적이다.

2. 구성요소

카탈로그는 단순한 사전이 아니라, 자동 수집과 사람의 설명이 결합된 하이브리드 시스템이다. 스키마, 컬럼명, 통계는 자동으로 수집할 수 있지만, 비즈니스 의미나 사용 시 주의점은 사람이 보강해야 한다. 그래서 운영 조직과 도구가 함께 필요하다.

또한 품질 지표와 사용량 지표가 중요하다. 데이터가 존재하는 것과 실제로 추천 가능한 것은 다르기 때문이다. NULL 비율, 갱신 주기, 최근 사용 빈도 같은 정보가 있어야 사용자가 신뢰할 수 있다.

3. 구조 및 원리

핵심 조건: 데이터 자산은 자동 수집 가능한 기술 메타데이터와 사람이 정의하는 비즈니스 메타데이터를 함께 가져야 하며, 리니지와 품질 정보까지 연결되어야 신뢰 가능한 발견이 가능하다.

동작 순서:

  1. 자산 수집 연결: DB, 레이크, ETL, BI 도구, API에 크롤러를 연결한다.
  2. 메타데이터 수집: 스키마, 컬럼, 통계, 위치, 변경 이력 등을 자동 적재한다.
  3. 비즈니스 보강: 오너, 설명, 용어, 중요도, 민감정보 태그를 추가한다.
  4. 리니지 연결: 어떤 원천이 어떤 변환을 거쳐 어떤 리포트에 쓰이는지 그래프로 연결한다.
  5. 검색/추천 제공: 사용자는 키워드, 태그, 도메인으로 적절한 데이터셋을 찾는다.
데이터 소스 / 파이프라인 / BI 리포트
           ↓
      [Crawler 수집]
           ↓
[기술 메타데이터 + 비즈니스 메타데이터]
           ↓
   [리니지 + 품질 + 오너십]
           ↓
     검색 / 발견 / 영향도 분석

이 구조에서 핵심은 찾기 쉬움과 믿을 수 있음이 동시에 충족되어야 한다는 점이다. 검색만 잘 되고 품질 정보가 없으면 잘못된 데이터를 쉽게 찾는 문제가 생긴다. 반대로 메타데이터는 많지만 검색 경험이 나쁘면 아무도 사용하지 않는다. 그래서 카탈로그는 메타데이터 저장소이자 사용자 경험 시스템이다.

4. 비교 및 연결

데이터 카탈로그는 데이터 거버넌스, 데이터 품질, 데이터 리니지와 직결된다. 레이크의 Data Swamp를 방지하고, BI의 공식 지표 정의를 일관되게 만들며, 레이크하우스의 테이블 자산을 탐색 가능하게 만든다. 따라서 카탈로그는 부가 기능이 아니라 현대 데이터 플랫폼의 필수 인프라다.

5. 실무 적용 및 판단

성공 조건:

  • 자동 수집 가능한 자산부터 빠르게 등록할 것
  • 도메인별 데이터 오너를 지정할 것
  • 비즈니스 용어 사전과 연결할 것
  • 품질 점수, 민감정보 태그, 갱신주기를 함께 표시할 것

주의 사항:

  • 카탈로그는 일회성 구축 프로젝트가 아니라 운영 서비스임
  • 설명 입력을 전적으로 수동에 의존하면 곧 노후화됨
  • 현업 용어와 기술 용어를 연결하지 않으면 사용성이 낮음

체크리스트:

  1. 사용자가 검색 후 바로 이해할 설명이 있는가?
  2. 데이터셋 오너와 문의 경로가 있는가?
  3. 컬럼 단위 민감정보 태깅이 되는가?
  4. 리니지가 ETL·dbt·BI까지 연결되는가?
  5. 품질 상태와 최근 사용량이 함께 제공되는가?

대표 솔루션으로는 Apache Atlas, AWS Glue Data Catalog, Microsoft Purview, DataHub, Collibra, Alation 등이 있으며, 클라우드·오픈소스·거버넌스 성숙도에 따라 선택이 달라진다.

6. 기대효과 및 결론

데이터 카탈로그가 정착되면 데이터 탐색 시간이 크게 줄고, 중복 데이터 생성이 줄며, 신뢰 가능한 공식 데이터셋 사용률이 높아진다. 또한 리니지와 오너십이 확보되어 장애·감사·스키마 변경 시 영향도를 빠르게 파악할 수 있다.

하지만 카탈로그는 메타데이터만 쌓는다고 성공하지 않는다. 설명의 최신성, 오너의 책임, 자동 수집, 사용자 검색 경험이 함께 유지되어야 한다. 따라서 결론적으로 데이터 카탈로그의 본질은 목록화가 아니라 데이터를 발견하고 신뢰하고 재사용하게 만드는 조직의 공통 의미 체계에 있다.
