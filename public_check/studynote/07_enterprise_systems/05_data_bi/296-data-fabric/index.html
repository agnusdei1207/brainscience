0. 핵심 인사이트

핵심: 데이터 패브릭 (Data Fabric)은 흩어진 데이터 자산을 하나로 옮기는 대신, 메타데이터·정책·자동화 계층을 깔아 전사 데이터가 하나의 연결망처럼 작동하도록 만드는 통합 아키텍처다. 비유: 여러 도시를 한곳으로 옮기는 것이 아니라, 도로·표지판·교통 규칙을 촘촘히 연결해 어디든 끊김 없이 이동하게 만드는 교통망과 같다.

📝 모범 답안

1. 개요 및 필요성

현대 기업 데이터는 온프레미스, 멀티 클라우드, SaaS, 데이터 레이크, 운영 DB, 스트리밍 플랫폼에 분산되어 있다. 과거처럼 모든 데이터를 중앙 저장소로 복제하려 하면 ETL 복잡도와 지연, 비용이 폭증하고, 데이터 이동 자체가 거버넌스 위험이 되기도 한다.

데이터 패브릭은 이 상황을 "또 다른 저장소 추가"로 해결하지 않는다. 대신 데이터 위치를 유지한 채, 메타데이터와 지식 그래프, 가상화, 정책 자동화, 파이프라인 오케스트레이션을 결합해 전사 데이터 활용 흐름을 연결한다. 핵심은 데이터 그 자체보다 데이터에 대한 이해와 제어를 통합하는 데 있다.

따라서 데이터 패브릭은 특정 제품명이 아니라 아키텍처 패턴이다. 조직이 이미 다양한 플랫폼을 운영하고 있고, 데이터 이동보다 연결과 가시성이 더 중요해진 시점에서 가치가 커진다.

2. 구성요소

구성요소역할핵심 포인트
액티브 메타데이터 (Active Metadata)사용 패턴, 품질, 리니지, 정책 정보를 지속 수집정적 카탈로그를 동적 운영 자산으로 전환
지식 그래프/카탈로그데이터 간 의미적 관계와 소유권 표현검색성과 추천 기능의 기반
데이터 연결/가상화 계층원천 데이터 접근과 연합 질의 제공이동 최소화, 접근 표준화
정책·보안 자동화권한, 마스킹, 보존, 규제 정책 적용중앙 통제와 분산 실행의 연결점
오케스트레이션/관측성파이프라인 실행, 품질 경보, SLA 모니터링운영 폐쇄루프 형성

패브릭에서 중요한 것은 이 구성요소가 느슨하게 연결된 도구 모음이 아니라는 점이다. 예를 들어 액티브 메타데이터가 품질 이상을 감지하면, 정책 계층이 접근 통제를 조정하거나 오케스트레이션이 재처리를 유도하는 식의 폐쇄루프가 만들어져야 한다. 즉 패브릭은 메타데이터 기반 자동화 수준이 높을수록 가치가 커진다.

3. 구조 및 원리

핵심 조건: 메타데이터 표준화, 다중 소스 연결성, 정책 일관성, 자동화 가능한 운영 이벤트가 확보되어야 한다. 단순 카탈로그만 있고 실행 계층과 연결되지 않으면 패브릭이 아니라 메타데이터 저장소에 머문다.

동작 순서:

  1. 자산 발견 및 프로파일링: 각 저장소와 플랫폼의 스키마, 품질, 소유자, 사용 패턴을 수집한다.
  2. 메타데이터 정규화: 서로 다른 시스템의 객체를 공통 모델로 매핑하고, 비즈니스 용어와 기술 메타데이터를 연결한다.
  3. 관계 그래프 구성: 리니지, 참조 관계, 민감도, 소비 패턴을 지식 그래프로 연결한다. 여기서 검색·추천·영향도 분석이 가능해진다.
  4. 정책 자동 적용: PII (Personally Identifiable Information) 탐지, 마스킹, 접근 제어, 보존 정책을 연결된 자산에 일관되게 적용한다.
  5. 활용 및 피드백: 사용자의 질의, 파이프라인 실행, 품질 이벤트가 다시 메타데이터를 갱신해 더 나은 추천과 자동화를 만든다.

데이터 패브릭은 데이터를 모두 가상화하자는 주장이 아니다. 자주 쓰는 고성능 분석 데이터는 여전히 DW나 레이크하우스에 물리적으로 적재할 수 있다. 패브릭은 그 위와 주변에 메타데이터 기반의 연결·정책·검색·자동화를 덧입히는 계층으로 보는 것이 정확하다.

4. 비교 및 연결

항목데이터 패브릭데이터 메시데이터 가상화
중심 축메타데이터와 자동화조직 책임 분산논리적 통합 질의
해결 방식기술 계층으로 연결도메인별 제품화데이터 이동 최소화
강점전사 가시성, 정책 일관성, 추천도메인 정확도, 확장성빠른 통합, 실시간 접근
관계상위 아키텍처운영 모델패브릭 구현 기술 중 하나

데이터 패브릭은 메시와 경쟁 개념이 아니라 보완 개념이다. 메시는 "누가 책임지는가"에 대한 답이고, 패브릭은 "흩어진 자산을 어떻게 연결하고 통제할 것인가"에 대한 답이다. 가상화는 패브릭을 구현하는 기술 요소 중 하나에 가깝다.

5. 실무 적용 및 판단

패브릭 도입이 필요한 조직은 이미 여러 저장소와 플랫폼을 운영하고 있으며, 데이터 이동보다 검색성·정책 일관성·전사 가시성 문제가 더 큰 곳이다. 특히 인수합병 이후 이기종 시스템이 늘어난 조직, 멀티 클라우드 환경, 규제 산업에서 유용하다.

실무 체크리스트:

  • 메타데이터 표준 모델이 정의되어 있는가?
  • 리니지, 품질, 오너십, 민감도 정보가 수집 가능한가?
  • 정책 자동화가 실제 실행 계층과 연결되는가?
  • 패브릭에서 해결할 범위를 명확히 했는가? 모든 데이터를 가상화하려 하지 않는가?
  • 카탈로그, 관측성, 보안, 오케스트레이션 도구 간 연동 전략이 있는가?

안티패턴은 패브릭을 "만능 통합 솔루션"으로 기대하는 것이다. 고성능 분석을 모두 가상화만으로 처리하거나, 메타데이터 품질이 낮은 상태에서 AI 추천 기능만 먼저 도입하면 오히려 혼란이 커진다.

6. 기대효과 및 결론

데이터 패브릭이 잘 작동하면 사용자는 데이터 위치를 몰라도 필요한 자산을 찾고, 정책은 데이터 이동 여부와 무관하게 일관되게 적용되며, 운영팀은 메타데이터 기반으로 이상 징후와 영향도를 더 빠르게 파악할 수 있다. 즉 복잡한 데이터 환경을 관리 가능한 연결망으로 바꾸는 효과가 있다.

하지만 패브릭의 성패는 기술 구매보다 메타데이터 품질에 달려 있다. 잘못된 오너십, 부정확한 리니지, 누락된 민감도 분류 위에서는 어떤 자동화도 신뢰를 얻기 어렵다.

결론적으로 데이터 패브릭은 흩어진 데이터를 하나로 "모으는" 전략이 아니라, 흩어진 상태를 전제로도 통합 활용이 가능하도록 만드는 운영 아키텍처다. 데이터 규모가 아니라 데이터 환경의 복잡성이 커질수록 중요성이 커진다.
