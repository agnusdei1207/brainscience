0. 핵심 인사이트

핵심: SAST(Static Application Security Testing)는 코드 실행 없이 소스코드를 분석하고, DAST(Dynamic Application Security Testing)는 실행 중인 앱에 공격을 시뮬레이션하여 취약점을 탐지하며, 두 방법은 상호 보완적이다. 비유: SAST는 음식 재료(소스코드)를 조리 전에 신선도 검사하는 것이고, DAST는 완성된 요리(실행 중 앱)를 먹어보고 독성을 확인하는 것이다. 둘 다 해야 안전하다.

📝 모범 답안

1. 개요 및 필요성

IBM의 연구에 따르면, 개발 단계에서 수정하는 보안 취약점 비용은 1이지만, 프로덕션에서 발생하는 사고 후 수정 비용은 30배에 달한다. 이것이 소프트웨어 개발 라이프사이클(SDLC)의 초기 단계에 보안을 내재화하는 Shift Left Security가 필요한 이유이다.

**시큐어 코딩(Secure Coding)**은 SQL 인젝션, XSS, 버퍼 오버플로우 등 알려진 취약점 패턴을 코드 작성 단계에서 회피하는 개발 습관이다. 행정안전부의 '소프트웨어 개발 보안 가이드'와 OWASP Top 10이 국내 공공 소프트웨어의 시큐어 코딩 기준이다.

SAST와 DAST는 이 목표를 자동화하는 도구이다. CI/CD 파이프라인에 통합하면 코드 커밋 시마다 자동으로 보안 검사가 수행되어 취약점이 프로덕션에 도달하기 전에 차단된다.

3. 구조 및 원리

핵심 조건: 시큐어 코딩 SAST DAST 정적/동적 분석 체계에서는 정책 수립, 통제 집행, 모니터링, 증적 축적이 끊기지 않는 관리 루프로 연결돼야 실효성이 생긴다.

동작 순서:

  1. 보호 대상과 기준 정의: 자산, 사용자, 규제 요구, 위협 가정을 먼저 식별한다.
  2. 정책 결정과 통제 배치: 인증·인가·암호화·분리·검사 지점을 설계해 적용 범위를 확정한다.
  3. 실행과 검증: 실제 요청·행위·데이터 흐름을 정책과 대조해 허용·차단·격리·경보를 수행한다.
  4. 증적 축적과 개선: 로그, 감사 기록, 사고 결과를 다시 위험 평가와 통제 개선에 반영한다.

SAST False Positive 관리 전략

SAST 도입 실패의 90%는 과도한 False Positive로 인한 개발자 피로(Security Alert Fatigue)이다.

문제해결책
Critical 취약점과 경고 구분 불가CVSS 점수 기반 우선순위 필터링
동일 취약점 반복 경고베이스라인 설정 후 신규 발견만 보고
개발 흐름 방해IDE 플러그인으로 실시간 피드백 (PR 머지 전 해결)
전체 스캔 시간 과다변경된 파일만 증분 스캔 적용

SCA(Software Composition Analysis)와 SBOM(452)의 연결

SAST가 자체 코드를 분석한다면, SCA는 오픈소스 라이브러리의 알려진 취약점(CVE)을 스캔한다. SBOM(Software Bill of Materials)은 이 정보를 공급망 전체로 확장한 개념이다.

4. 비교 및 연결

비교 관점적용 시 강조점연결되는 대안·인접 개념
통제 방식사후 대응보다 사전 정책화와 지속 검증의 비중이 크다.수동 점검, 경계형 방어, 단발성 심사
운영 증적로그·정책·설정·행위 데이터가 증적으로 축적돼야 한다.경험 의존 운영, 문서 중심 준수
확장 전략표준화된 통제 지점이 많을수록 대규모 환경에서도 일관성이 유지된다.예외 처리 남발, 부서별 분산 규칙

공공 소프트웨어 시큐어 코딩 적용 체크리스트 (행정안전부 기준)

  1. 입력 데이터 검증: 모든 외부 입력에 화이트리스트 검증 + 길이 제한 적용
  2. SQL 인젝션 방지: PreparedStatement/파라미터화 쿼리 의무 사용, 동적 쿼리 금지
  3. XSS 방지: 출력 인코딩 (HTML Encoding) 전처리 의무
  4. 인증/인가: 취약한 세션 토큰 금지, JWT 서명 알고리즘 명시 (none 알고리즘 차단)
  5. 암호화: 비밀번호 저장 시 bcrypt/Argon2 해싱, MD5/SHA1 사용 금지

5. 실무 적용 및 판단

채택 조건:

  • 규제 대응, 접근 통제, 감사 가능성처럼 반복 가능한 통제 체계가 필요한 경우
  • 사람 중심 운영을 정책·자동화·증적으로 전환해야 하는 경우

회피 조건:

  • 보호 대상 정의 없이 도구만 먼저 도입하려는 경우
  • 운영 조직과 프로세스가 준비되지 않아 경보·예외 처리만 늘어나는 경우

체크리스트:

  1. 자산·사용자·권한·로그의 기준 데이터가 정리되어 있는가?
  2. 통제 우회 경로와 예외 승인 절차가 문서화되어 있는가?
  3. 감사 증적과 실제 운영 로그가 일치하는가?

기대효과:

  • 개발 단계 보안 취약점 발견으로 수정 비용 30배 절감
  • CI/CD 통합으로 보안 검사 자동화 → 릴리즈 주기 단축과 보안 동시 달성
  • 공공기관 행정안전부 시큐어 코딩 가이드 준수 의무화 요건 충족

한계 및 전제조건:

  • SAST False Positive 관리 없이는 개발 생산성 저하
  • DAST는 실제 환경과 동일한 스테이징 환경 구축 필요
  • 보안 도구가 있어도 개발자의 보안 인식 교육이 병행되지 않으면 효과 반감
  • RASP(Runtime Application Self-Protection)를 프로덕션에 추가하면 성능 오버헤드 발생

6. 기대효과 및 결론

시큐어 코딩 SAST DAST 정적/동적 분석 체계의 가치는 단발성 통제가 아니라 정책과 운영을 연결하는 관리 체계로 접근할 때 가장 크게 나타난다. 제대로 정착하면 침해 확산 억제, 규제 준수, 감사 대응, 운영 표준화 측면에서 높은 효과를 제공한다.

다만 통제 수단만 늘리고 기준 데이터·운영 프로세스를 정비하지 않으면 오히려 복잡도와 오탐, 예외 처리 비용이 증가한다. 앞으로는 자동화된 증적 수집, AI 보조 분석, 프라이버시 강화 기술, 표준화된 인터페이스가 결합되며 시큐어 코딩 SAST DAST 정적/동적 분석 체계의 실효성과 확장성이 함께 높아질 것이다.
