0. 핵심 인사이트

핵심: 하이퍼파라미터 튜닝 (Hyperparameter Tuning)은(는) 인공지능 시스템에서 문제를 표현하고 의사결정 또는 학습으로 연결하는 핵심 개념이다. 비유: 하이퍼파라미터는 요리사가 레시피 전에 결정하는 "오븐 온도"와 "조리 시간" — 재료(데이터)가 조리 중에 알아서 반응하는 것이 파라미터.

📝 모범 답안

1. 개요 및 필요성

파라미터 (Parameter):
  모델 학습 중 데이터에서 자동으로 최적화
  신경망 가중치(W, b)
  선형 회귀 계수 (β0, β1, ...)

하이퍼파라미터 (Hyperparameter):
  학습 시작 전 인간이 설정
  알고리즘의 동작 방식 제어

주요 하이퍼파라미터 예시:

신경망:
  학습률 (Learning Rate): 0.001, 0.01 등
  배치 크기 (Batch Size): 32, 64, 128
  레이어 수, 유닛 수
  드롭아웃율 (Dropout Rate): 0.2~0.5
  에폭 수 (Epochs)

결정 트리 / 앙상블:
  최대 깊이 (Max Depth): 3, 5, 10
  최소 분할 샘플 수
  n_estimators (트리 수)
  learning_rate (부스팅)

SVM:
  C (정규화 강도)
  γ (RBF 커널 파라미터)

2. 구성요소

하이퍼파라미터 튜닝 방법:

1. 그리드 서치 (Grid Search):
   모든 조합 완전 탐색
   예: lr=[0.001,0.01], batch=[32,64] → 4가지
   장점: 완전 탐색, 재현 가능
   단점: 조합 수 지수적 증가 (차원의 저주)

2. 랜덤 서치 (Random Search):
   정해진 탐색 횟수 내 무작위 조합
   Bergstra & Bengio (2012) 논문:
   "랜덤 서치가 그리드 서치보다 효율적"
   이유: 중요하지 않은 HP는 아무 값이나 OK
   장점: 같은 비용에 더 넓은 탐색

3. 베이지안 최적화:
   이전 평가 결과로 다음 탐색 위치 예측
   Gaussian Process + Expected Improvement
   도구: Optuna, Hyperopt, Ax (Facebook)
   장점: 적은 평가로 최적값 근접

4. HyperBand / ASHA:
   조기 종료 (Early Stopping) 활용
   나쁜 설정 빠르게 제거 → 유망한 것 집중

5. AutoML:
   NAS (Neural Architecture Search)
   Google AutoML Tables, H2O, Auto-sklearn

3. 구조 및 원리

핵심 조건: 하이퍼파라미터 튜닝 (Hyperparameter Tuning)의 성능과 타당성은 입력 표현, 핵심 구조 또는 연산, 학습·추론 절차, 평가 기준, 자원 제약이 서로 정합될 때 확보된다.

동작 순서:

학습률 (Learning Rate):
  가장 중요한 하이퍼파라미터
  너무 크면: 발산 (Loss 폭발)
  너무 작으면: 수렴 매우 느림

일반 권고:
  Adam 옵티마이저: 0.001 (기본값)
  SGD: 0.01~0.1

학습률 스케줄러:
  Step Decay: 일정 에폭마다 감소
  Cosine Annealing: 코사인 함수로 감소
  Warm-up: 초반 작게 시작 → 증가 → 감소

학습률 탐색 (LR Finder):
  매우 작게 시작해서 점차 증가
  Loss가 최소인 지점의 1/10 사용

학습률 중요성:
  학습률만 잘 조정해도 성능 10~20% 향상
  배치 크기 2배 시 학습률도 2배 (선형 스케일링)

4. 비교 및 연결

올바른 하이퍼파라미터 검증:

K-Fold 교차 검증:
  데이터를 K개로 분할
  K번 반복: K-1개 훈련, 1개 검증
  평균 성능 = HP 평가 기준

주의: 데이터 누수 (Data Leakage):
  검증 데이터가 학습에 영향 받으면 안 됨

  잘못된 방법:
    전체 데이터 정규화 후 분할 (누수!)
    검증 성능 보고 HP 수동 조정 반복

  올바른 방법:
    분할 후 훈련셋만으로 정규화 파라미터 계산
    검증셋은 훈련셋 기준으로만 변환

테스트 세트 보호:
  HP 튜닝에 테스트 세트 절대 사용 금지
  최종 모델 평가에만 한 번 사용

Nested Cross-Validation:
  외부 CV: 성능 추정
  내부 CV: HP 튜닝
  과적합 방지된 공정한 평가

5. 실무 적용 및 판단

신용 점수 모델 HP 튜닝 실무:

데이터: 50만 명 대출 기록, 150개 특성
기본 모델: XGBoost (기본 HP)
기본 AUC: 0.84

튜닝 전략:

1단계: 중요 HP 선별 (전문 지식)
  n_estimators: 100~2000
  max_depth: 3~10
  learning_rate: 0.01~0.3
  subsample: 0.6~1.0

2단계: 랜덤 서치 50회
  각 조합: 5-Fold CV 평가
  최적 범위 식별
  결과: AUC 0.87~0.88

3단계: 베이지안 최적화 (Optuna, 30회)
  랜덤 서치 결과 기반 범위 좁히기
  결과: AUC 0.89

4단계: 조기 종료 + 최종 학습률 튜닝
  결과: AUC 0.905

성능 개선: 0.84 -> 0.905 (+7.7%)
  신용 점수 1% 개선 = 연 수십억 리스크 감소

모니터링:
  월별 리트레이닝 시 HP 재검증
  데이터 분포 변화 감지 후 전체 튜닝 반복

6. 기대효과 및 결론

성능 개선: 0.84 -> 0.905 (+7.7%) 신용 점수 1% 개선 = 연 수십억 리스크 감소

모니터링: 월별 리트레이닝 시 HP 재검증 데이터 분포 변화 감지 후 전체 튜닝 반복

## 7. 발전 흐름도

[Grid Search (1980s~)] 체계적 탐색, 간단하지만 느림 | v [Random Search 효율성 증명 (Bergstra & Bengio, 2012)] 그리드 서치보다 효율적임 수학적 증명 | v [Bayesian Optimization (Snoek, 2012)] Spearmint, Hyperopt 이전 결과 활용 지능적 탐색 | v [Optuna (2019)] Define-by-run, 병렬 탐색 실무 표준 HP 튜닝 라이브러리 | v [현재: AutoML + 파운데이션 모델] NAS로 아키텍처 자동 탐색 LLM 사전학습 HP = 핵심 연구 영역
