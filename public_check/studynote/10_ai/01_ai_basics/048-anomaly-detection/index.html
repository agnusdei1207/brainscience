0. 핵심 인사이트

핵심: 이상 탐지 — Anomaly Detection은(는) 인공지능 시스템에서 문제를 표현하고 의사결정 또는 학습으로 연결하는 핵심 개념이다. 비유: 이상 탐지 유형 = 이상한 수학 문제 유형 — 포인트 이상(답이 틀림), 맥락적 이상(문제는 맞는데 이 시험에서 틀림), 집합적 이상(각 문제는 맞는데 순서가 이상)!

📝 모범 답안

1. 개요 및 필요성

이상(Anomaly) 정의:
  정상 데이터의 분포에서 크게 벗어나는 관측값

3가지 유형:

1. 포인트 이상 (Point Anomaly):
  단일 데이터 포인트가 비정상

  예:
  신용카드 거래: 평소 3만원 결제
  → 갑자기 500만원 결제 (이상!)

  체온: 정상 36.5°C
  → 갑자기 42°C (이상!)

2. 맥락적 이상 (Contextual Anomaly):
  맥락을 고려할 때 이상 (단독으로는 정상)

  예:
  기온 30°C: 여름에는 정상, 12월에는 이상!

  웹 트래픽 5000RPS: 이벤트 시 정상, 새벽에는 이상!

3. 집합적 이상 (Collective Anomaly):
  개별 포인트는 정상, 패턴이 이상

  예:
  ECG: 각 심전도 값은 정상 범위
  → 전체 파형이 비정상 패턴

  네트워크: 단일 패킷은 정상
  → 수천 개의 작은 패킷이 DDoS 패턴

이상 탐지 접근법:
  통계 기반: Z-score, IQR, 가우시안
  거리 기반: KNN, LOF (Local Outlier Factor)
  클러스터링: DBSCAN, K-means
  머신러닝: Isolation Forest, One-Class SVM
  딥러닝: Autoencoder, LSTM

2. 구성요소

1. 통계 기반:

Z-Score:
  z = (x - μ) / σ
  |z| > 3 → 이상 (99.7% 벗어남)

  가정: 정규 분포
  장점: 단순, 빠름
  단점: 정규 분포 아닌 데이터에 취약

IQR (Interquartile Range):
  Q1, Q3 계산 → IQR = Q3 - Q1
  이상치 경계: [Q1 - 1.5×IQR, Q3 + 1.5×IQR]

  비정규 분포에도 robust

2. 거리 기반:

LOF (Local Outlier Factor):
  각 점의 지역 밀도를 주변 점들과 비교
  LOF >> 1 → 이상 (주변보다 밀도 낮음)

  장점: 지역적 이상 탐지 (전역 기준 불필요)
  단점: 계산 비용 O(n²)

3. 앙상블 기반:

Isolation Forest:
  랜덤 분리로 이상치 빠르게 격리

  원리:
  정상 데이터: 분리하기 어려움 (많은 분리 필요)
  이상 데이터: 분리하기 쉬움 (적은 분리로 격리)

  이상 점수 = 1 / (평균 분리 깊이)

  장점: 빠름(O(n log n)), 고차원에서도 효과적
  단점: 스트리밍 데이터에 약함

4. 딥러닝:

Autoencoder:
  인코더 → 잠재 표현 → 디코더
  학습: 정상 데이터로만 재구성 훈련

  이상 감지: 재구성 오류(MSE) 임계값 초과 → 이상

  장점: 복잡한 패턴 학습
  단점: 임계값 설정 어려움

LSTM Autoencoder:
  시계열 이상 탐지
  정상 패턴 학습 후 미래 예측
  예측 오류 큰 구간 = 이상

3. 구조 및 원리

핵심 조건: 이상 탐지 — Anomaly Detection의 성능과 타당성은 입력 표현, 핵심 구조 또는 연산, 학습·추론 절차, 평가 기준, 자원 제약이 서로 정합될 때 확보된다.

동작 순서:

시계열 이상 탐지:
  시간에 따른 데이터 패턴 이상 감지
  IoT, 보안, 인프라 모니터링

주요 기법:

1. STL 분해 + 잔차 분석:
  시계열 = 추세 + 계절성 + 잔차
  잔차의 Z-score 높은 구간 = 이상

  도구: Python statsmodels

2. Prophet (Facebook):
  추세 + 계절성 자동 감지
  공휴일 효과 지원
  이상치 자동 제외 후 재학습

  사용: 트래픽 이상 탐지, 매출 이상

3. LSTM Autoencoder:
  시퀀스 패턴 학습
  제조 센서 이상 탐지에 강점

4. 통계적 프로세스 제어 (SPC):
  Control Chart (관리도)
  Shewhart X-bar chart: ±3σ 경계
  CUSUM: 누적 합계 이상 탐지 (드리프트 감지)

임계값 설정 전략:

동적 임계값:
  고정 임계값 문제: 계절성 무시
  → 롤링 평균 ± nσ (동적 경계)

  예: 서버 CPU
  월요일 오전 9시 평균 70% → 임계값 90%
  일요일 새벽 평균 20% → 임계값 40%

모델 기반 임계값:
  Percentile 기반: 99.9번째 백분위수
  Bayesian 최적화: FPR/FNR 최적 임계값

실제 시스템:
  AWS CloudWatch Anomaly Detection
  Datadog Anomaly Monitor (Prophet 기반)
  Azure Monitor (ML 기반 기준선)

4. 비교 및 연결

이상 탐지의 트레이드오프:

         탐지 경계 낮춤         탐지 경계 높임
          ────────────────────────────────
탐지율   높음 (더 많이 탐지)   낮음 (덜 탐지)
FPR     높음 (과탐 많음)      낮음 (과탐 적음)
FNR     낮음 (미탐 적음)      높음 (미탐 많음)

Alert Fatigue (경보 피로):
  SOC 팀 현실:
  일 300~500건 보안 경보 → 실제 위협 5건

  결과:
  분석가가 경보를 무시하기 시작
  실제 위협 탐지율 오히려 감소

FP 감소 전략:

1. 화이트리스트:
  알려진 정상 패턴/IP/행동 → 탐지 제외
  예: 정기 백업 작업 → 트래픽 이상 제외

2. 문맥 보강:
  단일 이상 신호 → 다중 신호 상관관계
  "IP 스캔 + 비정상 로그인 + 새 프로세스"
  → 복합 조건 충족 시 경보

3. 학습 기반 FP 억제:
  분석가가 "False Positive" 레이블 → 모델 재학습
  점진적 FP 감소

4. 경보 우선순위화:
  위험도(Risk Score) 계산
  Critical → 즉시 대응
  Low → 주간 배치 검토

Precision-Recall 트레이드오프:
  보안: 높은 Recall 선호 (미탐 비용 > 과탐 비용)
  제조 품질검사: 높은 Precision 선호 (과탐 비용 > 미탐 비용)

5. 실무 적용 및 판단

금융 FDS (Fraud Detection System) 구축:

요구사항:
  초당 거래 10,000건
  이상 거래 비율: 0.1% (하루 약 8,640건)
  최대 허용 FPR: 1% (고객 불편 최소화)

  실시간 탐지 요구: < 50ms

피처 엔지니어링:
  거래 금액 (현재 vs 평균)
  거래 위치 (현재 vs 일반 위치 거리)
  거래 시간 (야간 여부)
  거래 빈도 (1시간 내 거래 수)
  카드 사용 패턴 (새벽 해외 결제)

모델 앙상블:
  Isolation Forest: 거래 금액/패턴 이상
  LSTM: 사용자별 시계열 패턴
  Rule-Based: 명시적 규칙 (해외 + 금액 > 100만)

  최종 판단: 가중 투표 (Weight Voting)

운영 최적화:

1. 실시간 특성 서빙 (Feature Store):
  Redis: 사용자별 최근 거래 윈도우 캐시
  < 5ms 특성 조회

2. 모델 서빙:
  ONNX Runtime: 추론 < 20ms
  배치 사이즈 32로 초당 16,000 거래 처리

3. 임계값 최적화:
  1년치 거래 데이터로 ROC 커브 분석
  FPR 1% @ Recall 72% 지점 선택

결과:
  탐지율: 72% (이상 거래 8,640건 중 6,221건 탐지)
  FPR: 0.8% (허용 1% 이내)

  고객 경험:
  정상 거래 차단: 0.8% → 월 약 20,000건 문의
  자동 재인증(OTP)으로 50%는 즉시 해결

  ROI:
  탐지 사기 = 월 평균 손실 예방 12억원
  시스템 운영 비용 2억원 → 순 ROI 6배

6. 기대효과 및 결론

고객 경험: 정상 거래 차단: 0.8% → 월 약 20,000건 문의 자동 재인증(OTP)으로 50%는 즉시 해결

ROI: 탐지 사기 = 월 평균 손실 예방 12억원 시스템 운영 비용 2억원 → 순 ROI 6배
