0. 핵심 인사이트

핵심: 피처 스토어 (Feature Store)는 ML 파이프라인에서 생성된 특징(Feature)들을 조직 내 여러 팀과 모델이 재사용할 수 있도록 중앙에서 저장·서빙·관리하는 플랫폼으로, 학습 시점과 서빙 시점의 특징이 일치하도록 보장하는 핵심 인프라다. 비유: 피처 스토어는 회사 공용 식재료 창고다. 마케팅팀·영업팀·고객서비스팀이 각각 "이번 달 고객 구매 통계"가 필요할 때, 각자 원재료를 사서 따로 요리하는 대신, 공용 창고(피처 스토어)에서 이미 손질된 재료를 바로 가져다 쓴다. 재료가 신선하고(최신 특징), 모두 같은 것을 쓴다(일관성 보장).

📝 모범 답안

1. 개요 및 필요성

대형 IT 기업에서 추천팀·광고팀·검색팀이 각각 "사용자 최근 7일 구매 이력"이라는 동일한 특징을 필요로 한다고 가정하자. 피처 스토어 없이는 세 팀이 각각 동일한 데이터 파이프라인을 중복 구현한다 — 개발 비용 3배, 불일치 위험도 증가.

또한 추천 모델 학습 시 "사용자 평균 구매 금액"을 계산한 방식과 서빙 시 실시간으로 계산하는 방식이 달라지는 **훈련-서빙 불일치(Training-Serving Skew)**가 발생한다. 이는 모델이 학습한 특징 분포와 서빙 시 특징 분포가 달라져 성능 저하를 일으킨다.

피처 스토어는 이 두 문제를 중앙화된 특징 저장소로 해결한다.

3. 구조 및 원리

핵심 조건: 피처 스토어 (Feature Store)의 성능과 타당성은 입력 표현, 핵심 구조 또는 연산, 학습·추론 절차, 평가 기준, 자원 제약이 서로 정합될 때 확보된다.

동작 순서:

포인트-인-타임 조회 (Point-in-Time Lookup): 학습 데이터 생성 시 "2023년 3월 15일 오후 3시 기준의 특징값"을 정확히 조회하는 기능. 미래 데이터를 과거 예측에 사용하는 데이터 누수(Data Leakage) 방지의 핵심이다. 예: 3월 15일에 예측을 했다면, 3월 15일 이전까지의 데이터만 사용해야 한다.

훈련-서빙 불일치 (Training-Serving Skew): 피처 스토어가 없으면 학습 코드와 서빙 코드의 특징 계산 로직이 달라질 수 있다. 피처 스토어는 동일한 특징 파이프라인 로직을 학습·서빙 모두에 사용하게 강제하여 이를 방지한다.

4. 비교 및 연결

피처 스토어 도입 기준:

  • 팀 수 3개 이상 + ML 모델 5개 이상: 피처 스토어 투자 가치 있음
  • 실시간 추론 지연 요구 < 100ms: 온라인 스토어 필수
  • 규정 준수(GDPR, CCPA): 특징 레지스트리를 통한 데이터 출처 추적 필요

한국 규제 관련: 신용점수 모델(금융위원회 규제), 의료 진단 AI(식약처 규제)에서 모델이 어떤 특징을 어떤 시점의 데이터로 학습했는지 감사 추적(Audit Trail)이 요구된다. 피처 스토어의 메타데이터 관리가 이 규제 준수의 기술적 기반이 된다.

5. 실무 적용 및 판단

피처 스토어는 ML 엔지니어링의 핵심 인프라로, 조직의 AI 생산성을 결정하는 플랫폼이다. 특징 재사용으로 개발 비용을 절감하고, 훈련-서빙 불일치를 제거하여 프로덕션 신뢰성을 높이고, 포인트-인-타임 조회로 데이터 누수를 방지한다. Feast(오픈소스), Tecton, Vertex AI Feature Store, AWS SageMaker Feature Store 등이 대표적 솔루션이며, 대규모 ML 운영 조직에서는 자체 피처 스토어 구축이 경쟁 우위의 원천이 된다.
