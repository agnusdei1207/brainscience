0. 핵심 인사이트

핵심: A/B 테스팅·섀도우 배포·카나리 배포는 ML 모델을 프로덕션 서비스에 안전하게 전환하는 점진적 배포(Progressive Delivery) 전략으로, 실제 트래픽의 일부 또는 복사본에서 새 모델을 검증하여 전체 배포 실패 위험을 최소화한다. 비유: 세 전략은 새 요리를 식당에 올리기 전 검증 과정이다. 섀도우는 주방에서 몰래 새 레시피로 맛을 보는 것(손님에게 안 냄), 카나리는 VIP 손님 3명에게 먼저 맛보게 하는 것, A/B는 절반 손님에게 기존 메뉴, 나머지 절반에게 새 메뉴를 내고 재방문율을 비교하는 것이다.

📝 모범 답안

1. 개요 및 필요성

재학습된 추천 모델이 오프라인 평가에서 CTR(Click-Through Rate)이 5% 향상됐다. 바로 전체 프로덕션에 배포할 수 있을까? 안 된다. 오프라인 평가와 실제 서비스의 차이(Distribution Shift), 예상치 못한 에지 케이스, 인프라 이슈가 있을 수 있다.

점진적 배포 전략은 이 위험을 단계적으로 줄인다:

  1. 섀도우 배포: 사용자 영향 없이 트래픽 복사본으로 새 모델 검증
  2. 카나리 배포: 1~5% 사용자에게 새 모델 노출, 실제 반응 확인
  3. A/B 테스팅: 통계적으로 유의미한 규모로 두 모델을 비교

2. 구성요소

┌──────────────────────────────────────────────────────────────────┐
│         점진적 배포 전략 3종 비교 아키텍처                            │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ① 섀도우 배포 (Shadow Deployment):                               │
│  실제 트래픽 ─────▶ 현재 모델 (Champion) ─────▶ 사용자에게 응답 전송 │
│              └────▶ 새 모델 (Shadow) ────────▶ 응답 로깅만 (미전송) │
│  효과: 사용자 영향 0, 새 모델 성능/오류 완전 검증 가능               │
│                                                                  │
│  ② 카나리 배포 (Canary Release):                                   │
│  실제 트래픽 ─────▶ 라우터 ──── 95% ────▶ 현재 모델 → 사용자        │
│                          └── 5% ─────▶ 새 모델 → 사용자           │
│  효과: 5%만 영향, 실제 사용자 반응 확인, 이상 시 즉시 롤백           │
│                                                                  │
│  ③ A/B 테스팅 (A/B Testing):                                      │
│  사용자 그룹 A(50%) ────▶ 모델 A (현재)                            │
│  사용자 그룹 B(50%) ────▶ 모델 B (새 모델)                         │
│  → 두 그룹의 비즈니스 메트릭(CTR, 전환율, 매출) 통계 비교            │
│  → 유의확률 p < 0.05이면 새 모델로 전환                            │
│                                                                  │
│  배포 단계 (Best Practice):                                       │
│  섀도우(검증) → 카나리 1%(안전 확인) → 10% → 50% → 100%(전체 전환)  │
└──────────────────────────────────────────────────────────────────┘
전략사용자 영향검증 방식적합 상황
섀도우 배포없음응답 로깅 비교처음 검증, 안전 최우선
카나리 배포소수(1~5%)실제 반응 + 에러율점진적 전환
A/B 테스팅대규모(50%+)통계적 유의성 검증비즈니스 메트릭 비교
블루-그린 배포전환 순간즉시 전환 + 롤백인프라 변경 없는 배포

3. 구조 및 원리

핵심 조건: A/B 테스팅 / 섀도우 배포 (Shadow Deployment) / 카나리 (Canary)의 성능과 타당성은 입력 표현, 핵심 구조 또는 연산, 학습·추론 절차, 평가 기준, 자원 제약이 서로 정합될 때 확보된다.

동작 순서:

A/B 테스팅 통계적 유의성:

  • 귀무가설(H₀): 두 모델의 CTR에 차이가 없다
  • 유의확률(p-value): p < 0.05이면 차이가 통계적으로 유의미하다고 판단
  • 샘플 크기: 검정력(Power) 80%, 효과 크기(Effect Size), α=0.05 기준으로 필요 샘플 수 계산
  • AA 테스트: A/B 전에 동일 모델을 A/A로 테스트하여 테스트 인프라 검증

멀티암드 밴딧(Multi-Armed Bandit) vs A/B 테스팅: A/B는 실험 기간 고정 할당, 밴딧은 실시간으로 더 좋은 버전에 더 많은 트래픽 자동 할당. 속도 vs 통계적 순도의 트레이드오프.

4. 비교 및 연결

A/B 테스팅 설계 체크리스트:

  1. 가설 명확화: "새 추천 모델은 기존 대비 CTR을 5% 향상시킨다"
  2. 주요 메트릭 사전 결정: CTR, 전환율, 세션 길이 (p-hacking 방지)
  3. 필요 샘플 수 계산: 통계적 검정력 계산 (α=0.05, Power=0.8)
  4. 최소 실험 기간: 주간 사이클리컬리티 반영 (최소 1~2주)
  5. 보조 메트릭 모니터링: 주요 메트릭 외 에러율·레이턴시·사용자 불만 모니터링
  6. 조기 종료 방지: p-값이 일찍 임계값 넘었다고 실험 중단 금지 (Peeking Problem)

MLOps CI/CD와 연계: 새 모델 학습 → 모델 레지스트리 등록 → 자동 섀도우 배포 → 성능 검증 → 자동 카나리 배포 → 자동 A/B 테스팅 → 결과에 따라 자동 전체 배포/롤백 파이프라인이 Level 2 MLOps의 표준 CD(Continuous Delivery) 구현이다.

5. 실무 적용 및 판단

A/B 테스팅·섀도우·카나리 배포는 ML 모델의 안전한 프로덕션 전환을 위한 업계 표준 방법론이다. "빠르게 배포하되 안전하게"라는 MLOps의 핵심 가치를 구현하는 기술이다. 아마존·넷플릭스·구글은 매일 수백~수천 개의 A/B 테스트를 동시 운영하며, 이 데이터 기반 의사결정 문화가 AI 제품의 지속적 개선과 비즈니스 경쟁력의 원천이 됐다. 기술사 시험에서 ML 시스템 설계 문제에서는 이 배포 전략들을 CI/CD 파이프라인과 연계해서 설명하는 것이 고득점 포인트다.
