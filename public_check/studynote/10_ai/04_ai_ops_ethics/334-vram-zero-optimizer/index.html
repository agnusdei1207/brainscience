0. 핵심 인사이트

핵심: VRAM (Video RAM) 부족은 대형 모델 학습의 핵심 병목이며, ZeRO (Zero Redundancy Optimizer) 는 옵티마이저 상태·그래디언트·파라미터를 GPU 간에 분할해 중복 저장을 제거함으로써 단일 GPU 한계를 돌파한다. 비유: VRAM 부족 문제는 "10명이 같은 두꺼운 교재를 각자 다 사서 들고 다니는" DDP 방식의 낭비와 같다. ZeRO 는 "교재를 10등분해서 한 명이 한 챕터씩만 들고 다니되, 필요할 때 빌려 쓰는" 도서관 방식이다.

📝 모범 답안

1. 개요 및 필요성

VRAM 부족 문제의 구조

GPT-3 (175B 파라미터) 를 FP32 (Float 32-bit Precision) 로 학습하면 파라미터만 700 GB 이상이 필요하다. 단일 A100 GPU 의 VRAM 은 80 GB 에 불과하므로, 파라미터 외에도 다음 요소가 메모리를 압박한다.

구성 요소메모리 비중설명
파라미터 (Parameters)~16%모델 가중치 자체
그래디언트 (Gradients)~16%역전파 결과값
옵티마이저 상태 (Optimizer States)~48%Adam: 모멘텀+분산 각 1copy
활성화 (Activations)~20%순전파 중간 결과

Adam Optimizer 를 사용할 경우 파라미터 1개당 옵티마이저 상태 2개 (m, v) 가 추가되어 실질 메모리 소비는 파라미터 단독 대비 3배 이상 증가한다.

기존 해법의 한계

  • DDP (Distributed Data Parallel): 각 GPU 가 전체 모델 사본을 보유 → VRAM 절감 없음
  • 모델 병렬화 (Tensor/Pipeline Parallelism): 구현 복잡도 높고 파이프라인 버블 발생

2. 구성요소

│            │   전체 보유  │              │                      │
├────────────┼──────────────┼──────────────┼──────────────────────┤
│  파라미터  │    각 GPU    │   각 GPU     │    분할(Shard)       │

├────────────┼──────────────┼──────────────┼──────────────────────┤

DeepSpeed ZeRO 동작 흐름

  Forward Pass (순전파)
  ┌──────────────────────────────────────────────┐
  │  GPU-0      GPU-1      GPU-2      GPU-3      │
  │  P[0..k]   P[k..2k]  P[2k..3k]  P[3k..N]  │  ← Stage 3: 파라미터 분할
  │     │           │          │           │     │
  │     └───────────┴──────────┴───────────┘     │
  │          All-Gather (파라미터 수집)            │
  └──────────────────────────────────────────────┘
  Backward Pass (역전파)
  ┌──────────────────────────────────────────────┐
  │  각 GPU 에서 로컬 그래디언트 계산              │
  │  Reduce-Scatter (그래디언트 집계 + 분산)       │
  │  각 GPU 는 자신의 파라미터 샤드만 업데이트     │
  └──────────────────────────────────────────────┘

ZeRO-Offload 와 ZeRO-Infinity

  • ZeRO-Offload: 옵티마이저 상태·그래디언트를 CPU RAM 으로 오프로드 → 단일 GPU 대형 모델 학습 가능
  • ZeRO-Infinity: NVMe SSD 까지 오프로드 확장, 수조 파라미터 모델 지원

4. 비교 및 연결

GPU VRAM 부족과 ZeRO 옵티마이저 (Zero Redundancy Optimizer)은(는) 유사 개념과 비교할 때 적용 범위, 계산 비용, 해석 가능성, 운영 난이도에서 차이가 난다. 따라서 대안 기술과의 경계와 연결 관계를 함께 판단해야 한다.

5. 실무 적용 및 판단

  1. Stage 선택: 모델 크기와 GPU 수에 따라 Stage 1→2→3 순차 시도
  2. Gradient Checkpointing 병행: 활성화 메모리를 추가 절감 (시간 ~30% 증가)
  3. Mixed Precision (FP16/BF16): VRAM 절반 수준으로 감소, Tensor Core 가속
  4. overlap_comm: 통신과 연산을 파이프라인화해 레이턴시 숨기기
  5. contiguous_gradients: 그래디언트를 연속 메모리에 할당해 AllReduce 효율 향상

기술사 출제 포인트

  • ZeRO 3단계 각각이 절약하는 메모리 구성 요소를 정확히 서술

  • "중복 제거(Redundancy Elimination) vs 통신 오버헤드" 트레이드오프 명시

  • DeepSpeed, Megatron-LM, FSDP (Fully Sharded Data Parallel) 비교 언급

  • 비용 절감: 소규모 GPU 클러스터로 GPT-3 급 모델 학습 가능

  • 확장성: GPU 수 증가에 비례한 메모리 분산 → 선형 확장

  • 생태계: HuggingFace Accelerate, PyTorch FSDP 에 ZeRO 아이디어 통합

  • 한계: All-Gather 통신이 빈번해 네트워크 대역폭이 병목 가능성 존재

ZeRO 는 "메모리 중복을 제거한다" 는 단순한 아이디어로 대형 언어 모델 시대의 핵심 인프라 기술이 되었다. 기술사 시험에서는 Stage 별 분할 대상과 통신 패턴을 정확히 서술하고, DeepSpeed 와의 연동 방식을 언급하면 고득점이 가능하다.

6. 기대효과 및 결론

ZeRO 는 "메모리 중복을 제거한다" 는 단순한 아이디어로 대형 언어 모델 시대의 핵심 인프라 기술이 되었다. 기술사 시험에서는 Stage 별 분할 대상과 통신 패턴을 정확히 서술하고, DeepSpeed 와의 연동 방식을 언급하면 고득점이 가능하다.
