0. 핵심 인사이트

핵심: AIC (Akaike Information Criterion)와 BIC (Bayesian Information Criterion)는 모델의 적합도와 복잡도 사이의 균형을 수치화하는 정보 기준이다. 비유: 시험 점수만 보고 반을 편성하면 인원만 많은 반이 유리해진다. AIC/BIC는 학생 수가 많아질수록 생기는 "과밀 보정"이다.

📝 모범 답안

1. 개요 및 필요성

모델 선택은 "가장 잘 맞는 것"과 "너무 복잡하지 않은 것"을 동시에 만족시켜야 한다. AIC와 BIC는 이 문제를 우도에 패널티를 더하는 방식으로 해결한다.

특히 군집화, 회귀, 시계열, 혼합모형(GMM)처럼 후보 모델이 여러 개일 때, 단순 점수만 비교하면 파라미터 수가 많은 모델이 무조건 유리해진다. 정보 기준은 이런 편향을 보정한다.

┌──────────────────────────────────────────────────────────────┐
│                 Model Selection via Information Criteria      │
├──────────────────────────────────────────────────────────────┤
│ Candidate model → Likelihood fit → Complexity penalty → Score│
└──────────────────────────────────────────────────────────────┘

2. 구성요소

두 기준은 모두 -2 ln(L)에 복잡도 항을 더한다. 차이는 패널티의 크기다.

기준수식패널티 성향해석
AICAIC = 2k - 2 ln(L)중간예측 성능과 복잡도의 균형
BICBIC = k ln(n) - 2 ln(L)강함더 단순한 모델 선호

여기서 k는 파라미터 수, n은 샘플 수, L은 우도다. n이 커질수록 BIC의 패널티가 더 커지므로, 대규모 데이터에서는 BIC가 더 보수적으로 동작한다.

┌──────────────────────────────────────────────────────────────┐
│                 AIC vs BIC Penalty Strength                  │
├──────────────────────────────────────────────────────────────┤
│ AIC:  2k              → predictive / flexible               │
│ BIC:  k ln(n)         → parsimonious / conservative          │
└──────────────────────────────────────────────────────────────┘

3. 구조 및 원리

핵심 조건: AIC/BIC 모델 선택 (Akaike Information Criterion / Bayesian Information Criterion)의 성능과 타당성은 입력 표현, 핵심 구조 또는 연산, 학습·추론 절차, 평가 기준, 자원 제약이 서로 정합될 때 확보된다.

동작 순서:

항목AICBIC엘보우 / 실루엣
기준예측 성능설명력과 간결성거리 기반 구조
패널티고정 2kk ln(n)없음(경험적)
강점유연함단순 모델 선호직관적
약점복잡한 모델을 덜 벌줌과소적합 가능주관성 존재

AIC/BIC는 409번의 K-Means 엘보우·실루엣과도 연결된다. 엘보우가 군집의 거리 구조를 보는 경험적 지표라면, AIC/BIC는 확률모형의 적합도와 복잡도를 함께 보는 모델 선택 기준이다.

4. 비교 및 연결

  1. 후보 모델들을 같은 데이터에서 학습한다.
  2. 각 모델의 우도와 파라미터 수를 구한다.
  3. AIC/BIC를 계산한다.
  4. 값이 가장 작은 모델을 우선 선택한다.

5. 실무 적용 및 판단

  1. 모델 간 비교가 같은 데이터셋과 같은 전처리 조건에서 이루어졌는가?
  2. 예측이 목적이면 AIC를, 설명과 간결성이 중요하면 BIC를 우선 고려했는가?
  3. 파라미터 수 k를 정확히 센 뒤 비교했는가?
  4. AIC/BIC가 비슷하면 교차검증 (Cross Validation)이나 도메인 기준을 추가했는가?

안티패턴

  • 우도만 보고 파라미터가 많은 모델을 선택
  • AIC/BIC가 낮다는 이유만으로 비즈니스 해석을 무시
  • 샘플 수가 작은데 BIC를 절대 기준처럼 사용

기술사 관점에서는 "정보 기준은 답이 아니라 경고등"이라고 설명하는 것이 좋다. 점수 차이가 크면 선택 근거가 강해지고, 차이가 작으면 추가 검증이 필요하다.

AIC/BIC를 쓰면 모델 선택이 감이 아니라 기준이 된다. 특히 시계열, 혼합모형, 변수 선택에서 과적합을 줄이고 재현성을 높일 수 있다.

결론적으로 AIC/BIC는 **'잘 맞는 모델'**과 **'지나치게 복잡한 모델'**을 구분하는 장치이므로, 우리는 목적에 맞는 패널티 철학을 먼저 정해야 한다.
