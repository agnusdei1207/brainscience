0. 핵심 인사이트

핵심: 인스턴스 정규화 (Instance Normalization, IN)와 그룹 정규화 (Group Normalization, GN)는 배치 전체가 아니라 샘플 내부 통계량으로 활성값을 정규화해, 작은 배치에서도 안정적인 학습을 가능하게 하는 기법이다. 비유: BN이 반 전체 시험 점수 평균으로 학생을 보정하는 방식이라면, IN/GN은 각 학생의 답안지 안에서만 기준을 잡는 방식이다. 반 인원이 3명으로 줄어도 채점 기준이 덜 흔들린다.

📝 모범 답안

1. 개요 및 필요성

정규화의 목적은 층마다 입력 분포가 급격히 흔들리는 현상을 줄여, 학습을 더 안정적으로 만드는 데 있다. 문제는 BN이 평균과 분산을 배치 축에서 계산한다는 점이다. GPU 메모리 한계로 배치 크기를 2~4 정도로 줄이면 추정된 통계량의 분산이 커지고, 멀티 GPU 환경에서는 디바이스마다 통계량이 달라져 학습 품질이 흔들린다.

이 한계를 해결하기 위해 등장한 것이 IN과 GN이다. 둘 다 통계량 계산 범위를 배치 밖에서 찾지 않고, 현재 샘플 내부로 가져온다. 그래서 배치 크기가 1이어도 수식이 성립하고, 추론 시에도 학습 시와 다른 이동 평균을 붙잡고 흔들릴 일이 적다.

┌──────────────────────────────────────────────────────────────┐
│         정규화 축의 차이: 배치 밖을 볼 것인가, 안을 볼 것인가 │
├──────────────────────────────────────────────────────────────┤
│ BN : [N, H, W] 축으로 채널별 평균/분산 계산                  │
│ IN : [H, W] 축으로 샘플·채널별 평균/분산 계산                │
│ GN : [C/G, H, W] 축으로 샘플 내부 그룹별 평균/분산 계산      │
│                                                              │
│ 핵심: IN/GN은 배치 크기 N에 의존하지 않는다                  │
└──────────────────────────────────────────────────────────────┘

이 그림의 핵심은 "무엇을 묶어 평균을 낼 것인가"다. BN은 같은 채널을 여러 샘플에 걸쳐 평균 내지만, IN/GN은 한 샘플 내부에서만 계산한다. 즉, 배치 통계의 불안정성을 구조적으로 제거한 것이다.

2. 구성요소

입력 텐서를 x ∈ R^{N×C×H×W}라고 하자. 정규화는 기본적으로 x̂ = (x - μ) / sqrt(σ² + ε) 형태를 따른다. 차이는 평균 μ와 분산 σ²를 어떤 축에서 계산하느냐다.

기법평균/분산 계산 범위장점약점
BN배치 N과 공간 축 H, W대규모 배치에서 강력소배치, 분산 환경에 민감
IN샘플 내부 채널별 H, W스타일 성분 제거에 강함분류용 표현력 감소 가능
GN샘플 내부 그룹별 C/G, H, W소배치 CNN에 안정적그룹 수 설정이 필요

대표 수식은 다음과 같이 이해하면 된다.

$$ \mu^{IN}{n,c} = \frac{1}{HW}\sum{h,w} x_{n,c,h,w}, \quad \mu^{GN}{n,g} = \frac{1}{|S_g|}\sum{(c,h,w)\in S_g} x_{n,c,h,w} $$

여기서 S_g는 하나의 그룹에 속한 채널과 공간 위치 집합이다. IN은 채널을 더 세밀하게 나누고, GN은 여러 채널을 한 그룹으로 묶는다. 그래서 IN은 스타일을 강하게 제거하는 반면, GN은 채널 간 상관관계를 어느 정도 보존한다.

┌──────────────────────────────────────────────────────────────┐
│            샘플 하나 내부에서 통계량을 계산하는 방식          │
├──────────────────────────────────────────────────────────────┤
│ 입력 feature map                                              │
│                                                              │
│ IN : [채널 1] [채널 2] [채널 3] [채널 4]                     │
│      └각 채널이 자기 H×W 평균/분산을 따로 계산┘              │
│                                                              │
│ GN : [채널 1|채널 2] [채널 3|채널 4]                         │
│      └그룹별로 묶어 H×W와 함께 평균/분산 계산┘               │
│                                                              │
│ 결과: 배치 크기와 무관하게 정규화 가능                        │
└──────────────────────────────────────────────────────────────┘

CNN에서는 GN이 특히 유용하다. 객체 검출과 세그멘테이션은 입력 해상도가 커서 배치 크기를 크게 가져가기 어렵기 때문이다. 반대로 RNN (Recurrent Neural Network)은 시간축 의존성이 강하고 채널 그룹화보다 은닉 상태 전체 정렬이 중요해, 실무에서는 보통 LN이 더 자주 쓰인다. 따라서 "CNN 소배치 문제"냐 "순환 은닉 상태 안정화"냐에 따라 선택 축이 갈린다.

3. 구조 및 원리

핵심 조건: 인스턴스 정규화 vs 그룹 정규화 (Instance Normalization vs Group Normalization)의 성능과 타당성은 입력 표현, 핵심 구조 또는 연산, 학습·추론 절차, 평가 기준, 자원 제약이 서로 정합될 때 확보된다.

동작 순서:

정규화 기법은 결국 "어떤 통계량이 현재 문제의 신호를 가장 덜 왜곡하는가"를 묻는다.

비교 축INGNBNLN
배치 크기 의존성없음없음큼없음
CNN 소배치 학습보통강함약함보통
스타일 정보 제거매우 강함중간약함중간
RNN/시퀀스 적합성낮음보통낮음강함

IN은 스타일 전이 (Style Transfer)에서 강점을 보인다. 샘플별 평균과 분산이 이미지의 스타일 성분과 밀접하기 때문에, 이를 정규화하면 내용 구조는 남기고 스타일 편차를 줄이기 쉽다. GN은 이보다 덜 공격적으로 정규화해 분류, 검출, 세그멘테이션처럼 의미 표현을 유지해야 하는 작업에 더 적합하다.

또한 GN은 SyncBN (Synchronized Batch Normalization)의 대안으로 자주 거론된다. SyncBN은 여러 GPU의 배치 통계를 강제로 모아 BN을 유지하는 방식이고, GN은 애초에 배치 통계를 쓰지 않으므로 통신 오버헤드를 줄인다. 즉, 분산 학습 환경에서 네트워크 비용까지 고려하면 GN이 더 실용적일 수 있다.

4. 비교 및 연결

인스턴스 정규화 vs 그룹 정규화 (Instance Normalization vs Group Normalization)은(는) 유사 개념과 비교할 때 적용 범위, 계산 비용, 해석 가능성, 운영 난이도에서 차이가 난다. 따라서 대안 기술과의 경계와 연결 관계를 함께 판단해야 한다.

5. 실무 적용 및 판단

  1. 배치 크기가 8 미만으로 떨어지는가?
  2. 작업이 스타일 전이처럼 샘플별 스타일 편차 제거에 민감한가?
  3. 객체 검출·세그멘테이션처럼 고해상도 입력 때문에 소배치가 불가피한가?
  4. RNN/LSTM (Long Short-Term Memory)처럼 시간축 정렬이 핵심인 구조인가?
  5. 다중 GPU에서 통계량 동기화 비용을 감당할 수 있는가?

소배치 CNN에서는 먼저 GN을 검토하는 편이 안전하다. 검출·세그멘테이션 백본에서 BN이 흔들리면 SyncBN으로 가거나 GN으로 바꾸게 되는데, 통신 병목과 구현 단순성까지 보면 GN이 더 실무적인 경우가 많다. 반면 스타일 전이나 생성 모델의 스타일 제어에서는 IN이 더 직접적이다.

RNN 계열에서는 GN을 무리하게 넣기보다 LN을 우선 검토하는 편이 낫다. 순환 은닉 상태는 시간 단계별 분포 안정화가 중요해서, 채널 그룹 기준보다는 레이어 전체 기준이 더 자연스럽기 때문이다. 시험 답안에서는 "GN은 CNN 소배치 대안, LN은 RNN/Transformer 대안"으로 정리하면 경계가 선명해진다.

안티패턴

  • 배치가 매우 작은데도 관성적으로 BN을 유지하는 설계
  • 스타일 보존이 중요한데 IN을 써서 표현력을 과도하게 지워 버리는 설계
  • GN의 그룹 수를 채널 구조와 무관하게 임의로 잡아 표현을 깨뜨리는 설계

IN과 GN은 "배치가 작아도 학습이 흔들리지 않게 하자"는 현실적 요구에서 나온 정규화 해법이다. IN은 스타일 성분 제어에 강하고, GN은 소배치 CNN의 범용 대안으로 자리 잡았다.

결론적으로 이 주제의 핵심은 정규화 기법의 우열이 아니라 통계량을 어떤 축에서 계산해야 현재 문제의 신호를 덜 망가뜨리는가에 있다. 소배치 CNN이면 GN, 스타일 변환이면 IN, 시퀀스 모델이면 LN이 우선 후보라는 식으로 기억하면 실무 판단이 빨라진다.
