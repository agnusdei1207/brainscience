0. 핵심 인사이트

핵심: 가변(Mutable) 인프라는 실행 중인 서버에 접속해 수정하는 방식이고, 불변(Immutable) 인프라는 절대 수정하지 않고 새 이미지로 통째로 교체하는 방식이다. 비유: 가변 인프라는 오래된 자동차를 계속 수리해가며 타는 방식이고, 불변 인프라는 문제가 생기면 새 차로 교체하는 렌터카 방식이다.

📝 모범 답안

1. 개요 및 필요성

전통적인 서버 관리는 SSH로 접속하여 패치를 적용하고 설정 파일을 수정하는 가변 방식이었다. 시간이 지남에 따라 각 서버는 서로 조금씩 다른 상태를 갖게 되는데 이를 **구성 드리프트(Configuration Drift)**라고 한다. "개발 환경에서는 되는데 운영에서는 안 된다"는 고전적인 문제의 원인이다.

불변 인프라(Immutable Infrastructure)는 "서버는 절대 수정하지 않는다"는 원칙이다. 코드나 설정을 바꿔야 할 때는 새 이미지를 빌드하고, 기존 서버를 완전히 교체한다. 도커 컨테이너가 이 철학의 완벽한 구현체다. 컨테이너는 기동 후 내부를 수정하지 않고, 새 버전 배포 시 이전 컨테이너를 삭제하고 새 컨테이너를 시작한다.

이 패러다임 전환의 배경에는 Phoenix Server 개념이 있다. 불사조처럼 언제든 죽고 다시 태어날 수 있는 서버를 지향하며, 반대 개념은 오랫동안 손수 돌봐야 하는 Snowflake Server다.

3. 구조 및 원리

핵심 조건: 변경 자동화와 운영 안정성은 별개가 아니라 하나의 루프이며, 빌드·검증·배포·관측·피드백이 끊기지 않아야 지속 개선이 가능하다.

동작 순서:

  1. 변경 사항을 버전 관리 시스템에서 감지한다.
  2. 빌드·테스트·보안 검증으로 변경의 품질을 빠르게 확인한다.
  3. 승인된 산출물을 선언형 배포나 자동화 파이프라인으로 운영 환경에 반영한다.
  4. 메트릭·로그·트레이스를 통해 실제 동작 결과를 관측한다.
  5. 피드백을 다음 개선 주기에 연결해 반복적으로 신뢰성을 높인다.

배포 원칙과의 연결

원칙/기술가변과의 관계불변과의 관계
컨테이너(Docker)-불변의 완벽한 구현
Blue/Green 배포어려움자연스럽게 연결
IaC(Terraform)함께 사용 가능이미지 교체와 시너지
카나리 배포복잡이미지 비율 조정으로 구현
Configuration Drift근본 원인원천 차단

불변 이미지 빌드 도구:

  • Packer: HashiCorp 제공, AMI(AWS Machine Image) 등 VM 이미지 빌드
  • Dockerfile: 컨테이너 이미지 빌드 명세
  • Kaniko: Kubernetes 환경에서 Docker 데몬 없이 이미지 빌드

4. 비교 및 연결

Golden Image 전략: 보안 패치, 기본 에이전트(모니터링, 로그 수집)가 포함된 "황금 기반 이미지"를 주기적으로 빌드하고, 모든 서비스 이미지는 이 기반 이미지를 FROM으로 사용한다.

실무 시나리오:

  1. 보안 취약점(CVE) 발견 → 기반 이미지 패치 재빌드
  2. 모든 서비스 이미지 자동 재빌드 (CI 파이프라인)
  3. Blue/Green으로 순차 교체 → 취약점 완전 제거

트레이드오프 관리:

  • 이미지 빌드 시간이 길면 빌드 캐시 레이어 최적화 필요
  • 컨테이너 내부 ephemeral 스토리지 → 데이터는 외부 볼륨 분리 필수
  • 디버깅 어려움 → 충분한 로그/트레이스 설계가 선행되어야 함

5. 실무 적용 및 판단

불변 인프라는 운영 환경의 예측 가능성을 극적으로 높인다. "개발 환경과 운영 환경의 차이"라는 고질적인 문제가 "동일 이미지"로 완전 해소된다. 롤백이 이미지 태그 변경으로 수분 내 완료되며, 보안 패치 적용이 이미지 교체로 표준화된다.

현대 쿠버네티스 기반 환경에서 불변 인프라는 이미 기본값이다. Pod는 기동 후 수정하지 않고, 이미지 버전을 바꿔 재배포하는 것이 표준 운영 방식이다. 앞으로의 과제는 불변 인프라의 이점을 VM 레벨의 인프라 프로비저닝까지 확장하는 것이다.

6. 기대효과 및 결론

가변 vs 불변 인프라 (Mutable vs Immutable Infrastructure)를 올바르게 적용하면 확장성, 운영 안정성, 자동화 수준, 가시성을 함께 높일 수 있다. 다만 이 효과는 기술 자체만으로 생기지 않으며, 책임 경계·표준화·보안 통제·비용 관리가 함께 설계될 때 비로소 현실화된다.

향후에는 관리형 서비스, 정책 자동화, AI 기반 운영 최적화와 결합되면서 가변 vs 불변 인프라 (Mutable vs Immutable Infrastructure)의 중요성이 더 커질 것이다. 따라서 핵심은 특정 도구를 도입하는 것이 아니라, 업무 특성과 조직 역량에 맞는 적용 범위와 운영 모델을 설계하는 데 있다.

    ▼

    ├─► Golden Image: Packer · AMI · Docker Image
    └─► 배포: Blue-Green · Rolling (무중단)

    ▼
