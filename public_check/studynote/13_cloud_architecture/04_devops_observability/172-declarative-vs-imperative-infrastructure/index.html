0. 핵심 인사이트

핵심: 선언형(Declarative)은 "원하는 최종 상태"를 기술하고 도구가 방법을 결정하며, 명령형(Imperative)은 달성 방법을 단계별 명령어로 직접 지시한다. 비유: 명령형은 요리사에게 "재료 씻고, 썰고, 볶고, 간 맞추고" 순서를 알려주는 레시피고, 선언형은 "짜지 않고 담백한 볶음밥이 필요해"라고 결과만 말하고 셰프(도구)에게 맡기는 방식이다.

📝 모범 답안

1. 개요 및 필요성

인프라를 코드로 관리하는 방식에는 두 가지 근본적인 철학이 있다. "어떻게(How) 할 것인가"를 지시하는 명령형과 "무엇(What)이 되어야 하는가"를 선언하는 선언형이다. 이 차이는 단순한 문법 차이가 아니라 시스템이 상태를 관리하는 방식 전체를 결정한다.

명령형 접근의 대표 예는 쉘 스크립트다. apt install nginx && systemctl start nginx처럼 각 단계를 순서대로 지시한다. 이미 nginx가 설치되어 있어도 스크립트는 동일하게 실행된다. 반면 Ansible의 선언형 태스크는 "nginx가 설치되어 있어야 한다(state: present)"를 선언하고, 이미 설치되어 있으면 아무 작업도 하지 않는다.

쿠버네티스(Kubernetes)는 선언형 API의 교과서적 사례다. kubectl apply -f deployment.yaml은 원하는 상태를 선언하고, 쿠버네티스 컨트롤러가 지속적으로 실제 상태를 원하는 상태로 맞춰간다.

3. 구조 및 원리

핵심 조건: 변경 자동화와 운영 안정성은 별개가 아니라 하나의 루프이며, 빌드·검증·배포·관측·피드백이 끊기지 않아야 지속 개선이 가능하다.

동작 순서:

  1. 변경 사항을 버전 관리 시스템에서 감지한다.
  2. 빌드·테스트·보안 검증으로 변경의 품질을 빠르게 확인한다.
  3. 승인된 산출물을 선언형 배포나 자동화 파이프라인으로 운영 환경에 반영한다.
  4. 메트릭·로그·트레이스를 통해 실제 동작 결과를 관측한다.
  5. 피드백을 다음 개선 주기에 연결해 반복적으로 신뢰성을 높인다.

실제 코드 비교

명령형 (AWS CLI 쉘 스크립트):

# S3 버킷이 없으면 생성 (조건 직접 처리)
if ! aws s3 ls "s3://my-bucket" 2>/dev/null; then
  aws s3 mb s3://my-bucket
fi

선언형 (Terraform HCL):

resource "aws_s3_bucket" "my_bucket" {
  bucket = "my-bucket"
}
# 이미 있으면 no-op, 없으면 생성 — 도구가 판단
상황추천 방식이유
인프라 프로비저닝선언형멱등성, 상태 추적
복잡한 조건 분기 자동화명령형표현력 우수
소프트웨어 설치·구성선언형(Ansible)반복 실행 안전
일회성 마이그레이션명령형빠른 작성
쿠버네티스 리소스 관리선언형쿠버네티스 철학

4. 비교 및 연결

실무 조합 패턴:

  • Terraform(선언형) + 쉘 스크립트(명령형): 인프라 생성 후 초기화 스크립트 실행
  • Kubernetes YAML(선언형) + Helm(명령형 패키징): 쿠버네티스 배포 관리
  • Ansible(선언형 위주) + shell 모듈(명령형): 대부분 선언형, 특수 케이스만 명령형

kubectl 명령형 vs 선언형 비교:

# 명령형 (권장하지 않음)
kubectl run nginx --image=nginx

# 선언형 (권장)
kubectl apply -f nginx-deployment.yaml
  • 선언형이 Git 버전 관리·감사 추적에 적합
  • 명령형은 빠른 임시 실험에만 사용

5. 실무 적용 및 판단

선언형 인프라 관리는 코드 의도의 명확성, 멱등성 자동 보장, 상태 기반 자동 복구라는 세 가지 핵심 가치를 제공한다. 쿠버네티스, Terraform의 확산으로 선언형은 현대 클라우드 네이티브 인프라 관리의 표준이 되었다.

그러나 선언형만으로 모든 것을 해결하려는 과도한 집착도 피해야 한다. 데이터 마이그레이션, 복잡한 조건 처리, 일회성 운영 작업에는 명령형이 더 적합할 수 있다. 핵심은 각 방식의 강점을 정확히 이해하고 목적에 맞게 조합하는 판단력이다.

6. 기대효과 및 결론

선언형 vs 명령형 접근 (Declarative vs Imperative Infrastructure)를 올바르게 적용하면 확장성, 운영 안정성, 자동화 수준, 가시성을 함께 높일 수 있다. 다만 이 효과는 기술 자체만으로 생기지 않으며, 책임 경계·표준화·보안 통제·비용 관리가 함께 설계될 때 비로소 현실화된다.

향후에는 관리형 서비스, 정책 자동화, AI 기반 운영 최적화와 결합되면서 선언형 vs 명령형 접근 (Declarative vs Imperative Infrastructure)의 중요성이 더 커질 것이다. 따라서 핵심은 특정 도구를 도입하는 것이 아니라, 업무 특성과 조직 역량에 맞는 적용 범위와 운영 모델을 설계하는 데 있다.
