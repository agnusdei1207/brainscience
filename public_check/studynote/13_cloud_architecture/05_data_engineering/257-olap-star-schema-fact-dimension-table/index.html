0. 핵심 인사이트

핵심: 스타 스키마는 데이터 웨어하우스에서 OLAP 집계 쿼리 성능을 최적화하기 위해 설계된 비정규화 데이터 모델로, 중앙의 팩트 테이블(측정값)이 여러 차원 테이블(분류 기준)과 조인된 별 모양 구조다. 비유: OLTP는 편의점 계산대(빠른 1건 처리), OLAP는 월말 재고 결산(많은 데이터 집계)이다. 계산대 구조(정규화)로 결산을 하면 너무 느리니, 결산용 별도 보고서 구조(스타 스키마)를 만드는 것이다.

📝 모범 답안

1. 개요 및 필요성

영업 부서에서 "2023년 4분기, 수도권 지역, 전자제품 카테고리의 온라인 채널 매출 합계"를 요청했다고 하자. 이를 OLTP 정규화 스키마에서 처리하면 수십 개의 테이블을 조인해야 해서 쿼리가 수 분씩 걸릴 수 있다.

**OLAP(Online Analytical Processing)**은 이런 다차원 분석 쿼리를 위해 최적화된 데이터 처리 방식이다. 스타 스키마(Star Schema)는 OLAP 데이터 웨어하우스의 핵심 설계 패턴이다.

[OLAP vs OLTP 비교]

OLTP (트랜잭션 처리)           OLAP (분석 처리)
┌─────────────────────┐       ┌─────────────────────┐
│ 목적: 트랜잭션 처리   │       │ 목적: 집계 분석       │
│ 쿼리: 소수 행 INSERT/│       │ 쿼리: 수백만 행 집계  │
│       UPDATE        │       │       SELECT         │
│ 정규화: 3NF 높음     │       │ 정규화: 낮음 (비정규화)│
│ 테이블: 수십~수백    │       │ 테이블: 팩트+차원 구조 │
│ 사용자: 실시간 많음  │       │ 사용자: 분석가 소수   │
└─────────────────────┘       └─────────────────────┘

3. 구조 및 원리

핵심 조건: 데이터 플랫폼은 수집·저장·처리·제공·거버넌스가 한 체계로 설계되어야 품질, 확장성, 비용 효율을 동시에 확보할 수 있다.

동작 순서:

  1. 데이터를 원천 시스템이나 이벤트 스트림에서 수집한다.
  2. 수집된 데이터를 적절한 저장 구조와 포맷에 적재한다.
  3. 배치·스트림·쿼리 엔진이 목적에 맞게 변환·처리한다.
  4. 분석·서빙·ML·애플리케이션 계층에 결과를 제공한다.
  5. 품질, 거버넌스, 비용, 보안을 기준으로 지속 최적화한다.

4. 비교 및 연결

OLAP 쿼리 최적화 예시

-- 스타 스키마를 활용한 다차원 분석 쿼리
-- 2023년 4분기, 수도권, 전자제품 매출 집계
SELECT
    d.year,
    d.quarter,
    c.region,
    p.category,
    SUM(f.sales_amount) AS total_sales,
    COUNT(f.sales_key)  AS transaction_count
FROM
    fact_sales f
    JOIN dim_date     d ON f.date_key     = d.date_key
    JOIN dim_customer c ON f.customer_key = c.customer_key
    JOIN dim_product  p ON f.product_key  = p.product_key
WHERE
    d.year = 2023
    AND d.quarter = 4
    AND c.region IN ('서울', '경기', '인천')
    AND p.category = '전자제품'
GROUP BY
    d.year, d.quarter, c.region, p.category;

기술사 시험 판단 포인트

  • 팩트 테이블 세분화(Grain): 팩트 테이블의 행 하나가 나타내는 비즈니스 이벤트 수준 명확화
  • 집계 팩트 테이블(Aggregate Fact Table): 자주 쓰는 집계 결과를 별도 팩트 테이블로 사전 계산
  • 콘텐츠 형 팩트: 팩토리스 팩트(Factless Fact Table) — 이벤트 발생 자체를 기록하는 팩트 테이블

5. 실무 적용 및 판단

기대효과

영역효과
쿼리 성능OLTP 정규화 대비 수십~수백 배 분석 쿼리 속도 향상
이해 용이성비즈니스 용어와 직결된 직관적 구조
BI 도구 호환성Tableau, Power BI 등이 스타 스키마 기준으로 설계됨
집계 단순화GROUP BY + SUM 패턴으로 복잡한 비즈니스 질문 해결

한계 및 주의사항

  • 비정규화로 인한 업데이트 비용: 차원 값 변경 시 수백만 행 업데이트 필요
  • ETL 복잡성: OLTP → 스타 스키마 변환(ETL) 파이프라인 설계가 복잡
  • 실시간 한계: OLAP 스키마는 배치 적재(T+1) 기반 → 실시간 분석에는 HTAP 아키텍처 필요
  • 모델 변경 비용: 초기 설계 이후 팩트 테이블 Grain 변경은 매우 어려움

6. 기대효과 및 결론

OLAP 스타 스키마 - 팩트/차원 테이블를 올바르게 적용하면 확장성, 운영 안정성, 자동화 수준, 가시성을 함께 높일 수 있다. 다만 이 효과는 기술 자체만으로 생기지 않으며, 책임 경계·표준화·보안 통제·비용 관리가 함께 설계될 때 비로소 현실화된다.

향후에는 관리형 서비스, 정책 자동화, AI 기반 운영 최적화와 결합되면서 OLAP 스타 스키마 - 팩트/차원 테이블의 중요성이 더 커질 것이다. 따라서 핵심은 특정 도구를 도입하는 것이 아니라, 업무 특성과 조직 역량에 맞는 적용 범위와 운영 모델을 설계하는 데 있다.
