0. 핵심 인사이트

핵심: 연합 학습(Federated Learning)은 원본 데이터를 중앙 서버로 전송하지 않고 각 기기/노드에서 로컬 모델 훈련 후 모델 파라미터(그래디언트)만 집계하여, 데이터 프라이버시를 보존하면서 분산 ML을 가능하게 한다. 비유: 연합 학습은 요리 경연대회에서 레시피(모델 파라미터)만 공유하는 것이다. 각 셰프(기기)는 자신의 비밀 재료(데이터)로 요리를 만들고, 맛 평가 결과(그래디언트)만 제출한다. 비밀 재료는 절대 공개하지 않는다.

📝 모범 답안

1. 개요 및 필요성

의료 AI 개발의 딜레마: 정확한 암 진단 모델 훈련에는 수십만 건의 의료 영상이 필요하지만, 각 병원은 환자 개인정보 보호 때문에 데이터를 공유할 수 없다.

전통적 해결책은 데이터를 중앙 서버로 수집하는 것이었지만:

  • GDPR, 개인정보보호법 위반 위험
  • 데이터 주권 침해
  • 보안 사고 시 전체 데이터 노출

**연합 학습(Federated Learning, FL)**은 "데이터는 이동하지 않고, 학습만 이동한다"는 혁신적 패러다임이다.

[연합 학습 vs 전통 중앙집중 학습]

전통 중앙집중 학습:
병원 A 데이터 ──┐
병원 B 데이터 ──┼──▶ 중앙 서버 ──▶ 모델 훈련
병원 C 데이터 ──┘    (데이터 노출 위험!)

연합 학습:
병원 A: 로컬 데이터로 훈련 ──▶ 파라미터(그래디언트)만 전송 ──┐
병원 B: 로컬 데이터로 훈련 ──▶ 파라미터만 전송 ──────────────┼──▶ 중앙 집계 ──▶ 글로벌 모델
병원 C: 로컬 데이터로 훈련 ──▶ 파라미터만 전송 ──────────────┘
(원본 데이터는 절대 병원 밖으로 나가지 않음!)

2. 구성요소

FedAvg (Federated Averaging) 알고리즘

[FedAvg 동작 과정]

1라운드:
중앙 서버: 글로벌 모델 w_0 초기화
        │ w_0 배포
        ▼
클라이언트 k=1,2,...,K 중 일부 선택

각 클라이언트:
w_k ← LocalUpdate(w_0, local_data_k)
(로컬 데이터로 E번의 에포크 훈련)
        │
        ▼ w_k 업로드 (파라미터만, 데이터 아님)

중앙 서버:
w_1_new = Σ(n_k/n) × w_k  (데이터 크기로 가중 평균)
(n_k = 클라이언트 k의 데이터 수, n = 전체 합계)
        │
        ▼ 다음 라운드에 w_1_new 배포
...반복...

연합 학습 유형

유형특징예시
Horizontal FL동일 특성, 다른 샘플 (행 기준 분산)병원들이 같은 환자 속성, 다른 환자들 보유
Vertical FL다른 특성, 같은 샘플 (열 기준 분산)은행(거래 내역) + 보험사(의료 기록) = 같은 고객
Federated Transfer Learning특성+샘플 모두 다름도메인이 다른 기업 간 협력

비IID 데이터 문제

[비IID 문제: 클라이언트 데이터 이질성]

IID (Independent and Identically Distributed):
이상적 상황 - 모든 클라이언트 데이터가 동일 분포

비IID (현실):
스마트폰 A: 영어 사용자 데이터
스마트폰 B: 한국어 사용자 데이터
병원 A: 노인 환자 중심
병원 B: 소아 환자 중심

→ 로컬 모델이 자신의 데이터에 과적합(Overfitting)
→ 집계된 글로벌 모델 성능 저하

해결책:
- FedProx: 로컬 모델이 글로벌 모델에서 너무 벗어나지 않도록 제약
- SCAFFOLD: 클라이언트 드리프트 보정
- Personalized FL: 글로벌 + 로컬 개인화 혼합

3. 구조 및 원리

핵심 조건: 데이터 플랫폼은 수집·저장·처리·제공·거버넌스가 한 체계로 설계되어야 품질, 확장성, 비용 효율을 동시에 확보할 수 있다.

동작 순서:

  1. 데이터를 원천 시스템이나 이벤트 스트림에서 수집한다.
  2. 수집된 데이터를 적절한 저장 구조와 포맷에 적재한다.
  3. 배치·스트림·쿼리 엔진이 목적에 맞게 변환·처리한다.
  4. 분석·서빙·ML·애플리케이션 계층에 결과를 제공한다.
  5. 품질, 거버넌스, 비용, 보안을 기준으로 지속 최적화한다.

연합 학습 vs 프라이버시 보존 기법 비교

기법원본 공유계산 위치적합 사례
연합 학습공유 안 함로컬모바일 기기, 의료 협업
차분 프라이버시부분 (통계)중앙통계 공개
동형 암호암호화된 데이터중앙매우 민감한 데이터
안전한 다자 계산공유 안 함분산기업 간 협력
연합 학습 + DP공유 안 함로컬 + 노이즈최강 프라이버시

통신 비용 최적화

[연합 학습의 주요 오버헤드: 통신 비용]

문제: 대규모 딥러닝 모델 (GPT: 수십억 파라미터)
→ 매 라운드마다 수 GB의 파라미터 업로드

최적화 방법:
1. 압축 (Compression):
   - 파라미터 양자화 (32bit → 8bit)
   - 희소 업데이트 (변화 큰 파라미터만 전송)

2. 라운드 수 감소:
   - 로컬 에포크 수 증가 (한 번 통신으로 더 많이 학습)

3. 클라이언트 선택:
   - 배터리·네트워크 상태 좋은 기기만 참여

기술사 시험 판단 포인트

  • 연합 학습의 한계: 데이터가 기기를 떠나지 않아도 그래디언트에서 원본 데이터 역추론 가능 (Gradient Inversion Attack)
  • FL + DP 조합: 그래디언트에 차분 프라이버시 노이즈를 추가하여 역추론 방어
  • Vertical FL 특수성: 같은 사용자의 다른 특성이 다른 서버에 있을 때 — PSI(Private Set Intersection) 기법으로 사용자 매칭

5. 실무 적용 및 판단

기대효과

영역효과
프라이버시 보존원본 데이터를 중앙 서버로 전송하지 않음
데이터 주권각 기관이 자신의 데이터에 대한 통제권 유지
규제 준수GDPR, HIPAA, 개인정보보호법 부담 완화
모델 품질단일 기관 대비 더 많은 데이터로 훈련된 강한 모델

한계 및 주의사항

  • 통신 비용: 많은 라운드의 파라미터 업로드가 대역폭 소비
  • 비IID 데이터 성능 저하: 클라이언트 데이터 이질성이 심할수록 글로벌 모델 성능 하락
  • 그래디언트 공격: 파라미터에서 원본 데이터 역추론 가능 — DP와 결합 필수
  • 조율 복잡성: 수천 개 기기의 훈련 스케줄링, 장애 처리, 버전 관리 어려움

6. 기대효과 및 결론

연합 학습 (Federated Learning) - 프라이버시 보존 ML를 올바르게 적용하면 확장성, 운영 안정성, 자동화 수준, 가시성을 함께 높일 수 있다. 다만 이 효과는 기술 자체만으로 생기지 않으며, 책임 경계·표준화·보안 통제·비용 관리가 함께 설계될 때 비로소 현실화된다.

향후에는 관리형 서비스, 정책 자동화, AI 기반 운영 최적화와 결합되면서 연합 학습 (Federated Learning) - 프라이버시 보존 ML의 중요성이 더 커질 것이다. 따라서 핵심은 특정 도구를 도입하는 것이 아니라, 업무 특성과 조직 역량에 맞는 적용 범위와 운영 모델을 설계하는 데 있다.
