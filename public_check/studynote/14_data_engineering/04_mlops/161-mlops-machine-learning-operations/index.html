0. 핵심 인사이트

핵심: MLOps (Machine Learning Operations)는 ML 모델의 개발(Dev)과 운영(Ops)을 통합하여, 실험실 모델을 신뢰할 수 있는 프로덕션 서비스로 자동화하는 전체 생명주기 관리 체계다. 비유: 숙련도가 쌓일수록 판단이 정교해지는 훈련 체계처럼, 데이터와 피드백이 구조적으로 누적되어 성능이 만들어지는 방식과 같다.

📝 모범 답안

1. 개요 및 필요성

**MLOps (Machine Learning Operations)**는 기계학습 시스템의 신뢰성 있는 배포와 유지 관리를 위해 ML, DevOps, 데이터 엔지니어링의 교집합에서 탄생한 실천 방법론이다.

기존 소프트웨어는 코드만 버전 관리하면 되었지만, ML 시스템은 코드 + 데이터 + 모델 3요소가 모두 변하기 때문에 기존 DevOps 관행만으로는 운영이 어렵다.

전통 소프트웨어           ML 시스템
┌─────────────────┐     ┌──────────────────────────────┐
│   Code (코드)   │     │  Code  │  Data  │  Model     │
│   버전 관리     │     │  코드  │  데이터│  모델       │
│   테스트/배포   │     │  변화  │  변화  │  드리프트   │
└─────────────────┘     └──────────────────────────────┘
        ↓                           ↓
  CI/CD 충분           CI / CD / CT (3축 자동화) 필요

Q. MLOps에서 CI/CD/CT의 역할을 설명하시오.

  • CI (Continuous Integration): 코드 변경 및 데이터 변경 시 자동 빌드, 데이터 스키마 검증, 단위 테스트 실행
  • CD (Continuous Delivery/Deployment): 검증된 모델을 스테이징 환경 자동 배포, 프로덕션 승인 후 자동 적용
  • CT (Continuous Training): 새 학습 데이터 도착, 데이터 드리프트 감지, 모델 성능 임계값 하락 시 자동 재학습 파이프라인 실행

Q. MLOps와 DevOps의 차이점을 설명하시오.

핵심 차이는 관리 대상의 복잡성에 있다. DevOps는 결정론적(Deterministic) 소프트웨어를 다루지만, MLOps는 확률론적(Probabilistic) 모델과 진화하는 데이터를 다룬다. 따라서 코드 변경 없이도 데이터 변화만으로 배포가 실패할 수 있고, 모델 드리프트라는 새로운 운영 개념이 추가된다.

사용자 행동 데이터 (실시간)
        │
        ▼
Kafka → Spark Streaming → 피처 스토어 (Feast)
                                │
                                ├─→ 오프라인 스토어 (S3/BigQuery)
                                │         → 주기적 모델 재학습
                                │
                                └─→ 온라인 스토어 (Redis)
                                          → 실시간 추천 API

모델 재학습 파이프라인 (Kubeflow)
  데이터 검증 → 피처 추출 → 학습 → 평가 → 모델 레지스트리 등록
                                              → 카나리 배포 (5%)
                                              → A/B 테스트 (CTR 비교)
                                              → 전체 배포 또는 롤백

6. 기대효과 및 결론

MLOps (Machine Learning Operations)의 효과는 성능 향상 자체보다도 예측 가능성과 운영 일관성을 확보하는 데 있다. 반대로 데이터 품질, 거버넌스, 모니터링 없이 도입하면 복잡도만 늘고 실질 가치는 줄어든다. 따라서 이 주제는 기능 도입이 아니라 구조적 운영 역량과 함께 판단해야 하며, 향후에는 자동화·실시간성·설명 가능성·비용 최적화와 결합된 방향으로 발전한다.
