0. 핵심 인사이트

핵심: 선언적 파이프라인은 Jenkinsfile로 CI/CD 흐름을 코드로 정의하는 방식이다. 비유: 요리 순서를 종이에 적어 두는 것이다.

📝 모범 답안

1. 개요 및 필요성

UI로만 파이프라인을 만들면 추적이 어렵다.

Jenkinsfile로 관리하면 코드 리뷰와 버전 관리가 가능하다.

2. 구성요소

선언적 파이프라인은 구조가 명확하고 읽기 쉬워 표준화에 적합하다.

3. 구조 및 원리

핵심 조건: 모든 변경이 버전 관리되고, 자동 검증을 통과하며, 배포 상태와 롤백 경로가 추적 가능해야 한다.

동작 순서:

  1. 코드와 배포 정의를 저장소에 커밋해 변경 이력을 단일 진실 공급원으로 만든다.
  2. 빌드·테스트·보안 검사를 자동 수행해 배포 가능 아티팩트를 만든다.
  3. 환경별 설정을 분리하면서도 동일한 파이프라인으로 일관성을 유지한다.
  4. 배포 후 메트릭과 로그를 확인하고 이상 시 즉시 롤백하거나 다음 단계 승인을 중단한다.

선언적 파이프라인은 운영 표준과 협업에 유리하다.

4. 비교 및 연결

체크리스트

  1. Jenkinsfile로 관리하는가?
  2. stage와 agent를 나눴는가?
  3. 코드 리뷰가 가능한가?
  4. 재현성이 있는가?
  5. 운영 표준과 맞는가?

안티패턴

  • UI에만 의존하는 설계
  • scripted와 declarative를 혼동하는 설계
  • 파이프라인을 문서처럼만 보는 설계
  • 환경 변수를 무질서하게 쓰는 설계

기술사 관점에서는 선언적 파이프라인을 "코드로 정의된 CI/CD 표준"으로 설명해야 한다.

5. 실무 적용 및 판단

Jenkinsfile은 파이프라인을 재현 가능하게 만든다.

6. 기대효과 및 결론

적으로 선언적 파이프라인은 Jenkinsfile로 정의하는 Pipeline as Code다.
