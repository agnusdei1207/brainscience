0. 핵심 인사이트

핵심: 마이데이터 (MyData)은(는) 빅데이터 전략과 거시적 변화 방향을 이해하기 위한 정책·시장·기술 트렌드 개념이다. 비유: 멀리서 지형과 조류를 함께 보며 데이터 산업의 큰 흐름을 읽는 전망대와 같다.

📝 모범 답안

1. 개요 및 필요성

마이데이터(MyData)는 개인이 자신의 데이터를 주도적으로 관리·활용하는 데이터 주권(Data Sovereignty) 개념이다.

기존 데이터 유통 vs 마이데이터

특성기존 방식마이데이터
데이터 주체기업 (데이터 소유)개인 (데이터 주권)
수집 동의포괄적·묵시적명시적·세분화된 동의
데이터 이동기업 간 계약 기반개인 API 요청 기반
투명성낮음높음 (이용 내역 조회)

법적 근거

  • 한국: 신용정보법 개정(2020), 개인정보 보호법 개정(2020) — 데이터 이동권
  • EU: GDPR 제20조 — 데이터 이동권 (Right to Data Portability)
  • 미국: CCPA — 캘리포니아 소비자 프라이버시법

3. 구조 및 원리

핵심 조건: 정책, 거버넌스, 플랫폼 구조, 산업 활용 방향을 함께 읽어야 한다.

동작 순서:

┌───────────────────────────────────────────────────────┐
│                 마이데이터 플랫폼                      │
│                                                       │
│  개인      ──→  마이데이터 사업자  ──→  정보 제공 기관│
│ (본인 인증)    (앱/플랫폼)          (은행·카드사 등) │
│                   │                       │          │
│                OAuth 2.0                 Open API     │
│                /동의 관리                REST/JSON    │
│                   │                                   │
│           마이데이터 종합 포털                        │
│           (금융결제원 중계)                           │
└───────────────────────────────────────────────────────┘

기술 표준

  • 인증: OAuth 2.0 + PKCE
  • API: REST/JSON, OpenAPI 3.0 스펙
  • 보안: TLS 1.3, 상호 인증 mTLS
  • 중계: 금융결제원 마이데이터 중계 서버

6. 기대효과 및 결론

마이데이터 (MyData)은(는) 해당 영역의 성능, 확장성, 운영 안정성, 거버넌스 수준을 직접 좌우하는 핵심 요소다. 따라서 도입 여부는 기능 비교를 넘어 데이터 특성, 팀 역량, 비용 구조, 규제 요구를 함께 보는 아키텍처 판단이어야 한다.

실무에서는 초기 효과보다 지속 운영 가능성과 연계 확장성이 더 중요하다. 거시 트렌드는 개별 제품 비교보다 데이터 산업 구조가 어디로 이동하는지 판단하게 해 주는 기준점이다.

핵심 키워드 연결:
개인정보 자기결정권 → 마이데이터 → 데이터 이동권
       ↓                   ↓              ↓
GDPR/개인정보법    금융·의료·공공    Open API 표준
       ↓
PFM 서비스 → AI 개인화 → 데이터 주권 실현

👶 어린이를 위한 3줄 비유 설명

  1. 마이데이터는 내 성적표를 내가 관리하는 것이다 — 선생님(은행·병원)이 가지고 있던 성적표를 내가 직접 볼 수 있고, 필요한 곳에 가져갈 수 있다.
  2. 금융 마이데이터는 여러 통장을 하나의 앱에서 보는 것이다 — 은행마다 앱을 열지 않아도 내 모든 돈이 어디에 얼마나 있는지 한눈에 알 수 있다.
  3. 데이터 이동권은 전학 갈 때 성적표를 가져갈 권리다 — 학교(서비스)를 바꿔도 내 기록(데이터)은 내가 새 학교(앱)에 직접 가져갈 수 있다.
